What it does

POET (Paired Open-Ended Trailblazer) — Uber's open-ended algorithm that co-evolves a population of parameterized Box2D environments and the solutions specialized to each, transferring agents between niches so challenges and capabilities bootstrap each other. Master implements Enhanced POET; the original paper code is also in-repo.

How it works

  • `master.py` is the entry point: parses ~25 hyperparameters (mc_lower/mc_upper, repro_threshold, steps_before_transfer, max_num_envs) and builds `MultiESOptimizer` in `poet_distributed/poet_algo.py`, which keeps one `ESOptimizer` per niche plus `env_registry`/`env_archive` of `Env_config` + `CppnEnvParams`.
  • Environment birth loop `adjust_envs_niches()`: niches whose `self_evals >= repro_threshold` are mutated via `Reproducer` and CPPN parameter mutation, then gated by `pass_dedup`, the minimal-criterion window `pass_mc` (score must fall in [mc_lower, mc_upper]), and novelty ranking via `compute_novelty_vs_archive` (novelty.py) before one child per interval is admitted; `remove_oldest` caps the population.
  • Transfer in `transfer()`: every source theta is evaluated on every other niche (direct transfer plus an Adam 'proposal' transfer via `get_step(propose_only=True)`), each niche then calls `pick_proposal` to accept improvements; `update_pata_ec` maintains performance-of-all-tasks rankings for prioritized transfer.
  • Domain: `poet_distributed/niches/box2d/` — `Box2DNiche` (box2d.py) rolls a flat policy vector (`Model(bipedhard_custom)`) through `bipedal_walker_custom.py` terrain generated from stump/pit/stair/roughness `Env_config` fields; workers run on Uber Fiber pools (`es.py: initialize_worker_fiber`), orchestrated by `run_poet_local.sh` / `run_poet_remote.sh` (Dockerfile included).

Key advantages

  • The canonical reference implementation of environment/solution co-evolution with an explicit minimal criterion + novelty gate — the clearest codebase for studying how open-ended curricula stay in the 'learnable but new' band instead of collapsing to trivial or impossible tasks.
  • The co-evolution skeleton is domain-agnostic: swap `Box2DNiche` for any parametric environment family and the registry/archive/transfer/PATA-EC bookkeeping in poet_algo.py carries over.
  • Unlike single-curriculum generators, solutions migrate between niches, so capabilities compound across the archive — the mechanism POET's authors showed can solve domains blockable from a fixed starting point.

Paired Open-Ended Trailblazer (POET): Endlessly Generating Increasingly Complex and Diverse Learning Environments and Their Solutions

Install & run

Enhanced POET (master branch): install deps per requirements.txt — `fiber`, `neat-python`, `gym[box2d]` — then `./run_poet_local.sh final_test` locally or `./run_poet_remote.sh final_test` on Kubernetes (via Fiber + persistent volume); logs with `fiber cp nfs:/persistent/logs/final_test .`. Original POET: the `original_poet` branch.

Learning note

Read poet_algo.py first — the whole algorithm is ~300 lines and both loops (transfer, adjust_envs_niches) fit on one screen. Master is Enhanced POET (ES over flat policy vectors; no TensorFlow); expect 2020-vintage Fiber/gym pinning friction to actually execute.

Repo README

POET and Enhanced POET

This repo contains implementation of the POET and Enhanced POET algorithms described in:

Paired Open-Ended Trailblazer (POET): Endlessly Generating Increasingly Complex and Diverse Learning Environments and Their Solutions

Enhanced POET: Open-Ended Reinforcement Learning through Unbounded Invention of Learning Challenges and their Solutions

An article on Uber Engineering Blog describing POET can be found here.

Requirements

  • Fiber
  • NEAT-Python
  • OpenAI Gym

Run Enhanced POET locally

To run locally on a multicore machine

./run_poet_local.sh final_test

Run Enhanced POET on a Kubernetes cluster

Follow instructions here to create a persistent volume.

Then run the following command:

./run_poet_remote.sh final_test

To get the training logs:

fiber cp nfs:/persistent/logs/final_test . fiber cp nfs:/persistent/logs/poet_final_test poet_final_test

Run Enhanced POET on a computer cluster

To containerize and run the code on a computer cluster (e.g., Google Kubernetes Engine on Google Cloud), please refer to Fiber Documentation.
