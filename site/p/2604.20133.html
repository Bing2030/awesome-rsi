EvoAgent: An Evolvable Agent Framework with Skill Learning and Multi-Agent Delegation

Aimin Zhang, Jiajing Guo, Fuwei Jia, Chen Lv, Boyu Wang, Fangzheng Li

arXiv 2026 · 2026

Local PDFOnline

TL;DR

EvoAgent wraps GPT5.2 in a user-feedback-driven dual loop — deterministic online skill matching/delegation, asynchronous offline skill extraction — lifting average LLM-as-Judge score 27.998% (3.547→4.541) in deployed foreign-trade use, while degrading weaker models.

Abstract

This paper proposes EvoAgent--an evolvable large language model (LLM) agent framework that integrates structured skill learning with a hierarchical sub-agent delegation mechanism. EvoAgent models skills as multi-file structured capability units equipped with triggering mechanisms and evolutionary metadata, and enables continuous skill generation and optimization through a user-feedback-driven closed-loop process. In addition, by incorporating a three-stage skill matching strategy and a three-layer memory architecture, the framework supports dynamic task decomposition for complex problems and long-term capability accumulation. Experimental results based on real-world foreign trade scenarios demonstrate that, after integrating EvoAgent, GPT5.2 achieves significant improvements in professionalism, accuracy, and practical utility. Under a five-dimensional LLM-as-Judge evaluation protocol, the overall average score increases by approximately 28\%. Further model transfer experiments indicate that the performance of an agent system depends not only on the intrinsic capabilities of the underlying model, but also on the degree of synergy between the model and the agent architecture. Code, data, and documents will be released at https://github.com/Focus-AI-Center/Mentarc-EvoAgent.git.

Method

A skill is the tuple (name, desc, triggers, instr, refs, meta): a multi-file package — SKILL.md plus lazily-loaded refs/ — carrying evolutionary metadata (usage count, success rate, timestamps). Online loop: three-stage cascading matching (case-insensitive trigger keywords → embedding cosine similarity above a 0.6 default threshold → LLM intent classification), structured context assembly, ReAct execution, and compression above 64K tokens that preserves an 'asset index' of skills, links, and key data; skills flagged requires_sub_agent spawn sub-agents with independent context spaces via OpenAI Agents SDK handoff, results flowing back past the main agent. Offline loop, triggered only at session end: an asynchronous Session Reviewer sub-agent updates SOUL.md/USER.md/MEMORY.md, extracts candidate skills, and grades maturity — Budding / Growing / Mature / Proficient at usage≥1 / ≥4 with success≥0.7 / ≥10 with success≥0.85. The MDP formalization is theoretical only: no numerical reward is computed; evolution runs on implicit usage/success statistics plus user feedback.

Key results

  • RQ1, five-dimension LLM-as-Judge (1–5 scale; 172 instances split from 20 sampled multi-turn dialogues out of 664 collected; queries script-generated over product category × target market × buyer type × 12 foreign-trade scenarios): GPT5.2 average 3.547 → 4.541 with EvoAgent (+27.998%); professionalism 2.703→4.762, accuracy 2.907→4.238, practicality 3.744→4.709, language quality 4.052→4.779, completeness flat 4.331→4.215 (−0.116)
  • RQ2 model transfer: GPT4.1 under EvoAgent drops ~13% below its own standalone baseline and reaches ~75% of EvoAgent-enhanced GPT5.2; Qwen3.5-35B-A3B drops to ~85% of standalone, 74.5% of enhanced GPT5.2 — the paper formalizes capability as γ1·inference + γ2·agent-implementation compatibility, conceding no ablations isolate the factors
  • RQ3 long-horizon memory: 420 dialogue turns with 6 compression events without runtime errors; no memory errors across 17 tests at 120 turns; full accuracy at 200 turns without compression; compression triggers when context exceeds 64K tokens
  • Latency: ~12s average response early, 14s around 80 turns, stabilizing at 24s beyond 120 turns; external tool calls add 5–30s depending on complexity

Key advantages

  • A concrete Harness Engineering instantiation (explicitly built on Hashimoto, OpenAI's Codex report, Böckeler/Fowler, Iusztin): deterministic low-latency online execution loop cleanly separated from an asynchronous offline evolution loop, compiling the MDP objective into post-session updates so no labeled data or numerical reward is needed
  • Full skill lifecycle modeled — generation, cascading matching, lazy-loading injection, maturity grading with explicit usage/success thresholds, pruning inputs — versus the implicit, unstructured capability updates it attributes to Voyager-style skill libraries
  • Publishes the negative transfer result most RSI papers omit: the same harness that gives GPT5.2 +27.998% degrades GPT4.1 ~13% and Qwen ~15%, evidence that architecture gains are a model–harness interaction, not a free amplifier
  • Deployed on a real foreign-trade assistant at Focus Technology rather than a benchmark; queries generated by a parameterized script independent of runtime skill-triggering outcomes

Limitations

  • Paper's own, from the HarnessEngineering lens: evolution triggers only after session termination (unidirectional online→offline coupling) — 'delayed learning but not real-time adaptation' to skill degradation or intent shift
  • Only single-skill invocation per task — no multi-skill orchestration or parallel execution; user profiling relies on heuristic frequency thresholds; no cross-user knowledge sharing
  • Evaluation is small (172 instances), synthetic, and collected inside the deployed EvoAgent environment (authors concede distribution dependence); LLM-as-Judge scoring with no human validation, variance, or ablations; no head-to-head against a standalone-GPT compression/memory baseline
  • Compression irreversibly loses early dialogue details and long-term memory lacks automatic pruning; system lacks cost tracking, monitoring dashboards, and enterprise auth (JWT/OAuth)

Where it fits the RSI arc

Stage 5 harness-level RSI: the industrial, user-in-the-loop counterpoint to EvoSkills' automated co-evolution verification (its main cited contrast) and Voyager's flat skill library. Pairs with RRSI and Harness-Zero on 'the harness moves scores' — and with the model–harness synergy caveat (GPT4.1/Qwen degradation) every RSI claim should be read against.
