PAPER · stage 7 · Coding / Software-Engineering Self-Improvement

Training Software Engineering Agents and Verifiers with SWE-Gym

Jiayi Pan, Xingyao Wang, Graham Neubig, Navdeep Jaitly, Heng Ji, Alane Suhr, Yizhe Zhang

ICML 2025 · 2025

Local PDFOnline

TL;DR

SWE-Gym: the first executable training environment for SWE agents — 2,438 Python task instances from 11 repos — on which rejection-sampling fine-tuning plus a trained verifier lift a 32B open model to 32.0% on SWE-Bench Verified.

Abstract

We present SWE-Gym, the first environment for training real-world software engineering (SWE) agents. SWE-Gym contains 2,438 real-world Python task instances, each comprising a codebase with an executable runtime environment, unit tests, and a task specified in natural language. We use SWE-Gym to train language model based SWE agents, achieving up to 19% absolute gains in resolve rate on the popular SWE-Bench Verified and Lite test sets. We also experiment with inference-time scaling through verifiers trained on agent trajectories sampled from SWE-Gym. When combined with our fine-tuned SWE agents, we achieve 32.0% and 26.0% on SWE-Bench Verified and Lite, respectively, reflecting a new state-of-the-art for open-weight SWE agents. To facilitate further research, we publicly release SWE-Gym, models, and agent trajectories.

Method

SWE-Gym is built from 358 filtered Python repos (>500 stars, >500 PRs, created before July 2022): 64,689 SWE-Bench-style instances (SWE-Gym Raw), of which 11 repos get semi-manually installed dependencies and gold-patch unit-test validation, yielding 2,438 executable instances (plus a 230-instance SWE-Gym Lite) and 6 TB of Docker images. Agents (OpenHands CodeAct, MoatlessTools) roll out against that runtime, whose expert tests supply the reward. Policy training is rejection-sampling fine-tuning (filtered behavior cloning) on 491 off-policy success trajectories from GPT-4o-2024-08-06 and Claude-3.5-Sonnet (~19 turns, ~19k tokens each), full-parameter FT of Qwen2.5-Coder-Instruct 7B/14B/32B (lr 1e-4, <=5 epochs, 32k context). The verifier is an outcome-supervised reward model: the same 32B model fine-tuned to emit <YES>/<NO> over 1,318 success + 1,318 failure trajectories (2,636 total), scoring r = exp(l_YES)/(exp(l_YES)+exp(l_NO)) from SGLang logprobs to rerank k rollouts.

Key results

  • OpenHands + Qwen2.5-Coder-Instruct-32B fine-tuned on only 491 SWE-Gym trajectories: SWE-Bench Lite 3.0% -> 15.3% (+12.3) and Verified 7.0% -> 20.6% (+13.6); the 7B model goes 1.0% -> 10.0% (Lite) and 1.8% -> 10.6% (Verified) (Table 3).
  • Training fixes agentic behavior, not just patches: stuck-in-loop rate falls 4.6-18.6 points (7B on Verified 39.6% -> 21.0%; 32B Verified 29.4% -> 23.8%), with empty-patch rate dropping in parallel (7B Lite 40.3% -> 29.7%).
  • Verifier reranking on SWE-Bench Verified (32B agent + 32B verifier, OpenHands): Best@k 20.6@1 -> 29.8@8 -> 32.0@16, while Pass@k reaches 37.8@8 and 42.8@16; a LoRA verifier beats full-parameter fine-tuning (29.8@8 vs 27.2@8). This 32.0/26.0 is the best open-weight result in the paper's comparison.
  • The same recipe transfers scaffolds: MoatlessTools verifiers on SWE-Bench Lite move the 7B policy 10% -> 13.3% and the 32B policy 19.7% -> 26.3% at k=8 (t=0.5); the 7B verifier plateaus after k=4 while the 32B one still improves at k=8.
  • Verifier training data matters: mixing on- and off-policy trajectories reaches 27@8, whereas off-policy-only training plateaus around 22%; MoatlessTools self-improvement moves the 7B model 7.0% -> 9.0% -> 10.0% over two rejection-sampling iterations, and 32B only 19.0% -> 19.7% then flat.

Key advantages

  • First executable SWE training environment: unlike SWE-Bench's train split (solutions as patches only, no runtime) or isolated/synthetic sets (HumanEval, APPS, R2E), it ships repo-level tasks with pre-installed dependencies and expert-test reward signals, and releases everything — 6 TB of Docker images, model weights, trajectories and the training pipeline. In its comparison table it is the only row with both model and environment open.
  • Shows SWE capability is trainable from very little data: 491 trajectories buy double-digit absolute gains, and performance keeps improving as training trajectories scale 25% -> 50% -> 100% with no saturation at the sampling limit — including when deduplicated by instance or by repository — so the bottleneck is sampling compute rather than SWE-Gym's size or repo diversity.
  • The trajectory data teaches the agentic loop itself: fine-tuning markedly reduces stuck-in-loop and empty-patch rates, addressing the failure mode that most limits open-weight models under general-purpose prompting.
  • A trained verifier makes inference-time compute pay: Best@k rises roughly log-linearly with rollouts to 32.0% on Verified and 26.0% on Lite, reaching open-weight SOTA with a 32B model.

Limitations

  • Self-improvement largely fails with this recipe: MoatlessTools rejection sampling gains only 7.0% -> 10.0% (7B) and 19.0% -> 19.7% (32B, then flat), and mixing 868 on-policy with 491 off-policy trajectories on OpenHands regressed SWE-Bench Lite 15.3% -> 8.7%. The authors attribute this to filtered-BC and suggest PPO or a stronger base model.
  • Environment diversity is narrow: only 11 Python repositories with a long tail (pandas ~one third of instances, bokeh ~1%) and hand-configured dependencies; the authors name automated environment synthesis (environment creation, test-case generation, task generation) and broader language/task coverage as the critical next step.
  • The verifier is the ceiling on inference-time scaling: Best@k trails Pass@k by 10.8 points at k=16 (32.0% vs 42.8%), dropping to ~22% when trained on off-policy data alone, and the 7B verifier stops improving after k=4.
  • No reinforcement learning and no human-in-the-loop evaluation; the paper's own comparison notes a concurrent 72B system trained on 80,036 trajectories reaches about 40% on SWE-Bench Verified, so scale still buys accuracy beyond what this 32B setup achieves.
