SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness

Haozhe Liu, Tian Ye, Sensen Gao, Qihang Cao, Yitong Li, Mingchen Zhuge, Duomin Wang, Ruihua Zhang, Ping Luo, Jiawang Bian, Lei Zhu, Ligeng Zhu, Enze Xie, Song Han

arXiv 2026 · 2026

Local PDFOnline

TL;DR

Runs auto-research loops over the coding-agent harness itself under a token-efficiency objective: 152 proposed mechanisms, four survive — ~45% fewer tokens and ~1/3 lower cost while retaining ~94% of Pi's score.

Abstract

As coding agents move from supervised code completion to unattended, around-the-clock exploration, their work expands from isolated predictions into long trajectories of reasoning, tool use, and feedback. Token efficiency therefore becomes important for scaling recursive self-improvement. We take an RSI-inspired approach at the harness layer, scaling auto-research loops across increasingly numerous and diverse environments for harness rollouts. At this scale, the process yields reusable improvements that transfer beyond their development setting, moving automated harness discovery toward production-level outcomes. Four mechanisms survive selection and form SoL-Pi, spanning action execution, context compaction, observation handling, and delegated reading. On the 51-task EdgeBench evaluation, SoL-Pi achieves performance comparable to Pi across GPT-5.6 Sol and Opus 5 while reducing recorded token traffic by 44.7-49.0% and API cost by about one third. In other words, estimated hourly savings are \$8.75-\$13.50 relative to native Codex and Claude Code harnesses, and \$4.36-\$5.71 relative to Pi.

Method

A 7-stage auto-research loop per candidate idea: Trajectory Rollouts -> Map-Reduce Analysis -> Proposal -> Implementation -> Reviewer -> In-Trajectory Validation -> Held-Out Validation on a frozen, isolated test set. A predeclared capability floor gates every mechanism (savings only count within a quality tolerance, so efficiency is bounded by non-regression), and the surviving mechanisms combine into the SoL-Pi harness.

Key results

  • 44.7-49% fewer recorded tokens and ~1/3 lower API cost vs Pi, retaining ~94% of Pi's EdgeBench score (and exceeding the native Codex harness on GPT-5.6 Sol).
  • Four reusable mechanisms: Action Fusion (fuse edit+run into one call), Online Context Compact (compact at subtask boundaries), ObservationPack (paged recall instead of full replay), Evidence-Preserving Reducer (delegate first reading to a cheaper agent, verify against the log).
  • In a 20-worker swarm, SoL-Pi workers reach 1,127 cycles at $60.11 — 17.5% fewer cycles and 26.8% lower cost than Pi workers.

Limitations

  • Efficiency measured against Pi and model-native harnesses on EdgeBench/Terminal-Bench; cross-harness transferability is claimed via held-out environments, not yet proven at scale.
  • Hybrid loop: human priors seeded and filtered the 152-idea pool, so it is not fully autonomous RSI.
  • The recursive-efficiency compounding ('REI') is explicitly a vision, not a demonstrated effect.

Where it fits the RSI arc

Harness-level RSI with an efficiency objective gated by a capability floor — the non-regression discipline rsif encodes as its val gate, now applied to token cost. Complements rsif (which evolves the agent's artifacts) by evolving the harness that runs the agent.

How to read it

Read the 7-stage loop and the predeclared capability floor / gate; the four mechanism cards show how narrow harness edits transfer across tasks.
