What it does

HyperAgents (DGM-Hyperagents, DGM-H) — code for arXiv 2603.19461: a task agent and a meta agent live in one editable program, so the improver rewrites both the task-solving code and its own improvement mechanism, generalizing the Darwin Gödel Machine beyond coding.

How it works

  • meta_agent.py / task_agent.py — the self-referential pair, both subclasses of AgentSystem (agent/base_agent.py): MetaAgent.forward(repo_path, eval_path, iterations_left) issues exactly one instruction — 'Modify any part of the codebase at `{repo_path}`' — via chat_with_agent with all bash/edit tools (agent/tools/); TaskAgent is the object-level agent being improved. run_meta_agent.py then git-resets domains/ back to the base commit (reset_paths_to_commit) so the eval harness can't be gamed, and saves the rest as model_patch.diff.
  • generate_loop.py — the evolution driver: per generation it builds a Docker container (image `hyperagents`), replays the parent's full lineage of diffs (get_patch_files → apply_diffs_container), runs the meta agent (6h timeout), requires a non-empty model_patch.diff plus a compilation check (run_commands_to_check_compilation), then staged-evals on a small subset (gate: every domain scores > 0) before the full eval via domains/harness.py + domains/report; accepted nodes append to archive.jsonl with metadata.json per gen_*/.
  • Open-ended search over the archive: utils/gl_utils.py::select_parent (default --parent_selection score_child_prop — score-proportional but inversely proportional to children, keeping the space open); --edit_select_parent hands the selection mechanism itself to the meta agent (select_next_parent.py, run inside a container via utils.run_select_next_parent); ensemble.py scores the whole archive as one agent; --meta_patch_files with --reset_task_agent/--reset_meta_agent drive the cross-run, cross-domain transfer experiments.
  • domains/ are swappable evaluators with train/val/test splits — paper_review (default in setup_initial.sh), search_arena, balrog_{babyai,babaisai,minihack,nle}, genesis_go2walking/hop/walkback (robot reward-function design), imo_grading, imo_proof, polyglot (SWE-bench, one Docker per task); baselines/ ships dgm/coding_agent.py plus no_selfimprove/no_archive ablations; agent/llm.py wires litellm (default anthropic/claude-sonnet-4-5-20250929).

Key advantages

  • The only substrate in this catalog where the search machinery itself sits inside the search space: parent selection, staged eval and ensembling are plain Python files next to the agents, so you can watch metacognitive improvements (the paper's persistent memory, performance tracking) land as diffs in archive.jsonl and check they transfer across domains and accumulate across runs — evidence DGM's coding-only task/self-mod alignment cannot produce.
  • One loop, many domains: the same generate_loop.py improves LLM graders (imo_grading), game agents (Balrog), reward functions (Genesis Go2) and SWE-bench patches (polyglot), with dgm / no_selfimprove / no_archive baselines wired through the identical harness — the cleanest available testbed for whether meta-level gains generalize beyond coding.
  • Honesty by construction: the evaluator is quarantined from the improver (domains/ reset after every meta-agent run), candidates must compile before scoring, and staged small-sample evals gate the expensive full evals — a concrete template for safe-ish untrusted-code RSI loops.

Install & run

echo 'OPENAI_API_KEY=...
ANTHROPIC_API_KEY=...
GEMINI_API_KEY=...' > .env  # README setup
python3.12 -m venv venv_nat && source venv_nat/bin/activate && pip install -r requirements.txt
docker build --network=host -t hyperagents .
bash ./setup_initial.sh
python generate_loop.py --domains paper_review  # script documents all args and baselines

Learning note

Start at run_meta_agent.py: the domains/ git-reset is what keeps evals honest while everything else is fair game. Then generate_loop.py's staged-eval gate and gl_utils.select_parent's score_child_prop. Watch archive.jsonl grow and read gen_*/agent_output/meta_agent_chat_history.md — the transcript of the improver improving itself. DGM baseline: baselines/dgm/.

Repo README

HyperAgents

Self-referential self-improving agents that can optimize for any computable task

Setup

# API keys, put these into .env file
OPENAI_API_KEY=...
ANTHROPIC_API_KEY=...
GEMINI_API_KEY=...

# Install things
sudo dnf install -y python3.12-devel
sudo dnf install -y graphviz graphviz-devel cmake ninja-build bzip2-devel zlib-devel ncurses-devel libffi-devel

# Create virtual environment
python3.12 -m venv venv_nat
source venv_nat/bin/activate
pip install -r requirements.txt
pip install -r requirements_dev.txt
# To build the docker container
docker build --network=host -t hyperagents .

# Setup initial agents
bash ./setup_initial.sh

Running HyperAgents

# See the script for args, and baseline selections
python generate_loop.py --domains <domain>

By default, outputs will be saved in outputs/ directory.

File Structure

  • agent/ code for using foundation models
  • analysis/ scripts used for plotting and analysis
  • domains/ code for each domain
  • utils/ common code used in the repo
  • run_meta_agent.py script to help run the meta agent and get the diffs
  • meta_agent.py main implementation of the meta agent
  • task_agent.py main implementation of the task agent
  • generate_loop.py entry point for running the algorithm
