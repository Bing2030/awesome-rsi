Voyager: An Open-Ended Embodied Agent with Large Language Models

Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi Fan, Anima Anandkumar

TMLR 2024 · 2024

Local PDFOnlineCode

TL;DR

Voyager is a GPT-4 Minecraft agent that learns open-endedly with no gradients: an automatic curriculum proposes tasks, a library of self-verified executable code skills supplies reusable behavior, and environment feedback, execution errors and self-verification refine the code — 3.3× more items than baselines.

Abstract

We introduce Voyager, the first LLM-powered embodied lifelong learning agent in Minecraft that continuously explores the world, acquires diverse skills, and makes novel discoveries without human intervention. Voyager consists of three key components: 1) an automatic curriculum that maximizes exploration, 2) an ever-growing skill library of executable code for storing and retrieving complex behaviors, and 3) a new iterative prompting mechanism that incorporates environment feedback, execution errors, and self-verification for program improvement. Voyager interacts with GPT-4 via blackbox queries, which bypasses the need for model parameter fine-tuning. The skills developed by Voyager are temporally extended, interpretable, and compositional, which compounds the agent's abilities rapidly and alleviates catastrophic forgetting. Empirically, Voyager shows strong in-context lifelong learning capability and exhibits exceptional proficiency in playing Minecraft. It obtains 3.3x more unique items, travels 2.3x longer distances, and unlocks key tech tree milestones up to 15.3x faster than prior SOTA. Voyager is able to utilize the learned skill library in a new Minecraft world to solve novel tasks from scratch, while other techniques struggle to generalize. We open-source our full codebase and prompts at https://voyager.minedojo.org/.

Method

Three GPT-4 modules over a MineDojo + Mineflayer bot (§2). (1) Automatic curriculum: GPT-4 (temperature 0.1) gets the directive 'discover as many diverse things as possible', the agent state (inventory, equipment, biome, time, health/hunger, position, nearby blocks/entities), completed and failed task lists, and GPT-3.5 self-asked Q&A context, then emits the next task. (2) Skill library: each solved task is committed as a JavaScript program calling hand-written control primitives, keyed by the embedding of a GPT-3.5-written description; for a new task the plan plus environment feedback retrieve the top-5 skills into the code prompt. (3) Iterative prompting: execute the generated program, feed back bot.chat() progress messages and interpreter error traces, re-prompt GPT-4 to refine, and repeat; a separate GPT-4 self-verification agent returns success plus a critique. Success commits the skill and queries the curriculum again; four failed code rounds trigger a new task. No fine-tuning, no parameter access.

Key results

  • Exploration (Fig. 1): Voyager discovers 63 unique items within 160 prompting iterations, 3.3× more than ReAct, Reflexion and AutoGPT, which barely progress against the abstract goal.
  • Tech tree (Table 1, prompting iterations to unlock, 3 trials): Voyager 6±2 wooden, 11±2 stone, 21±7 iron (3/3 each) and, uniquely, diamond at 102 (1/3); AutoGPT 92±72 / 94±72 / 135±103 (3/3) but never diamond; Voyager without the skill library 7±2 / 9±4 / 29±11 but never diamond; ReAct and Reflexion never unlock even wooden (0/3). That is 15.3×, 8.5× and 6.4× faster than the best baseline at the three levels.
  • Map coverage (Fig. 7): Voyager travels 2.3× longer distances across diverse terrain, while baselines stay confined to local areas.
  • Zero-shot generalization (Table 2, fresh world, cleared inventory, 50-iteration cap): Voyager solves all four unseen tasks at 19±3 (Diamond Pickaxe), 18±7 (Golden Sword), 21±5 (Lava Bucket) and 18±2 (Compass) iterations, 3/3 each; no baseline solves any (0/3), and AutoGPT given Voyager's skill library reaches only 39 (1/3), 30 (1/3), 0/3 and 30 (2/3).
  • Ablations (Fig. 9): a random curriculum costs 93% of discovered items, deleting self-verification costs 73%, removing the skill library plateaus later stages, and swapping GPT-4 for GPT-3.5 in code generation yields 5.7× fewer unique items. Skill retrieval scores 80.2±3.0 top-1 and 96.5±0.3 top-5 accuracy over 309 samples (Table A.4).

Key advantages

  • Skills are executable, interpretable, compositional code, not text memories: each one is admitted only after environment execution and critic-confirmed success, is built on named control primitives, and composes into harder programs — the mechanism that lets later skills stand on earlier ones and keeps the agent off the plateau seen when the library is ablated.
  • The library transfers as an artifact: it works in a newly instantiated world and is plug-and-play for another agent, lifting AutoGPT from 0/3 on every unseen task to partial success on three of four — the paper's clearest evidence that the learned skills, not the prompting style, carry the capability.
  • Component attribution is measured rather than asserted: curriculum (−93%), self-verification (−73%), skill library and GPT-4-class code generation (5.7× items) are each individually ablated, isolating what actually drives open-ended progress.
  • Whole loop is gradient-free on a blackbox GPT-4: the model is queried through prompting only, needs no trajectory data, reward model or fine-tuning, and the results are robust across gpt-4-0314 and gpt-4-0613.

Limitations

  • Cost and model lock-in: GPT-4 is 15× more expensive than GPT-3.5, yet the paper states the loop requires GPT-4's code-generation quality (GPT-3.5 loses 5.7× in unique items) and that open-source LLMs cannot substitute at the time of writing.
  • Failure modes persist despite the loop: the agent still gets stuck on some skills, self-verification misses cases (it does not read spider string as evidence of killing a spider), the curriculum hallucinates non-existent items such as 'copper sword' and 'copper chestplate', and generated code misuses invalid fuel (cobblestone) or calls absent API functions.
  • No perception: the GPT-4 API is text-only, so Voyager sees inventory/state text rather than pixels and acts through the high-level Mineflayer API — the paper explicitly declines comparison with pixel-and-low-level-control agents and leaves vision to future multimodal models.
  • The hardest demonstrations are human-scaffolded: building a Nether Portal or a house required a human as critic and as curriculum, and the domain is Minecraft only; transferring to physical robots would need added safety constraints.
