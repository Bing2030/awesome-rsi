MLEvolve: A Self-Evolving Framework for Automated Machine Learning Algorithm Discovery

Shangheng Du, Xiangchao Yan, Jinxin Shi, Zongsheng Cao, Shiyang Feng, Zichen Liang, Boyuan Sun, Tianshuo Peng, Yifan Zhou, Xin Li, Jie Zhou, Liang He, Bo Zhang, Lei Bai

arXiv 2026 · 2026

Local PDFOnlineCode

TL;DR

An LLM multi-agent framework that evolves end-to-end ML algorithms, reaching 65.3% average medal rate on MLE-Bench in a 12-hour budget — best among compared agents at half the standard 24h runtime — and the best result on 11 of 15 AlphaEvolve math-optimization tasks.

Abstract

Large language model (LLM) agents are increasingly applied to long-horizon tasks such as scientific discovery and machine learning engineering (MLE), where sustained self-evolution becomes a key capability. However, existing MLE agents suffer from inter-branch information isolation, memoryless search, and lack of hierarchical control, which together hinder long-horizon optimization. We present MLEvolve, an LLM-based self-evolving multi-agent framework for end-to-end machine learning algorithm discovery. By extending tree search to Progressive MCGS, MLEvolve enables cross-branch information flow through graph-based reference edges and gradually shifts the search from broad exploration to focused exploitation with an entropy-inspired progressive schedule. To allow the agent to evolve with accumulated experience, we introduce Retrospective Memory, which combines a cold-start domain knowledge base with a dynamic global memory for task-specific experience retrieval and reuse. For stable long-horizon iteration, we further decouple strategic planning from code generation with adaptive coding modes. Evaluation on MLE-Bench shows that MLEvolve achieves state-of-the-art performance across multiple dimensions including average medal rate and valid submission rate under a 12-hour budget (half the standard runtime). Moreover, MLEvolve also outperforms specialized algorithm discovery methods including AlphaEvolve on mathematical algorithm optimization tasks, demonstrating strong cross-domain generalization. Our code is available at https://github.com/InternScience/MLEvolve.

Method

Three coupled mechanisms per task (500 steps, 12h). A branch is a root-to-leaf trajectory of candidate solutions (3 initial drafts, max 5 branches plus 2 fusion). (1) Progressive MCGS: primary edges carry UCT selection and backpropagation; reference edges — never backpropagated — point from other branches' top nodes, so cross-branch transfer conditions generation on retrieved solutions, not scalar rewards. A soft switch w(t) decays 1.0→0.2, blending UCT exploration into Elite-Guided picks from the global top-3 by inverse rank; two-level stagnation detection (τ_branch=3, τ_global=6) triggers intra-branch evolution, cross-branch fusion, or multi-branch aggregation at the root. (2) Retrospective Memory: curated cold-start knowledge base plus a dynamic global store of per-node records (plan, outcome, metric, analysis), retrieved by BM25+FAISS fused via RRF at planning/debugging stages — records persist across the run, replacing memoryless scalar-only search. (3) Planner-coder decoupling: planner decides what/why at module level; coder implements via Base/Stepwise/Diff modes chosen by search state.

Key results

  • MLE-Bench (75 tasks, 12h budget, 3 seeds): 65.3% average medal rate, 34.7% gold, 100% valid submissions, 76.0% above-median — vs. best 24h baselines MARS+ 62.7% medal / 33.8% gold and AIBuildAI 63.1% / 25.8%; by complexity 80.3% low, 64.0% medium, 46.7% high.
  • AlphaEvolve's 15 math-optimization tasks: best result on 11 of 15 vs. AlphaEvolve, AlphaEvolve-v2, SimpleTES, TTT-Discover, and OpenEvolve (e.g., sums-differences problem 1: 1.1901774219 vs. AlphaEvolve's 1.1479889651; circle packing in a rectangle: 2.3658323759 vs. 2.3658321334).
  • Component ablation on MLE-Bench Lite (22 tasks): medal 81.82% full → 68.18% w/o Progressive MCGS, 68.18% w/o Retrospective Memory (the paper's cited 13.64% drop), 72.73% w/o adaptive code generation; beat ratio 88.39% vs. 79.91/81.90/84.14.
  • Search dynamics: effective active branches exp(H(π)) falls 4.8 → 2.8 over the run (vanilla MCTS flat at ~4.3); on representative tasks beat ratio reaches 98.2% vs. ~70% for vanilla MCTS, which plateaus early.
  • Mechanism-level ablation (9-task subset): removing intra-branch evolution drops medal 66.67% → 33.33% (largest single factor); removing the knowledge base or the global memory each drops it to 44.44%.

Key advantages

  • State-of-the-art MLE-Bench result at half the standard 24-hour budget (65.3% vs. MARS+ 62.7% and AIBuildAI 63.1%, both at 24h) with 100% valid submissions — an efficiency claim, not just a score claim.
  • Cross-domain check most MLE agents skip: unchanged, it beats specialized algorithm-discovery systems (AlphaEvolve, AlphaEvolve-v2, OpenEvolve) on 11/15 math tasks, evidence the search machinery generalizes past Kaggle.
  • Reference edges are a clean way to get cross-branch information flow without corrupting credit assignment — backpropagation stays strictly on primary edges — and every mechanism ablates positively, with intra-branch evolution isolated as the critical one.
  • Memory accumulates without extra reflection LLM calls: records are logged by a Result Parse Agent and retrieved by BM25+FAISS/RRF, unlike MARS/ROME-style reflection memory, and the two memory halves (static KB vs. dynamic store) are separately ablatable.

Limitations

  • Expensive per task: up to 500 expansion steps over 12h on 21 vCPUs / 234GB RAM, an H200 GPU, and a frontier backbone (Gemini-3.1-Pro-preview); baseline numbers are taken from leaderboards or papers, so comparisons confound framework with different backbone LLMs and budgets.
  • The edge shrinks with difficulty: 46.7% medal on high-complexity tasks only ties AIBuildAI's 46.7% (at 24h), vs. 80.3% on low-complexity — most of the gain over MARS+ comes from medium tasks (64.0% vs. 60.5%).
  • The cold-start knowledge base is manually curated per task type from repositories and competition platforms, so part of performance is static human prior rather than self-evolved; the dynamic memory is task-scoped, not accumulated across tasks (ML-Master 2.0's cross-task caching is the contrast).
  • Ablation statistics are thin: 22 tasks (Lite) for component removal, 9 tasks for mechanism analysis, and some headline cells carry ±0.0 SEM over 3 seeds (gold rate, valid rate, high-complexity).

Where it fits the RSI arc

Stage-8 descendant of AutoML-Zero/AlphaEvolve for whole-ML-algorithm discovery (the repo positions it as AutoMLGen's successor): it keeps the propose-execute-evaluate loop but adds machinery that makes long-horizon search persistent — graph reference edges for cross-branch reuse, an entropy schedule shifting exploration toward exploitation, run-length experience memory, and planner/coder decoupling.
