What it does

SEAL (Self-Adapting LLMs, MIT CSAIL; arXiv 2506.10943) is the official implementation of models RL-trained to emit their own *self-edits* per new input — a list of passage implications or a JSON training config — in two domains: general-knowledge (SQuAD, Qwen2.5-7B) and few-shot (ARC-AGI, Llama-3.2-1B-Instruct).

How it works

  • A self-edit is domain-specific and narrower than the pitch suggests. In general-knowledge it is a generated list of passage *implications* (data_generation/make_squad_data.py prompt variants: implications, implications-long, rewrite, self-qa, chain-of-thought) that is split into finetuning sequences; in few-shot it is a JSON config over a fixed toolbox — four augmentation switches (basic / size / chain / repeat) plus training strategy (`train_using_all_tokens` vs `train_using_output_tokens`), learning_rate and num_train_epochs (utils/prompts.py, self-edit.py).
  • Inner loop = test-time training. general-knowledge/src/inner/TTT_server.py is a stateless ZMQ server (default port 5555) that takes {train_sequences, eval_questions, LoRA hyperparameters}, finetunes a throwaway adapter, then answers the SQuAD questions with base and adapter and grades both with GPT-4.1 (`grade_with_gpt4`), replying with baseline_accuracy / adapter_accuracy / adapter_gain. Few-shot's TTT (arclib/update_model.py) instead builds leave-n (n in {1,2}) examples with the selected augmenters, caps at 250 examples, and trains an r=128, alpha=16 LoRA on q/v/gate/down/up_proj (batch 2, cosine).
  • Reward and selection. The primary reward is downstream accuracy gain after finetuning (`--reward_mode ttt`); a cheaper `proxy` mode has GPT-4.1 score the self-edit text itself on Length / Diversity / Quality / Correctness (1–5 each, summed and clamped to [4,20]). query_server.py samples k completions per article over eval_times TTT runs and reports mean_gain plus mean_adapter_std_over_completions (variance the RL selector can exploit, per its own docstring); src/EM/build_SFT_dataset.py keeps the top-k by adapter_mean and emits an SFT JSONL for the next round.
  • Continual self-edits (paper §5, src/continual/continual_self_edits.py): for K datapoints, self-edit on d_k, finetune one LoRA on that completion plus the raw passage, *merge the adapter into the base weights*, then evaluate the freshly merged model on d_0…d_k — producing a (K+1)×K lower-triangular mean-accuracy and std-dev matrix (defaults 8 sequences × 8 datapoints). Row 0 is the untouched base model.

Key advantages

  • Both domains are runnable end-to-end and the intermediate artifacts are in-tree: iter0/iter1/iter2 synthetic train and eval sets plus EM_SFT jsonl for the 3B model, and few-shot final_results.json — so the ReST-EM loop can be inspected at each iteration without regenerating data. README: all experiments fit on 2 A100/H100 GPUs.
  • The three moving parts are cleanly separated — self-edit generator, ZMQ inner TTT server, outer ReST-EM driver — so reward mode (ttt vs proxy), self-edit representation, and TTT hyperparameters can each be swapped independently; that is exactly the ablation surface an RSI study wants.
  • continual_self_edits.py is one of the few concrete implementations of compounding weight-space self-improvement: each datapoint's LoRA is merged into the base, so later self-edits are generated by a model that already contains the earlier ones, with an explicit matrix protocol for measuring the accumulation.

Install & run

# setup (root README §Setup)
git clone https://github.com/Continual-Intelligence/SEAL && cd SEAL
conda create -n seal_env python=3.12 && conda activate seal_env
pip install -r requirements.txt   # torch 2.7.0, transformers 4.52.4, peft 0.15.2, vllm 0.9.1
# .env: OPENAI_API_KEY=... (GPT-4.1 grades answers, and proxy self-edits in --reward_mode proxy)

# general-knowledge (Qwen/Qwen2.5-7B by default; edit each .sh SLURM header first)
sbatch general-knowledge/scripts/make_squad_data.sh && sbatch general-knowledge/scripts/TTT_server.sh
sbatch general-knowledge/scripts/query_server.sh
python3 general-knowledge/src/EM/build_SFT_dataset.py general-knowledge/results/query_server/train/rank_iter0.json
sbatch general-knowledge/scripts/train_SFT.sh              # one ReST-EM round
sbatch general-knowledge/scripts/continual_self_edits.sh    # paper §5

# few-shot (run from few-shot/, Llama-3.2-1B-Instruct)
python self-edit.py --experiment_name=training_set_iteration_1 --challenge_file=${DATA_DIR}/arc-agi_training_challenges_filtered_1B_training_set.json --solution_file=${DATA_DIR}/arc-agi_training_solutions_filtered_1B_training_set.json --model_name=meta-llama/Llama-3.2-1B-Instruct --n_tasks=12 --n_self_edits_per_task=15
python eval-self-edits.py --experiment_folder=... --pretrained_checkpoint=meta-llama/Llama-3.2-1B-Instruct --lora_checkpoints_folder=... --max_lora_rank=128 --include_n=1 --new_format --n_self_edits=15
python BC-self-edit.py --configs_and_indices=... --results=... --model_name=meta-llama/Llama-3.2-1B-Instruct --lora_rank=16 --lora_alpha=16 --num_train_epochs=8 --per_device_train_batch_size=5 --learning_rate=5e-5

Learning note

Read utils/prompts.py then self-edit.py (the JSON self-edit: augmentation switches + LoRA hyperparameters), TTT_server.py for the reward contract, and continual/continual_self_edits.py for adapter merging. Note few-shot self-edits are toolbox configs, not raw data — the 'finetuning data' half of the pitch lives in general-knowledge.

Repo README

Self-Adapting Language Models

Paper, Website

Adam Zweiger, Jyothish Pari, Han Guo, Ekin Akyürek, Yoon Kim, Pulkit Agrawal

MIT CSAIL

SEAL (Self-Adapting LLMs) is a framework for training language models via RL to generate self-edits (finetuning data and other update directives for themselves) in response to new inputs.

We explore SEAL in two domains:

  • general-knowledge: Incorporating new factual knowledge
  • few-shot: Adapting to new tasks from few-shot examples

Both folders include code, data, and documentation.

🔧 Setup

1. Clone the repository

git clone https://github.com/Continual-Intelligence/SEAL.git
cd SEAL

2. Set up a virtual environment

Using conda:

conda create -n seal_env python=3.12
conda activate seal_env

Using venv:

python3.12 -m venv seal_env
source seal_env/bin/activate

3. Install dependencies

pip install -r requirements.txt

4. Configure environment

Create a .env file in the project root and add your OpenAI API key:

OPENAI_API_KEY=your_openai_api_key_here

5. SLURM users

Before running any shell scripts, make sure to update the SLURM directives at the top of each .sh file to match your system configuration. All experiments can be run with 2 A100/H100 GPUs. Other setups may require refactoring and/or changing model sizes.
