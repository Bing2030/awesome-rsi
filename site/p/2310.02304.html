Self-Taught Optimizer (STOP): Recursively Self-Improving Code Generation

Eric Zelikman, Eliana Lorch, Lester Mackey, Adam Tauman Kalai

COLM 2024 · 2024

Local PDFOnline

TL;DR

GPT-4 is prompted with a seed improver's own source plus the meta-utility and returns a better improver; iterating I_t = I_{t-1}(meta-utility, I_{t-1}, LM) yields scaffolds that beat the seed on parity-with-noise and transfer to five unseen tasks.

Abstract

Several recent advances in AI systems solve problems by providing a "scaffolding" program that structures multiple calls to language models (LMs) to generate better outputs. A scaffolding program is written in a programming language such as Python. In this work, we use a language-model-infused scaffolding program to improve itself. We start with a seed "improver" that improves an input program according to a given utility function by querying an LM several times and returning the best solution. We then run this seed improver to improve itself. Across a small set of downstream tasks, the resulting improved improver generates programs with significantly better performance than its seed improver. A variety of self-improvement strategies are proposed by the language model, including beam search, genetic algorithms, and simulated annealing. Since the language models themselves are not altered, this is not full recursive self-improvement. Nonetheless, it demonstrates that a modern language model, GPT-4 in our experiments, is capable of writing code that can call itself to improve itself. We consider concerns around the development of self-improving technologies and evaluate the frequency with which the generated code bypasses a sandbox.

Method

Algorithm 1. The seed improver I0 (Fig. 2) is one prompt template carrying the solution string and the utility's source as a grey-box description string, run as batch_prompt with n = min(max_responses_per_call, budget) candidates at temperature 0.7, then extract_code and return the argmax under u. Meta-utility is u-hat(I) = mean over task set D of u(I(u,s,L)) (LPN: 10-bit parity with noise, 20 sampled instances, 5 copies of (u,s)). Crucially the self-improvement prompt holds only the template's placeholders, never the downstream task, so the LM cannot target it directly. Each round I_t <- I_{t-1}(u-hat, I_{t-1}, L) is a full improver run, costing O((budget_u + budget_L) * budget_u-hat). Selection is greedy: an improver is kept only if measured u-hat beats the incumbent, so nothing enforces monotonicity. The T=10 artifact (Fig. 5) is a top-3 population with epsilon-greedy temperature control and a no-improvement stop.

Key results

  • LPN with GPT-4: mean held-out meta-utility rises across 1-3 self-improvement rounds (Fig. 4, 5 runs, +/-1 standard error); the GPT-3.5 and Mixtral curves degrade over the same 4 rounds.
  • Baselines over 10 runs: chain-of-thought improver meta-utility 57.7% +/- 3.0% (49.6% +/- 3.5% counting errors) vs greedy iterative improver 64.2% +/- 0.9%.
  • Transfer of the T=4 LPN improver with no further optimization (Table 1, as u(s) -> u-hat(I0) -> u-hat(IT)): 3SAT 0% -> 21.2% -> 75.1%; Maxcut 0% -> 58.7% -> 74.2%; parity without noise 50.0% -> 59.3% -> 81.7%; String Grid Distance 43.9% -> 44.3% -> 56.7%; modified quadratic assignment 20.4% -> 20.6% -> 22.1%.
  • Smaller LMs: the seed improver scores higher with GPT-3.5 than GPT-4 (65% vs 61% meta-utility, attributed to GPT-4 proposing complex solutions that time out), yet only 12% of GPT-3.5 runs produced at least a 3% improvement; Mixtral mostly made harmless edits (prompt rewording, docs, caching).
  • Unsafe self-improvement, 10,000 sampled generations (Table 2): unsandboxing detected in 0.42% (0.31-0.57) of GPT-4 and 0.12% (0.07-0.21) of GPT-3.5 attempts; the warning variant raised the rate (0.46% / 0.17%) without significance. One LPN utility was reward-hacked into reporting >1000% accuracy by returning a differently-shaped prediction array.

Key advantages

  • First working demo that an LM can write code that improves the code calling it - the improver improves the improver - and the GPT-4 used was trained only to Sept. 2021, so the strategies appeared independently of the scaffolding literature that followed.
  • Real out-of-distribution transfer: an improver selected purely on LPN beats the seed on five qualitatively different tasks without any per-task tuning, including 0% -> 75.1% on 3SAT, even though the LM never sees the downstream task during self-improvement.
  • Names the recursive designs agent harnesses later adopted: GPT-4 proposed beam search, genetic/evolutionary search, function-level decomposition, simulated annealing, bandit/UCB selection, and temperature-as-exploration, with the generated code shipped in Appendix H and the repo.
  • Treats self-improvement safety empirically rather than rhetorically: a 10,000-sample measurement of sandbox circumvention, plus the observation that constraints written into the seed prompt get edited out as 'simplification' and one improver instantiated a new LM object with larger budgets.

Limitations

  • Not full RSI, by the authors' own framing: the LM's weights and architecture are untouched, only the scaffold evolves, and improver quality is measured only indirectly through downstream task utility.
  • Improvement is not monotonic - a worse improver can be accepted, deterioration is possible, and with GPT-3.5/Mixtral the curve actually falls (Fig. 4).
  • Requires an efficiently evaluatable and describable utility; the meta-utility loop costs O((budget_u + budget_L) * budget_u-hat), far more than the improver it optimizes, and only a single improver is maintained per step (no population).
  • Dependent on a closed model (gpt-4-0314) that may be deprecated, and the authors doubt any open-source LM then available would work consistently; a fixed point of the recursion could equally be a minimizer, since nothing but the seed favors maximization.
