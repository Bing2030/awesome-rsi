What it does

OpenEvolve — the reference open-source AlphaEvolve: an evolutionary coding agent that turns an LLM into an autonomous program optimizer. Per-island MAP-Elites quality-diversity grid, SEARCH/REPLACE diff mutations, cascade evaluators; pip-installable as `openevolve` (Apache-2.0, 7.4k stars).

How it works

  • One iteration = one process (`_run_iteration_worker` in openevolve/process_parallel.py): snapshot the database, sample a (parent, inspirations) pair from one island, build the prompt, call the LLM ensemble, parse the reply as SEARCH/REPLACE diff blocks (`extract_diffs` → `apply_diff`; the default `diff_based_evolution: true`, with a full-rewrite mode alongside), reject output over `max_code_length` (10000) or with no valid diff, evaluate the child, and return it for `database.add(child, target_island=i)` in the parent process. The coordinator keeps `min(num_workers*2, max_iterations)` iterations in flight, dealt round-robin across the `num_islands` islands.
  • Parent selection is a three-way random split, not top-k (`_sample_parent`): 0.2 `exploration_ratio` → a uniformly random program from the current island; the next 0.7 `exploitation_ratio` → a random archive elite (preferring one tagged with the current island, falling back to exploration); the remaining 0.1 → a uniformly random program anywhere. Inspirations (`_sample_inspirations`) never leave the parent's island — its tracked best, then `elite_selection_ratio`×n top programs, then programs occupying feature cells within ±2 bins of the parent — which is what keeps islands genetically isolated.
  • `ProgramDatabase` is a per-island MAP-Elites grid (`num_islands: 5`) keyed by `'-'.join(feature_coords)`. Dimensions are config (`feature_dimensions`, default `['complexity','diversity']`): `complexity` = len(code), `score`, `diversity` = mean of `_fast_code_diversity` — the approximation `0.1*|Δlen| + 10*|Δlines| + 0.5*|charset symmetric difference|` against a 20-program reference set, *not* the `edit_distance` that `diversity_metric` still advertises — or any custom key your evaluator returns as a raw continuous value (the database min-max scales and bins it; `feature_bins` is 10 by default, raised to `archive_size**(1/len(dims))` when larger). A child occupies a cell only if it beats the incumbent; the incumbent is dropped from the island and, if it then owns no cell and sits in no island, deleted as a 'zombie'. Fitness is `combined_score` when the evaluator supplies it, else the mean of the non-feature metrics (`get_fitness_score`).
  • Migration fires every `migration_interval: 50` generations: each island copies its top `migration_rate: 0.1` by fitness to islands i+1 and i−1 only (ring topology), stamping copies `metadata['migrant']=True` so a lineage migrates at most once, and skipping any target island that already holds identical code. The source comment documents the bug this fixed — one program had accrued 183 descendant copies by iteration 850 — because identical copies collide in the same MAP-Elites cell and waste evaluation budget.

Key advantages

  • It ships an external benchmark with the prompt ablation, not just a demo: examples/algotune reports AlgoTune harmonic-mean 1.381x with generic hints → 1.886x with implementation-specific hints → a final 1.984x across 8 tasks in ~200 minutes, with per-task 321.01x on polynomial_real (JAX JIT; needs `strip_zeros=False` and functions defined outside classes), 256.15x on convolve2d_full_fill (O(N⁴)→O(N²log N) via scipy.signal.fftconvolve), 3.22x on affine_transform_2d (order=0 + float32), 2.20x on fft_cmplx_scipy_fftpack, 1.94x on psd_cone_projection, 1.48x on eigenvectors_complex, 1.38x on fft_convolution, 1.19x on lu_factorization — plus the system-message diff that produced each one, which is what the README means by 'system messages are the secret'.
  • The AlphaEvolve math suite is ported as runnable examples (examples/alphaevolve_math_problems/: circle_packing_rect, erdos_min_overlap, the three autocorr inequalities, heilbronn_triangle/convex, hexagon_packing, kissing_number, matmul, minimizing_max_min_dist, sums_diffs_finite_sets, uncertainty_ineq), and the circle-packing walkthrough is a full documented trajectory — 0.959 random → 1.795 hexagonal rings → 2.201 staggered grid → 2.6343, 99.97% of AlphaEvolve's published 2.635 — where the winning program is a scipy SLSQP constrained optimizer, i.e. the loop discovered the solver rather than a hand-built construction.
  • The LLM backend reaches all the way down to the harness: `llm.provider: 'claude_code'` (openevolve/llm/claude_code.py) shells out to `claude -p --model <name> --no-session-persistence --output-format text --system-prompt <sys> --max-budget-usd <n>`, so evolution runs off a Claude Code CLI OAuth session with no API key; otherwise any OpenAI-compatible endpoint works (Gemini, Ollama, vLLM, an OptiLLM proxy for test-time compute), models are a weighted ensemble with fallback, and `run_evolution(...)` / `evolve_function(...)` in openevolve/api.py run a loop from inline strings with no files on disk.

Learning note

The steering wheel is `prompt.system_message` in config.yaml, not the search code — the AlgoTune ablation (1.381x→1.984x) is pure system-message tuning. Read database.py's add()/_sample_parent/_sample_inspirations for the real selection mechanics. Caveat: the MLX Metal example's own post-fix run ended 3.2% slower than baseline, so the README's '2.8x speedup' is pre-fix.

🚀 Quick Start

Get from zero to evolving code in 30 seconds:

# Install OpenEvolve
pip install openevolve

# The example uses Google Gemini by default (free tier available)
# Get your API key from: https://aistudio.google.com/apikey
export OPENAI_API_KEY="your-gemini-api-key"  # Yes, use OPENAI_API_KEY env var

# Run your first evolution!
python openevolve-run.py examples/function_minimization/initial_program.py \
  examples/function_minimization/evaluator.py \
  --config examples/function_minimization/config.yaml \
  --iterations 50

Note: The example config uses Gemini by default, but you can use any OpenAI-compatible provider by modifying the config.yaml. See the configs for full configuration options.

Library Usage

OpenEvolve can be used as a library without any external files:

from openevolve import run_evolution, evolve_function

# Evolution with inline code (no files needed!)
result = run_evolution(
    initial_program='''
    def fibonacci(n):
        if n <= 1: return n
        return fibonacci(n-1) + fibonacci(n-2)
    ''',
    evaluator=lambda path: {"score": benchmark_fib(path)},
    iterations=100
)

# Evolve Python functions directly
def bubble_sort(arr):
    for i in range(len(arr)):
        for j in range(len(arr)-1):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j] 
    return arr

result = evolve_function(
    bubble_sort,
    test_cases=[([3,1,2], [1,2,3]), ([5,2,8], [2,5,8])],
    iterations=50
)
print(f"Evolved sorting algorithm: {result.best_code}")

How OpenEvolve Works

OpenEvolve implements a sophisticated evolutionary coding pipeline that goes far beyond simple optimization:

Core Innovation: MAP-Elites + LLMs

  • Quality-Diversity Evolution: Maintains diverse populations across feature dimensions
  • Island-Based Architecture: Multiple populations prevent premature convergence
  • LLM Ensemble: Multiple models with intelligent fallback strategies
  • Artifact Side-Channel: Error feedback improves subsequent generations

Advanced Features

Scientific Reproducibility
  • Comprehensive Seeding: Every component (LLM, database, evaluation) is seeded
  • Default Seed=42: Immediate reproducible results out of the box
  • Deterministic Evolution: Exact reproduction of runs across machines
  • Component Isolation: Hash-based isolation prevents cross-contamination
Advanced LLM Integration
  • Universal API: Works with OpenAI, Google, Claude Code CLI, local models, and proxies
  • Intelligent Ensembles: Weighted combinations with sophisticated fallback
  • Test-Time Compute: Enhanced reasoning through proxy systems (see OptiLLM setup)
  • Plugin Ecosystem: Support for advanced reasoning plugins
Evolution Algorithm Innovations
  • Double Selection: Different programs for performance vs inspiration
  • Adaptive Feature Dimensions: Custom quality-diversity metrics
  • Migration Patterns: Ring topology with controlled gene flow
  • Multi-Strategy Sampling: Elite, diverse, and exploratory selection

Cost Estimation

Cost depends on your LLM provider and iterations:

  • o3: ~$0.15-0.60 per iteration (depending on code size)
  • o3-mini: ~$0.03-0.12 per iteration (more cost-effective)
  • Gemini-2.5-Pro: ~$0.08-0.30 per iteration
  • Gemini-2.5-Flash: ~$0.01-0.05 per iteration (fastest and cheapest)
  • Local models: Nearly free after setup
  • OptiLLM: Use cheaper models with test-time compute for better results

Cost-saving tips:

  • Start with fewer iterations (100-200)
  • Use o3-mini, Gemini-2.5-Flash or local models for exploration
  • Use cascade evaluation to filter bad programs early
  • Configure smaller population sizes initially

Quick Example: Function Minimization

Watch OpenEvolve evolve from random search to sophisticated optimization:

# Initial Program (Random Search)
def minimize_function(func, bounds, max_evals=1000):
    best_x, best_val = None, float('inf')
    for _ in range(max_evals):
        x = random_point_in_bounds(bounds)
        val = func(x)
        if val < best_val:
            best_x, best_val = x, val
    return best_x, best_val

Evolution Process

# Evolved Program (Simulated Annealing + Adaptive Cooling)
def minimize_function(func, bounds, max_evals=1000):
    x = random_point_in_bounds(bounds)
    temp = adaptive_initial_temperature(func, bounds)
    
    for i in range(max_evals):
        neighbor = generate_neighbor(x, temp, bounds)
        delta = func(neighbor) - func(x)
        
        if delta < 0 or random.random() < exp(-delta/temp):
            x = neighbor
            
        temp *= adaptive_cooling_rate(i, max_evals)  # Dynamic cooling
    
    return x, func(x)

max_iterations: 1000

llm:

  # MAP-Elites quality-diversity

  num_islands: 5  # Parallel evolution
  migration_interval: 20
  feature_dimensions: ["complexity", "diversity", "performance"]

  # Optional novelty filtering with Gemini embeddings
  embedding_model: "gemini-embedding-001"
  similarity_threshold: 0.99

evaluator:
  enable_artifacts: true      # Error feedback to LLM
  cascade_evaluation: true    # Multi-stage testing
  use_llm_feedback: true      # AI code quality assessment

prompt:
  # Sophisticated inspiration system
  num_top_programs: 3         # Best performers

  include_artifacts: true     # Execution feedback
  
  # Custom templates
