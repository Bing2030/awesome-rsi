Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models

Qizheng Zhang, Changran Hu, Shubhangi Upasani, Boyuan Ma, Fenglu Hong, Vamsidhar Kamanuru, Jay Rainton, Chen Wu, Mengmeng Ji, Hanchen Li, Urmish Thakker, James Zou, Kunle Olukotun

ICLR 2026 · 2026

Local PDFOnlineCode

TL;DR

Treats an LLM's entire context as an evolving playbook of ID'd, helpful/harmful-counted bullets, self-improved by a Generator/Reflector/Curator loop applying structured incremental delta updates with deterministic non-LLM merging — fixing the brevity bias and context collapse of monolithic prompt rewriting.

Abstract

Large language model (LLM) applications such as agents and domain-specific reasoning increasingly rely on context adaptation: modifying inputs with instructions, strategies, or evidence, rather than weight updates. Prior approaches improve usability but often suffer from brevity bias, which drops domain insights for concise summaries, and from context collapse, where iterative rewriting erodes details over time. We introduce ACE (Agentic Context Engineering), a framework that treats contexts as evolving playbooks that accumulate, refine, and organize strategies through a modular process of generation, reflection, and curation. ACE prevents collapse with structured, incremental updates that preserve detailed knowledge and scale with long-context models. Across agent and domain-specific benchmarks, ACE optimizes contexts both offline (e.g., system prompts) and online (e.g., agent memory), consistently outperforming strong baselines: +10.6% on agents and +8.6% on finance, while significantly reducing adaptation latency and rollout cost. Notably, ACE could adapt effectively without labeled supervision and instead by leveraging natural execution feedback. On the AppWorld leaderboard, ACE matches the top-ranked production-level agent on the overall average and surpasses it on the harder test-challenge split, despite using a smaller open-source model. These results show that comprehensive, evolving contexts enable scalable, efficient, and self-improving LLM systems with low overhead.

Method

Context is a structured playbook of itemized bullets, each with metadata (unique ID, helpful/harmful counters) and content (a strategy, concept, or failure mode). Three same-model roles (DeepSeek-V3.1 non-thinking throughout, to isolate context effects) loop: the Generator solves a query while flagging which bullets helped or misled; the Reflector diagnoses the trace — up to 5 refinement rounds — extracting key insights and tagging each bullet helpful/harmful/neutral; the Curator emits compact JSON delta operations (ADD-only in the shipped prompts, IDs system-assigned) merged by deterministic non-LLM logic, so deltas batch in parallel. Grow-and-refine controls growth: counters update in place and semantic-embedding dedup prunes redundancy, either proactively after each delta or lazily when the context window is exceeded. Offline mode runs up to 5 epochs over training queries (system prompts); online mode updates after each test sample (agent memory).

Key results

  • AppWorld (DeepSeek-V3.1, ReAct base avg 42.4): offline ACE 59.4 (+17.0) with GT labels, 57.2 (+14.8) without; beats ICL by 12.3 and GEPA by 11.9 offline, and Dynamic Cheatsheet by 7.6 online (online ACE 59.5, +17.1) — the headline +10.6% agent average.
  • AppWorld leaderboard (09/2025): 59.4% avg matches top-ranked IBM CUGA (60.3%, GPT-4.1-powered) using smaller open-source DeepSeek-V3.1; online ACE surpasses CUGA by 8.4% TGC / 0.7% SGC on test-challenge.
  • Finance (FiNER+Formula, base 69.1 avg): offline ACE with GT 81.9 (+12.8), beating ICL/MIPROv2/GEPA by 10.9 avg; DDXPlus medical 75.2→90.2 (+15.0, vs GEPA's 76.4); BIRD-SQL 47.8→52.9 (+5.1) — the headline +8.6% domain average.
  • Cost: vs GEPA offline AppWorld −82.3% latency (53,898→9,517s), −75.1% rollouts (1,434→357); vs DC online FiNER −91.5% latency (65,104→5,503s), −83.6% token cost ($17.7→$2.9); 86.9% average latency reduction; 91.8% cache hit rate cuts billed input cost 82.6%.
  • Ablation: removing incremental delta updates drops test-normal TGC 76.2→67.3 and SGC 64.3→46.4 (−11.7%/−27.8% relative); gains hold across GPT-OSS-120B, GPT-5.1, and Llama-3.3-70B without algorithm changes.

Key advantages

  • First to name and quantify context collapse — a Dynamic Cheatsheet rewrite on AppWorld shrank 18,282 tokens to 122 in one step, accuracy 66.7→57.1, below the 63.7 no-adaptation baseline — and to fix it structurally via deterministic localized deltas rather than just scoring higher.
  • Self-supervised by construction: +14.8% on AppWorld offline with no GT labels, learning purely from execution feedback; the Reflector is separable and weak reflectors still gain (+5.9 with GPT-OSS-120B), with noise tolerated unless adversarial every single step.
  • The ADD-only, system-ID'd, helpful/harmful-counted bullet playbook merged by non-LLM code is directly portable discipline for any RSI harness with unboundedly growing notes — hyperparameters prove forgiving (dedup 50–90%, pruning trigger 10K–100K tokens, all stable).
  • Reframes long-context cost: richer playbooks don't scale billed cost linearly because KV/prompt caching amortizes reused context (91.8% of eval input tokens served from cache on GPT-5.1).

Limitations

  • Feedback quality is load-bearing — the paper's own caveat: without GT labels or reliable execution signals, ACE degrades (FiNER online no-GT 67.3, −3.4) as spurious reflections pollute the playbook, and it drops below base under adversarial reflections every step (66.7 vs 70.7).
  • Relies on a reasonably strong Reflector: weak models show smaller gains (Llama-3.3-70B reflects noisily), and over-reflection hurts — 10 rounds degrade to 65.2 avg vs 67.6 at 5 ('overthinking' injects noisy updates).
  • Not for concise-context tasks: the paper concedes HotPotQA-style retrieval QA and fixed-strategy games like Game of 24 benefit more from terse instructions than comprehensive playbooks — detail-heavy domains are where it wins.
  • Context capacity is managed by dedup/pruning thresholds, not eliminated; leader-board comparison to IBM CUGA is explicitly a rough contextual reference, not a controlled baseline.
