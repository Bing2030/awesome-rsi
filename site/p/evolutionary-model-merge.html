Evolutionary Model Merge

repo

GitHub

What it does

Sakana AI's hub for the Evolutionary Model Merge series (Nature Machine Intelligence 2025): the released EvoLLM-JP / EvoVLM-JP merged checkpoints plus the harness that reproduces the paper's evaluation. The CMA-ES merge search itself is not in this repo.

How it works

  • Evaluation-only codebase: the tree is evaluate.py plus evomerge/{eval,models,modules} — no search code. A GitHub code search for `cma` across the repo returns 0 hits; README states it "serves as a central hub ... includes models and code for reproducing the evaluation presented in our paper." The merge optimizer lives in the paper, which the card's context below draws from.
  • The evolved space, per arXiv 2403.13187: (a) parameter space — DARE-TIES sparsification plus per-layer weight-mixing coefficients (one config per embedding/transformer block), optimized by Optuna's CMA-ES with all initial values 0.5, sigma 1/6, population 4+⌊3·ln(n_params)⌋, 1000 trials, fitness = accuracy on 1069 held-out Japanese GSM8k items; (b) data-flow space — an indicator array I over M=64 layers repeated r=3 times (so T=192 slots) plus a scaling matrix W, optimized by EvoJAX CMA-ES for 100 generations, population 128, with W forced to 1 on same-model adjacent hops so any gain comes from layer stacking/permutation alone.
  • Config-driven runner: each YAML pairs a model with one or more evaluators. Models are evomerge.CausalLMWithvLLM (vLLM backend, default template ja-alpaca-cot, stop tokens Instruction:/Response:) or evomerge.LLaVA for the VLM; evaluate.py loads the config, set_seed(42), instantiates, runs evaluator(model), and writes results/<config-basename>.json.
  • Three evaluators ship in-tree: JaMGSM (juletxara/mgsm, ja test split), JaVGVQA (SakanaAI/JA-VG-VQA-500) and JaVLMBenchIntheWild (SakanaAI/JA-VLM-Bench-In-the-Wild). MGSM-JA is zero-shot pass@1 accuracy on the last number regex-extracted from the response; every evaluator also reports a `_ja` strict variant that calls fasttext on lid.176.ftz and zeroes answers not labeled Japanese with p>0.5. VLM scoring is MeCab-tokenized ROUGE-L after neologdn full/half-width normalization.

Key advantages

  • The released weights are the artifact: EvoLLM-JP-v1-7B scores 52.0 MGSM-JA and 70.5 on lm-eval-harness JP average where its source models sit at or below 30.0 and 66.1; EvoLLM-JP-v1-10B reaches 55.6/66.2 and EvoLLM-JP-A-v1-7B 52.4/69.0. Weight-level capability gain with zero gradient steps — the cleanest demonstration in the catalog that recombination is a distinct improvement operator.
  • The harness encodes the exact protocol behind those claims, not a leaderboard snapshot: the fasttext Japanese-answer gate, the last-number extraction heuristic (needed because source models use incompatible output formats), and MeCab-tokenized ROUGE for VQA are all visible and re-runnable.
  • EvoLLM-JP-v1-10B is produced by merging EvoLLM-JP-v1-7B with shisa-gamma-7b-v1 — a merge of a merge — and EvoVLM-JP crosses modality (LLaVA-1.6-Mistral-7B + shisa-gamma-7b-v1), so the released set doubles as a worked example of iterated and cross-domain recombination.

Install & run

git clone https://github.com/SakanaAI/evolutionary-model-merge.git && cd evolutionary-model-merge
# download fasttext lid.176.ftz into the cwd, or point LID176FTZ_PATH at it
pip install -e .
python evaluate.py --config_path configs/llm/evollm-v1-jp-7b.yaml
# VLM: python evaluate.py --config_path configs/vlm/evovlm-v1-jp-7b.yaml
# tested on Python 3.10.12, CUDA 12.3; vllm is pinned to the SakanaAI/vllm fork rev 538aa22a278dc731bc09bb968af2eae909a834c7

Learning note

Open it for the evaluation protocol, not the search. Read evomerge/eval/metrics.py (fasttext Japanese gate, MeCab ROUGE) and evomerge/eval/ja_mgsm.py, then diff configs/llm/evollm-v1-jp-7b.yaml against a source-model config. Pair with the 2403.13187 paper for the CMA-ES search space the weights came from.

Reproducing the Evaluation

1. Clone the Repo

git clone https://github.com/SakanaAI/evolutionary-model-merge.git
cd evolutionary-model-merge

2. Download fastext Model

We use fastext to detect language for evaluation. Please download lid.176.ftz from this link and place it in your current directory. If you place the file in a directory other than the current directory, specify the path to the file using the LID176FTZ_PATH environment variable.

3. Install Libraries

pip install -e .

We conducted our tests in the following environment: Python Version 3.10.12 and CUDA Version 12.3. We cannot guarantee that it will work in other environments.

4. Run

To launch evaluation, run the following script with a certain config. All configs used for the paper are in configs.

python evaluate.py --config_path {path-to-config}
