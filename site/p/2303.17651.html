Self-Refine: Iterative Refinement with Self-Feedback

Aman Madaan, Niket Tandon, Prakhar Gupta, Skyler Hallinan, Luyu Gao, Sarah Wiegreffe, Uri Alon, Nouha Dziri, Shrimai Prabhumoye, Yiming Yang, Shashank Gupta, Bodhisattwa Prasad Majumder, Katherine Hermann, Sean Welleck, Amir Yazdanbakhsh, Peter Clark

NeurIPS 2023 · 2023

Local PDFOnline

TL;DR

Self-Refine: one frozen LLM generates an output, critiques it, then rewrites it from that critique, iterating with no training, extra data, or reward model — improving 7 tasks by ~20% absolute on average.

Abstract

Like humans, large language models (LLMs) do not always generate the best output on their first try. Motivated by how humans refine their written text, we introduce Self-Refine, an approach for improving initial outputs from LLMs through iterative feedback and refinement. The main idea is to generate an initial output using an LLMs; then, the same LLMs provides feedback for its output and uses it to refine itself, iteratively. Self-Refine does not require any supervised training data, additional training, or reinforcement learning, and instead uses a single LLM as the generator, refiner, and feedback provider. We evaluate Self-Refine across 7 diverse tasks, ranging from dialog response generation to mathematical reasoning, using state-of-the-art (GPT-3.5, ChatGPT, and GPT-4) LLMs. Across all evaluated tasks, outputs generated with Self-Refine are preferred by humans and automatic metrics over those generated with the same LLM using conventional one-step generation, improving by ~20% absolute on average in task performance. Our work demonstrates that even state-of-the-art LLMs like GPT-4 can be further improved at test time using our simple, standalone approach.

Method

Training-free, inference-only loop on a single frozen model M with three few-shot prompts. (1) Generate y0 = M(pgen || x). (2) FEEDBACK: fb_t = M(pfb || x || y_t), where pfb carries input-output-feedback triples whose feedback must be 'actionable' (names a concrete fix) and 'specific' (names the phrase or loop to change). (3) Stop check: stop(fb_t, t) either fires after a fixed timestep or reads a scalar stop score the model emits in pfb; otherwise (4) REFINE: y_{t+1} = M(prefine || x || y0 || fb0 || ... || y_t || fb_t) — the full output/feedback history is retained so the model does not repeat past mistakes. Iterate to at most 4 rounds; return the last refinement. Greedy decoding, temperature 0.7, no weight updates.

Key results

  • Table 1, 7 tasks x 3 base LLMs, the same model with vs without the loop: Constrained Generation GPT-4 15.0 -> 45.0 and ChatGPT 44.0 -> 67.0 coverage; Dialogue Response GPT-4 25.4 -> 74.6 and GPT-3.5 36.4 -> 63.6 preference; Sentiment Reversal GPT-4 3.8 -> 36.2, ChatGPT 11.4 -> 43.2; Code Optimization GPT-4 27.3 -> 36.0, GPT-3.5 14.8 -> 23.0; Code Readability GPT-4 27.4 -> 56.2; Acronym Generation GPT-3.5 41.6 -> 56.4.
  • Math Reasoning is the flat case (Table 1): GPT-3.5 64.1 -> 64.1 (0), ChatGPT 74.8 -> 75.0, GPT-4 92.9 -> 93.1 — the authors trace it to the model feeding back 'everything looks good' for 94% of ChatGPT instances.
  • Iterations help but saturate (Figure 4 left, averaged over the three models): Code Optimization 22.0 (y0) -> 27.0 -> 27.9 -> 28.8 (y3); Sentiment Reversal 33.9 -> 36.8; Constrained Generation 29.0 -> 49.7 at y3, with marginal gain shrinking each round.
  • Feedback quality is the causal lever (Table 2, actionable vs generic vs no feedback): Code Optimization 27.5 / 26.0 / 24.8, Sentiment Reversal 43.2 / 31.2 / 0, Acronym Generation 56.4 / 54.0 / 48.0 — the model may still iterate without feedback, and the task then fails outright.
  • Against fine-tuned and sampled baselines on the PIE code-optimization benchmark (Table 8, %OPT): Self-Refine with GPT-4 36.0 using at most 4 samples, vs PIE-16B best@32 26.6, PIE-few-shot best@32 38.3, and human references 12.6 / 19.6. With an oracle correctness signal on math the gains reappear (Table 9): GPT-3.5 64.06 -> 68.9, ChatGPT 74.8 -> 76.2, GPT-4 92.9 -> 93.8.

Key advantages

  • Trains nothing: no supervised refinement data, reward model, RL, or separate refiner — one model plays generator, feedback provider and refiner, and only the three few-shot prompts change across 7 heterogeneous tasks (dialogue, code optimization, code readability, math, sentiment reversal, acronyms, constrained generation).
  • Shows refinement beats spending the same budget on sampling: in a 1-vs-k human evaluation, Self-Refine's output was preferred over all k = 4 plain ChatGPT samples, so the gain is the feedback-conditioned revision, not extra generations.
  • Quantifies the mechanism rather than asserting it — the feedback ablation (Table 2) shows actionable, specific feedback is what carries the improvement, and the manual analysis of 70 cases found 61% of failures were bad fixes suggested by feedback and only 6% were the refiner misimplementing good feedback.
  • Establishes the reference template for test-time self-improvement — generate, critique, refine, retain history, stop on a scored signal — and reports Wilson confidence intervals (Table 13) showing nearly all GPT-4 gains significant, ChatGPT 4/7 and GPT-3.5 3/7.

Limitations

  • Requires a strong instruction-following base model. Vicuna-13B could not reliably emit feedback in the required format, and even given oracle or hard-coded feedback it repeated its output or hallucinated dialogue instead of refining (Appendix G) — though Vicuna-13b initialized at 24.18% on math did reach 40.5% when ChatGPT supplied the feedback and refinement.
  • Feedback is the bottleneck and it is self-generated: on math the model declares the answer fine in 94% of ChatGPT cases, and in the audited failures 33% of errors came from feedback mislocating the bug and 61% from feedback proposing an inappropriate fix.
  • All base LLMs are closed (text-davinci-003, gpt-3.5-turbo, GPT-4, code-davinci-002) with undisclosed pretraining data, sizes and biases, and are paid to use; the paper's own limitation section also notes the evaluation is English-only with no guard against prompting a model toward toxic or harmful text.
  • The stopping rule is essentially a fixed budget of up to 4 FEEDBACK-REFINE rounds or a prompted per-task scalar score rather than a learned criterion, and gains are already diminishing after the first iteration.
