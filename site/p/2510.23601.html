Alita-G: Self-Evolving Generative Agent for Agent Generation

Jiahao Qiu, Xuan Qi, Hongru Wang, Xinzhe Juan, Yimin Wang, Zelin Zhao, Jiayi Geng, Jiacheng Guo, Peihang Li, Jingzhe Shi, Shilong Liu, Mengdi Wang

arXiv 2025 · 2025

Local PDFOnline

TL;DR

Alita-G turns a generalist agent into a domain expert by harvesting MCP tools from its own successful GAIA/PathVQA/HLE runs, abstracting them into parameterized FastMCP primitives, and retrieving them per task by description-plus-use-case RAG — 83.03% pass@1 on GAIA.

Abstract

Large language models (LLMs) have been shown to perform better when scaffolded into agents with memory, tools, and feedback. Beyond this, self-evolving agents have emerged, but current work largely limits adaptation to prompt rewriting or failure retries. Therefore, we present ALITA-G, a self-evolution framework that transforms a general-purpose agent into a domain expert by systematically generating, abstracting, and curating Model Context Protocol (MCP) tools. In this framework, a generalist agent executes a curated suite of target-domain tasks and synthesizes candidate MCPs from successful trajectories. These are then abstracted to parameterized primitives and consolidated into an MCP Box. At inference time, ALITA-G performs retrieval-augmented MCP selection with the help of each tool's descriptions and use cases, before executing an agent equipped with the MCP Executor. Across several benchmarks GAIA, PathVQA, and Humanity's Last Exam, ALITA-G attains strong gains while reducing computation costs. On GAIA validation, it achieves 83.03% pass@1 and 89.09% pass@3, establishing a new state-of-the-art result while reducing mean tokens per example by approximately 15% relative to a strong baseline agent. ALITA-G thus provides a principled pathway from generalist capability to reusable, domain-specific competence, improving both accuracy and efficiency on complex reasoning tasks.

Method

A master agent (Alita architecture: Claude-Sonnet-4 Manager + GPT-4.1 Web Agent) executes each target-domain task K times, explicitly prompted to externalize reusable sub-solutions as self-contained MCPs, each carrying code, a description, and the use_case that triggered it. Only MCPs from successful runs (πmaster(xi)=yi) enter the raw pool. A high-capacity abstraction LLM then converts each into a reusable primitive via four operations — parameter generalization (hard-coded values lifted to arguments), context removal, FastMCP interface standardization, docstring/type-annotation enrichment — producing the MCP Box; diversity is deliberately preserved instead of clustered. At inference, description⊕use_case is embedded (text-embedding-3-large) and scored against the task embedding by cosine similarity; MCPs above τ=0.7 (or top-k) load into the MCP Executor that the specialized agent calls mid-reasoning. No weights or prompts of the master change.

Key results

  • GAIA validation set: Alita-G with a 3× MCP Box reaches 83.03% pass@1 and 89.09% pass@3 (paper's claimed new SOTA), vs 75.15% pass@1 for the same master agent with no MCP Box (+10.3% relative) and 55.15% for ODR-smolagents (+50.5% relative); a single-generation box gives 80.00% pass@1.
  • Accuracy and cost improve together: mean tokens per GAIA example drop to 10,394 (3×) from 12,305 for the un-augmented master — a 15.5% reduction — because retrieval replaces broad tool search.
  • Other domains (100 sampled examples each): PathVQA 52% → 60% and HLE 24% → 33% pass@1 over the original agent; 3× beats 1× on both.
  • MCP Box richness scales then saturates: k=1/2/3/4/5 iterations yield 26/46/74/102/128 curated MCPs and 80.00/81.82/83.03/83.03/83.63% GAIA accuracy, while effective coverage (#clusters/#MCPs) decays 1.00 → 0.51 as mean pairwise MCP similarity rises 0.28 → 0.34 — later rounds add near-duplicates.
  • Ablations: retrieval on description+use_case 83.03% vs description-only 81.82% vs use_case-only 77.57%; on a 25-question GAIA subset threshold selection at τ=0.70 hits 84.0% (τ=0.90 collapses to 68.0%) and top-k peaks at 80.0% (k=2/3); encoder choice moves 72.0% (BGE-M3) to 84.0% (text-embedding-3-large). Usage tracks gains: MCP calls per question 1.9 → 2.4 (2.7 → 3.4 on improved questions), with 9/12/13 Wrong→Right flips against 1/1/0 Right→Wrong over 1/2/3 generations.

Key advantages

  • First framework to couple MCP abstraction with MCP-level RAG (the paper's claim): the 'self-evolution' lever is a curated, retrievable tool corpus rather than prompt rewriting or failure-retry heuristics, and the payoff is auditable as flips — net +8/+11/+13 Wrong→Right on GAIA with regressions falling to zero by three generations.
  • Breaks the usual accuracy-versus-cost tradeoff: +7.9 points over the master agent on GAIA while using ~15% fewer tokens, because the specialized agent retrieves a small relevant tool set instead of searching a broad tool space.
  • The evolved artifact is standard and inspectable: FastMCP-compatible parameterized code plus description/use_case metadata, so domain competence sits in a swappable box; the case study shows an abstracted extract_pdf_measurement turning a failed Freon-12 answer (20 mL) into the correct 55 mL by pulling real thermodynamic properties.
  • Gives an explicit redundancy dial: K-run harvesting plus similarity/cluster statistics (26 → 65 connected components under τ=0.7) identifies k=3 as the point that captures most distinct MCP families before duplicates dominate, rather than assuming more generations always help.

Limitations

  • Non-GAIA results rest on 100 sampled examples each (PathVQA, HLE) — the paper cites resource constraints — so those gains are far noisier than the full-validation-set GAIA numbers that carry the headline.
  • Evolution is entirely non-parametric at the tool layer: the master agent's weights and prompts are frozen, so the ceiling is set by the base model and by abstraction-LLM quality, and tool acceptance is gated only on the task having succeeded — no independent verification that harvested tool code is correct or reusable.
  • Diminishing returns are the paper's own finding: past k=3 average GAIA accuracy is flat (+0.6 points at k=5) while curated MCPs grow 74 → 128 and clusters only 52 → 65, i.e. later iterations mostly mint narrow variants; the paper leaves richer evolution to future work.
  • Selection is hyperparameter-fragile and tuned on a small sample: over 25 GAIA validation questions accuracy swings 68.0–84.0% across τ ∈ {0.65…0.90} and 72.0–84.0% across encoders, so the deployment defaults (τ=0.70, text-embedding-3-large) are not robust settings so much as measured optima.
