Darwin Gödel Machine

repo

GitHub

What it does

Official implementation of the Darwin Gödel Machine (arXiv 2505.22954, Sakana AI + UBC): a coding agent that rewrites its own codebase, validates every candidate self-modification on SWE-bench/Polyglot in Docker, and archives each compiled variant as a parent future variants build on.

How it works

  • Outer loop (`DGM_outer.py`): up to `--max_generation 80` generations, each spawning `--selfimprove_size 2` parallel improvement attempts. `choose_selfimproves` picks a parent from the archive plus a target — a 25% roll each for `solve_empty_patches` (only if ≥10% of the parent's eval came back empty), `solve_stochasticity`, or `solve_contextlength`, else a random unresolved SWE-bench instance; an o1 diagnoser (`diagnose_model='o1-2024-12-17'`) converts that parent's failure logs into the `problem_statement` handed to the improver.
  • Improvement is a patch, not a commit: each attempt builds a fresh `dgm` Docker container, replays the entire ancestral chain of `model_patch.diff` files (`get_model_patch_paths` walks `parent_commit` links back to `initial`, applying them with `patch -p1`), then runs `coding_agent.py --self_improve` (bash + edit tools, 30-min timeout) whose edits are captured by `diff_versus_commit` as a new `model_patch.diff` against the DGM's own source.
  • Archive is a scored phylogenetic tree, not a leaderboard: every node stores accuracy plus `parent_commit`; the default parent sampler `score_child_prop` weights nodes by sigmoid(10·(score−0.5)) × 1/(children+1) — objective quality times novelty pressure. Default `--update_archive keep_all` keeps every child passing `is_compiled_self_improve` (non-empty patch, full subset actually evaluated) even when it didn't improve; `keep_better` (≥ initial score − `--eval_noise 0.1`) and the `--run_baseline` ablations (`no_darwin` = greedy always-latest-commit, `no_selfimprove`) isolate what open-endedness buys.
  • Staged empirical gate: children are scored on a small SWE-bench Verified subset, promoted to a medium subset only at ≥0.4 resolution (`test_more_threshold`), and get the full evaluation only above `get_full_eval_threshold` — the second-highest fully-evaluated archive score, floored at 0.4. `--polyglot` swaps in `coding_agent_polyglot.py` and the Aider Polyglot harness.

Key advantages

  • The substrate where the object under improvement is the improver's own executable source: the archived patch edits the tool/loop code that produces the next patches, so tool, prompt, and control-flow improvements compound across generations.
  • A unusually clean open-endedness control: `--run_baseline no_darwin` ablates exactly the archive-based parent selection while holding the improver fixed, and `keep_all` vs `keep_better` tests whether retaining 'failed but compiled' cousins — not just hill-climbing — drives the gains.
  • Ships the full experiment apparatus: `initial/` reference eval logs defining the starting agent's baseline, staged small→medium→full evaluation to keep Dockerized SWE-bench runs affordable, and the paper's complete model-output logs on Google Drive.

Install & run

Docker + Python venv; export OPENAI_API_KEY and ANTHROPIC_API_KEY. `pip install -r requirements.txt`; in `swe_bench/` clone SWE-bench at pinned commit `dc4c087c2b9e4cefebf2e3d201d27e36` and `pip install -e .`; `python -m polyglot.prepare_polyglot_dataset`; then `python DGM_outer.py` (default output `output_dgm/`; `--polyglot` for the Polyglot run).

Learning note

Read `choose_selfimproves` and `update_archive` in DGM_outer.py — the score×novelty parent sampler and keep_all archive — against the `no_darwin` baseline, then `self_improve_step.py`'s container-per-attempt patch replay. README warning: it executes untrusted model-generated code.

Repo README

Darwin Gödel Machine:
Open-Ended Evolution of Self-Improving Agents

Repository for Darwin Gödel Machine (DGM), a novel self-improving system that iteratively modifies its own code (thereby also improving its ability to modify its own codebase) and empirically validates each change using coding benchmarks.

Setup

# API keys, add to ~/.bashrc
export OPENAI_API_KEY='...'
export ANTHROPIC_API_KEY='...'

# Verify that Docker is properly configured in your environment.
docker run hello-world
 
# If a permission error occurs, add the user to the Docker group
sudo usermod -aG docker $USER
newgrp docker

# Install dependencies
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Optional: for running analysis
sudo apt-get install graphviz graphviz-dev
pip install -r requirements_dev.txt

# Clone SWE-bench
cd swe_bench
git clone https://github.com/princeton-nlp/SWE-bench.git
cd SWE-bench
git checkout dc4c087c2b9e4cefebf2e3d201d27e36
pip install -e .
cd ../../

# Prepare Polyglot
# Make sure git is properly configured in your environment with username and email
python -m polyglot.prepare_polyglot_dataset

Running the DGM

python DGM_outer.py

By default, outputs will be saved in the output_dgm/ directory.

File Structure

  • analysis/ scripts used for plotting and analysis
  • initial/ SWE-bench logs and performance of the initial agent
  • initial_polyglot/ Polyglot logs and performance of the initial agent
  • swe_bench/ code needed for SWE-bench evaluation
  • polyglot/ code needed for Polyglot evaluation
  • prompts/ prompts used for foundation models
  • tests/ tests for the DGM system
  • tools/ tools available to the foundation models
  • coding_agent.py main implementation of the initial coding agent
  • DGM_outer.py entry point for running the DGM algorithm

Safety Consideration

[!WARNING]
This repository involves executing untrusted, model-generated code. We strongly advise users to be aware of the associated safety risks. While it is highly unlikely that such code will perform overtly malicious actions under our current settings and with the models we use, it may still behave destructively due to limitations in model capability or alignment. By using this repository, you acknowledge and accept these risks.
