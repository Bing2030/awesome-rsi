A-MEM: Agentic Memory for LLM Agents

Wujiang Xu, Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang

NeurIPS 2025 · 2025

Local PDFOnline

TL;DR

A-MEM turns agent memory into a self-organizing Zettelkasten: each interaction becomes an LLM-annotated note (keywords, tags, context, embedding), new notes link to nearest neighbours and rewrite them, beating MemGPT/MemoryBank on LoCoMo while using ~1,200 tokens per operation.

Abstract

While large language model (LLM) agents can effectively use external tools for complex real-world tasks, they require memory systems to leverage historical experiences. Current memory systems enable basic storage and retrieval but lack sophisticated memory organization, despite recent attempts to incorporate graph databases. Moreover, these systems' fixed operations and structures limit their adaptability across diverse tasks. To address this limitation, this paper proposes a novel agentic memory system for LLM agents that can dynamically organize memories in an agentic way. Following the basic principles of the Zettelkasten method, we designed our memory system to create interconnected knowledge networks through dynamic indexing and linking. When a new memory is added, we generate a comprehensive note containing multiple structured attributes, including contextual descriptions, keywords, and tags. The system then analyzes historical memories to identify relevant connections, establishing links where meaningful similarities exist. Additionally, this process enables memory evolution - as new memories are integrated, they can trigger updates to the contextual representations and attributes of existing historical memories, allowing the memory network to continuously refine its understanding. Our approach combines the structured organization principles of Zettelkasten with the flexibility of agent-driven decision making, allowing for more adaptive and context-aware memory management. Empirical experiments on six foundation models show superior improvement against existing SOTA baselines. The source code for evaluating performance is available at https://github.com/WujiangXu/A-mem, while the source code of the agentic memory system is available at https://github.com/WujiangXu/A-mem-sys.

Method

Each interaction becomes one atomic note m = {content, timestamp, LLM keywords K, LLM tags G, LLM context X, embedding e, links L}. A note-construction prompt (Appendix B.1) makes a structured LLM call returning keywords/tags/context as JSON; e = encoder(concat(c,K,G,X)) with all-minilm-l6-v2. On write, cosine similarity against every stored note selects top-k neighbours (k=10 by default, tuned 10-50 per model and category, Table 8). A second LLM call then returns structured JSON - should_evolve, actions (strengthen, update_neighbor), suggested_connections, tags_to_update, new_context_neighborhood - which establishes the links and rewrites the neighbours' context and tags in place, so existing notes change as new ones arrive. Retrieval embeds the query, takes top-k by cosine, and (per Figure 2) co-accesses notes linked in the same 'box'. No weights are trained: all structure is inference-time LLM calls over a growing note store.

Key results

  • LoCoMo across six frozen models (Llama 3.2 1B/3B, Qwen2.5 1.5B/3B, GPT-4o, GPT-4o-mini): A-MEM takes the best average rank in every model (1.0-1.6) while no baseline ranks better than 2.0; it beats every baseline in every category for the non-GPT models, and on GPT models is 'at least two times better' on Multi-Hop (GPT-4o-mini: ROUGE-L 44.27 vs LoCoMo 18.09, METEOR 23.43 vs 7.61, SBERT 70.49 vs 52.30).
  • DialSim (Table 2, A-MEM vs LoCoMo vs MemGPT): F1 3.45 vs 2.55 vs 1.18 (+35% over LoCoMo, +192% over MemGPT), BLEU-1 3.37 vs 3.13 vs 1.07, ROUGE-L 3.54 vs 2.75 vs 0.96, ROUGE-2 3.60 vs 0.90 vs 0.42, METEOR 2.05 vs 1.64 vs 0.95, SBERT 19.51 vs 15.76 vs 8.54.
  • Ablation on GPT-4o-mini (Table 3), no link generation or evolution -> link generation only -> full A-MEM: Multi-Hop F1 9.65 -> 21.35 -> 27.02; Temporal 24.55 -> 31.24 -> 45.85; Single Hop 13.28 -> 39.17 -> 44.65; Adversarial 15.32 -> 44.16 -> 50.03; Open Domain 7.77 -> 10.13 -> 12.14.
  • Cost: roughly 1,200 tokens per memory operation (1,200-2,500 depending on model) against 16,900 for LoCoMo and MemGPT, an 85-93% reduction, under $0.0003 per operation; 5.4 s average per operation on GPT-4o-mini and 1.1 s on locally hosted Llama 3.2 1B.
  • Scaling (Table 4): retrieval latency 0.31 us at 1,000 notes, 0.38 at 10,000, 1.40 at 100,000, 3.70 at 1,000,000, versus ReadAgent's 43.62 / 484.45 / 6,682.22 / 120,069.68 us; storage is identical linear O(N) for A-MEM, MemoryBank and ReadAgent (1.46 MB at 1,000 notes rising to 1,464.84 MB at 1M).

Key advantages

  • The agency is in storage, not retrieval: A-MEM's second LLM call rewrites both the link graph and the text of existing notes, whereas agentic RAG (§2.2's own contrast) keeps a static knowledge base and only decides when/what to fetch. Nothing is pre-specified - no schema, no write points in the workflow, no fixed topology.
  • The ablation isolates both mechanisms with the right ordering: dropping link generation and evolution collapses Multi-Hop to 9.65 F1 and Adversarial to 15.32, restoring linking alone reaches 21.35 / 44.16, and evolution adds the rest - so the graph is load-bearing, not decoration.
  • It wins while being cheaper and scalable: ~1/10 the tokens of LoCoMo and MemGPT per operation, sub-microsecond retrieval that grows only ~12x from 1K to 1M notes (3.70 us, vs ReadAgent's 120,069 us), and no storage overhead over plain vector baselines.
  • Model-agnostic and released: works over six frozen backbones from 1B local (Ollama, LiteLLM structured output) to GPT-4o with zero weight updates, and both the benchmark code and a production memory service are public.

Limitations

  • The paper's own first limitation: organization quality is bounded by the underlying LLM - different models generate different contexts and links, so the memory inherits the backbone's capability and variance.
  • The paper's own second limitation: text only. Multimodal memories (images, audio) are left as future work, and the whole note schema assumes textual interaction turns.
  • Memory only grows: the evolution prompt can name 'merge' and 'prune' actions, but §3.3 implements only in-place context/keyword/tag rewrites - there is no dedup, deletion or forgetting, and no audit of evolved-note quality or of how many generated links are wrong.
  • Evidence is conversational QA only (LoCoMo, DialSim) scored by F1/BLEU/ROUGE/METEOR/SBERT, with k tuned per category and model against those same evaluation categories (Table 8); no downstream agent task, and no test of whether the shipped links survive beyond the benchmark.

Where it fits the RSI arc

Stage 4's memory-organization centre: it lifts the Reflexion/ExpeL/ACE line from append-and-retrieve to self-linking, self-rewriting notes. Pairs with MemoryBank (a fixed decay curve where A-MEM has agentic reorganization), MemEvolve (which evolves the memory system itself and uses A-MEM as a baseline), EvolveR (experience into RL), and ACE (context as the evolving artifact).
