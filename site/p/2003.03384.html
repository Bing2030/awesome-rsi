AutoML-Zero: Evolving Machine Learning Algorithms From Scratch

Esteban Real, Chen Liang, David R. So, Quoc V. Le

ICML 2020 · 2020

Local PDFOnline

TL;DR

Searches whole ML algorithms symbolically — Setup/Predict/Learn programs over 65 basic scalar/vector/matrix ops — and evolves two-layer nets trained by backprop, bilinear multiplicative interactions, unit-normalized gradients and accumulated-weight averaging that beat hand-designed baselines on CIFAR-10.

Abstract

Machine learning research has advanced in multiple aspects, including model structures and learning methods. The effort to automate such research, known as AutoML, has also made significant progress. However, this progress has largely focused on the architecture of neural networks, where it has relied on sophisticated expert-designed layers as building blocks---or similarly restrictive search spaces. Our goal is to show that AutoML can go further: it is possible today to automatically discover complete machine learning algorithms just using basic mathematical operations as building blocks. We demonstrate this by introducing a novel framework that significantly reduces human bias through a generic search space. Despite the vastness of this space, evolutionary search can still discover two-layer neural networks trained by backpropagation. These simple neural networks can then be surpassed by evolving directly on tasks of interest, e.g. CIFAR-10 variants, where modern techniques emerge in the top algorithms, such as bilinear interactions, normalized gradients, and weight averaging. Moreover, evolution adapts algorithms to different task types: e.g., dropout-like techniques appear when little data is available. We believe these preliminary successes in discovering machine learning algorithms from scratch indicate a promising new direction for the field.

Method

An algorithm is a three-function program — Setup, Predict, Learn — over a small zero-initialized virtual memory of scalar/vector/matrix addresses. Predict reads features (v0) and writes its prediction to s1 (sigmoid/softmax-normalized); Learn then sees the label (s0) and may update memory; validation runs Predict alone. The 65 ops are high-school math (add, dot, outer, sin, gauss, heaviside) — no derivatives, batches or convolutions — so any gradient used for training must be evolved. Search is regularized evolution: population P of initially empty programs; each cycle picks T=10 at random, copies the best, mutates it (insert/remove instruction, randomize a function, tweak an argument), evicts the oldest. Functional equivalence checking hashes 20 predictions to reuse cached scores (4x speedup); hurdles early-stop below the population's rolling 75th percentile (75% of compute saved); up to W=10,000 single-core workers migrate half their populations through a central server; half also search projected MNIST.

Key results

  • Best evolved algorithm on the original 3072-dim CIFAR-10 test set: 84.06 ± 0.10% vs logistic regression 77.65 ± 0.22% and a 2-layer fully connected net trained by gradient descent 82.22 ± 0.17%, all tuned with equal compute, 5 seeds.
  • Gains transfer to other binary classification datasets (evolved / linear / nonlinear): SVHN 88.12% vs 59.58% vs 85.14%; downsampled ImageNet 80.78% vs 76.44% vs 78.44%; Fashion MNIST 98.60% vs 97.90% vs 98.21%.
  • From empty programs it re-invents backprop: with one search task (D=1) evolution hard-codes the teacher net's weights into the forward pass; with D=100 it must find per-task weights and 'invents' gradient-descent code (Fig. 5: dot, ReLU, outer-product weight deltas, learning-rate scalar).
  • Motif ablations on the best algorithm (4 of 6 sections significant): removing weight accumulation costs −4.11, bilinear interactions −1.46, unit-normalized gradients −1.20, input-noise regularization −0.16.
  • Search-method ablation, 30 runs at 1k processes: best accuracy 0.703 ± 0.002 → 0.738 ± 0.008 and the fraction of runs beating a plain NN 0.00 → 0.53 after adding migration, FEC, 50% MNIST data and hurdles; the same ordering holds at 100 processes (0.700 → 0.714) and 10 processes (0.700 → 0.705).

Key advantages

  • Discovers complete algorithms symbolically rather than numerically — the output is readable code, not an opaque learned optimizer — and starts from empty component functions with no built-in assumption of a neural network, of layers, or even of gradients.
  • Shows evolution beats random search exactly where the space is sparse: ~5.6x on linear regression rising to 23,000x on affine-regression tasks as difficulty grows (Fig. 4) — the opposite of conventional AutoML spaces, where RS is competitive (linear regression has only 1 acceptable algorithm per 10^7; the paper estimates 1 in 10^12 in the freest space).
  • Task-conditioned adaptation emerges reproducibly from the same starting population: noisy ReLU / dropout-like regularization when data is scarce (8/30 experiments vs 0/30 control, p < 0.0005), iterated-arctan learning-rate decay that is nearly exponential when training is short (30/30 vs 3/30, p < 10^-14), and a learning rate derived from the transformed mean of the weight matrix for 10-class tasks (24/30 vs 0/30, p < 10^-11).
  • Engineered for scale and open-sourced: 2k–10k algorithms/second/CPU core, with baselines published at three compute scales so future search methods can be compared on the same space.

Limitations

  • The space cannot express batch normalization or convolution: one example is processed at a time, with no loops or higher-order tensors, so a multi-layer network must be discovered layer-by-layer, and no derivative ops exist, so any gradient computation must be evolved.
  • Scale: the main experiment used W=10,000 CPU workers for 5 days (plus 100<W<1000 smaller runs); search happens on binary tasks projected to 8 ≤ F ≤ 256 dims, with the 3072-dim CIFAR-10 test set reserved for final evaluation only.
  • Only 13 of 20 search experiments produced candidates beating the hand-designed reference, and the headline win is ~1.8 accuracy points over a 2-layer MLP.
  • Hyperparameter coupling had to be fixed by hand — an expression such as s7 = v2·v2 can coincide with a good value on the search tasks but not generalize, requiring manual decoupling that the authors say 'could be automated by future work'.
