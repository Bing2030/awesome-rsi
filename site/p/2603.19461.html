Hyperagents

Jenny Zhang, Bingchen Zhao, Wannan Yang, Jakob Foerster, Jeff Clune, Minqi Jiang, Sam Devlin, Tatiana Shavrina

arXiv 2026 · 2026

Local PDFOnlineCode

TL;DR

Hyperagents merge the task agent and the agent that improves it into one editable program, so the improvement mechanism itself evolves — metacognitive self-modification — removing the DGM's fixed handcrafted instruction-generation layer and its coding-only task/self-modification alignment assumption.

Abstract

Self-improving AI systems aim to reduce reliance on human engineering by learning to improve their own learning and problem-solving processes. Existing approaches to self-improvement rely on fixed, handcrafted meta-level mechanisms, fundamentally limiting how fast such systems can improve. The Darwin Gödel Machine (DGM) demonstrates open-ended self-improvement in coding by repeatedly generating and evaluating self-modified variants. Because both evaluation and self-modification are coding tasks, gains in coding ability can translate into gains in self-improvement ability. However, this alignment does not generally hold beyond coding domains. We introduce \textbf{hyperagents}, self-referential agents that integrate a task agent (which solves the target task) and a meta agent (which modifies itself and the task agent) into a single editable program. Crucially, the meta-level modification procedure is itself editable, enabling metacognitive self-modification, improving not only the task-solving behavior, but also the mechanism that generates future improvements. We instantiate this framework by extending DGM to create DGM-Hyperagents (DGM-H), eliminating the assumption of domain-specific alignment between task performance and self-modification skill to potentially support self-accelerating progress on any computable task. Across diverse domains, the DGM-H improves performance over time and outperforms baselines without self-improvement or open-ended exploration, as well as prior self-improving systems. Furthermore, the DGM-H improves the process by which it generates new agents (e.g., persistent memory, performance tracking), and these meta-level improvements transfer across domains and accumulate across runs. DGM-Hyperagents offer a glimpse of open-ended AI systems that do not merely search for better solutions, but continually improve their search for how to improve.

Method

A hyperagent is one editable Python program containing a task agent (solves the task; initially a single FM call) and a meta agent, whose only job is to modify any part of the codebase given the repo path, past evaluation results, and remaining iterations. DGM-H wraps this in DGM's open-ended loop: sample a parent from the archive (probability proportional to performance, inversely proportional to successfully compiled children — score-child-prop), let it metacognitively self-modify, stage-eval the child (small task subset first; zero on any failed domain), and add survivors to the archive. Because the instruction-generation mechanism, memory, and tooling are all code inside the search space, the meta agent rewrites how future improvements are generated (e.g., performance tracking, persistent memory). Only the outer loop — parent selection and evaluation protocol — stays handcrafted in the main experiments; Appendix E.5 relaxes parent selection.

Key results

  • Polyglot (80 iterations, DGM's exact setup, 5 runs): training 50-task subset 0.140 → 0.340 (CI 0.300–0.380), full benchmark 0.084 → 0.267 (CI 0.231–0.280) — comparable to DGM's 0.380/0.307 despite not being handcrafted for coding
  • Beyond coding (100 iterations, joint paper-review + robotics runs): paper-review test 0.0 → 0.710 (CI 0.590–0.750), beating the AI-Scientist-v2 reviewer baseline (0.630); robotics reward design 0.060 → 0.372 (CI 0.355–0.436) vs the directly-optimizing default reward (0.348), discovering jumping gaits over the standing-tall local optimum
  • Baselines (test, both domains): unmodified DGM 0.0/0.0; manually customized DGM-custom 0.590/0.348 (still p<0.05 below DGM-H); DGM-H w/o self-improve — a fixed meta agent, i.e. ADAS — 0.0/0.213; w/o open-ended exploration 0.0/0.116; all significantly worse (Wilcoxon p<0.05)
  • Transfer, measured by imp@50 on held-out IMO-level math grading: hyperagents transferred from paper-review/robotics runs reach 0.630 (CI 0.540–0.630), vs imp@50 = 0.0 for the initial meta agent (both DGM and DGM-H variants) and 0.0 (CI 0.0–0.010) for DGM-custom transfer agents — the meta improvements (performance tracker, persistent memory) are general, not domain-specific
  • Compounding and the outer loop: 200 iterations from transfer hyperagents score 0.640 vs 0.610 from scratch (n.s., higher median); initialized from ProofAutoGrader it lifts full IMO-GradingBench accuracy 0.561 → 0.601 (MAE 0.178 → 0.175); Appendix E.5's evolved parent selection (rediscovered UCB, adaptive-temperature softmax) reaches 0.491 vs 0.428 random, still below handcrafted score-child-prop 0.532

Key advantages

  • First demonstration that the improvement mechanism itself can be left to evolve, with the gains shown transferable (imp@50 0.630 vs 0.0 for DGM-custom transfers) and attributable to named acquired machinery — a PerformanceTracker over performance_history.json and a persistent memory of insights/hypotheses/plans shown as real evolved code and memory entries (Appendix E.3)
  • Drops DGM's load-bearing assumption that task-solving skill and self-modification skill coincide (true only in coding): one unmodified loop improves Polyglot, paper review, Genesis reward design, and IMO grading, matching DGM where DGM is native and beating it everywhere else without per-domain handcrafting
  • Cleanest ablation design in the RSI literature: every run starts from the same deliberately trivial single-FM-call agent, and the fixed-meta (ADAS-replicating) and no-archive baselines isolate exactly how much comes from meta-level self-improvement and open-ended search rather than task-level optimization
  • Honest hard-to-verify evaluation: paper review scores agreement with observed human accept/reject decisions rather than claimed quality, and the E.5 experiment honestly reports that evolved parent selection loses to the handcrafted mechanism

Limitations

  • Fixed task distribution: the paper's own first limitation — nothing co-evolves the tasks or curriculum, so 'any computable task' means any task a human has pre-defined an evaluator for
  • Full self-referentiality is deferred: parent selection and evaluation protocols stay handcrafted in the main experiments; the preliminary E.5 relaxation shows the agent reinvents UCB/softmax/stagnation heuristics but does not yet beat score-child-prop (0.491 vs 0.532, n.s.)
  • The headline meta-level wins over human engineering are median-only: DGM-H vs DGM-custom and the compounding gain (0.640 vs 0.610) are both not statistically significant, and the paper concedes saturation makes late gains small in absolute terms
  • Expensive and gate-sensitive: ~88.6M tokens per 100-iteration run (33M self-modification + 0.506M/iteration evaluation, App. D.2), and staged evaluation assigns zero to all unevaluated tasks of any agent failing a small-subset gate

Where it fits the RSI arc

Stage 5 harness-level RSI, the direct generalization of DGM: the improver itself becomes improvable, and its improvements demonstrably transfer across domains (imp@50) and compound across runs.
