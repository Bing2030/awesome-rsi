PAPER · stage 6 · Multi-Agent Self-Improvement

EvoAgent: Towards Automatic Multi-Agent Generation via Evolutionary Algorithms

Siyu Yuan, Kaitao Song, Jiangjie Chen, Xu Tan, Dongsheng Li, Deqing Yang

NAACL 2025 · 2025

Local PDFOnline

TL;DR

EvoAgent treats any existing LLM agent as a parent whose role/skill/prompt settings form an evolvable genome, and applies LLM-simulated crossover, mutation, and quality-checked selection to grow it into a specialized multi-agent team that beats hand-designed multi-agent frameworks on reasoning, science, and planning benchmarks.

Abstract

The rise of powerful large language models (LLMs) has spurred a new trend in building LLM-based autonomous agents for solving complex tasks, especially multi-agent systems. Despite the remarkable progress, we notice that existing works are heavily dependent on human-designed frameworks, which greatly limits the functional scope and scalability of agent systems. How to automatically extend the specialized agent to multi-agent systems to improve task-solving capability still remains a significant challenge. In this paper, we introduce EvoAgent, a generic method to automatically extend specialized agents to multi-agent systems via the evolutionary algorithm, thereby improving the effectiveness of LLM-based agents in solving tasks. Specifically, we consider the existing agent frameworks as the initial individual and then apply a series of evolutionary operators (e.g., mutation, crossover, selection, etc.) to generate multiple agents with diverse settings. Experimental results across various tasks show that EvoAgent can significantly enhance the task-solving capability of LLM-based agents, and can be generalized to any LLM-based agent framework to extend them into multi-agent systems. Resources are available at https://evo-agent.github.io/.

Method

An individual is one agent from any framework; its evolvable genome is its natural-language settings (role, skills, prompts), so LLMs can simulate the operators by rewriting them. From initial parent A(0,0), each of T iterations runs: (1) Crossover — parents answer the query, an LLM inspects the results to pick skills to improve, and rewrites settings into child agents; (2) Mutation — an LLM compares children against parents and edits them until distinct yet still task-capable; (3) Selection — an LLM quality-check module discards children that fail to inherit parent characteristics or duplicate an existing skill type (Fig. 1's hotel agent is dropped for duplicating the accommodation agent), keeping N per iteration; (4) Result update — every survivor drafts an answer and an LLM integrates all candidates with the prior result (EvoUpdate). All earlier agents stay in the population (EvoAgent(N,T) yields N×T specialists per query; main runs are (1,3)).

Key results

  • Logic Grid Puzzle (200 puzzles, accuracy): GPT-4 77.0 vs hand-designed AutoAgents 69.0, AgentVerse 66.5, CoT 65.5; GPT-3.5 71.5 vs 68.0/66.5; Llama2-13B 35.5 vs Self-Refine 33.5 while persona-ensemble SPP collapses to 0.0 (Table 1).
  • TravelPlanner (180-query validation, GPT-4): final macro pass rate 7.2 vs 2.2 Direct/CoT, 1.1 Self-Refine, 0.6 SPP; hard-constraint micro 21.1 vs 15.8; commonsense micro 81.5 vs 79.4. On Mistral-7B it doubles hard-constraint micro (7.8 vs 3.9) and is the only method with nonzero final pass (1.1 vs 0.0).
  • ScienceWorld (30 interactive science tasks, sub-task completion): GPT-4 overall 27.97 to 30.42 and GPT-3.5 17.12 to 19.02 over the single-agent ReAct baseline; biggest gains on short trajectories (GPT-4 42.41 to 48.67), smallest on long ones (Table 2).
  • Ablation (TravelPlanner, averaged GPT-3.5 + Gemini-Pro): EvoAgent(1,3) with quality check reaches 68.9 commonsense / 14.0 hard micro vs same-budget variants Overgen3 61.4/10.7, PromptRefine3 63.0/13.8, Suggest3 61.7/8.4, Direct 59.5/13.7 (Table 4).
  • Cost (Table 5, Llama-3.1-70B on 8x RTX 3090 via SGLang): Logic 67.0 in 1060.8s vs AutoAgents 61.5 in 988.8s and AgentVerse 60.0 in 1056.0s — near-identical wall-clock to other multi-agent baselines at the best score. The MetaGPT/CAMEL/AutoGen adaptations (Appendix D) report no benchmark numbers — qualitative demos only.

Key advantages

  • Framework-agnostic by construction: because the genome is plain-language agent settings, the same four operators wrap MetaGPT, AutoGen, and CAMEL without modifying their code — unlike ADAS (stage 5), which must program a new executable pipeline per domain and framework.
  • Selection needs no validation metric: the quality check tests inheritance and non-duplication rather than benchmark fitness, so the loop runs on tasks where you cannot score candidates individually (at the cost of optimizer signal — see limitations).
  • Gains hold on weak backbones where persona methods fail: on Llama2-13B Logic it scores 35.5 while SPP scores 0.0, showing diversity-from-evolution generalizes where SPP's persona self-collaboration does not.
  • Outperforms the dedicated auto-generation frameworks AgentVerse and AutoAgents it is closest to, at comparable inference cost, and beats same-budget ablations (Overgen, PromptRefine, Suggest), isolating the value of evolving agents rather than just sampling or refining prompts.

Limitations

  • From the paper's own Limitations section: generating multiple specialized agents brings higher token cost than a single agent; comparisons with existing multi-agent frameworks are limited to AgentVerse and AutoAgents because adapting others to each benchmark was out of scope; and the generated agents' quality is never manually evaluated.
  • Improvements shrink as trajectories lengthen — ScienceWorld gains are largest on short tasks and the authors attribute this to long contexts degrading multi-agent systems (Table 2).
  • Iteration gains plateau after 3 on Trivia Creative Writing as generated agents converge and become similar, and with N>1 the quality-check module is needed to suppress duplicate-type agents (Sec. 4.4, App. B).
  • Scaling population/iterations shifts plans toward user preferences at the expense of commonsense-rule adherence — the authors blame an initial-agent integration bias they leave to future work.
