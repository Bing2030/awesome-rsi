FunSearch

repo

GitHub

What it does

Official code for the Nature 2023 FunSearch paper: a frozen LLM evolves a `priority` function inside a problem skeleton while evaluators score candidates and islands of programs recycle the best as few-shot examples; ships the discovered cap-set, admissible-set, bin-packing and cyclic-graph artifacts.

How it works

  • Skeleton contract (implementation/funsearch.py): a specification must contain exactly one `@funsearch.run` function (the scorer, e.g. `evaluate(n) -> int`) and one `@funsearch.evolve` function to evolve (e.g. `priority(el, n)`); funsearch.main() seeds the initial body into all islands and launches Sampler/evaluator loops. cap_set/cap_set.ipynb shows the full skeleton — solve() builds a cap set greedily from the LLM-written priority, so the LLM evolves a scoring rule, not the object itself.
  • Prompt construction (implementation/programs_database.py): each of num_islands=10 Islands clusters programs by signature (the tuple of per-test scores); clusters are softmax-sampled with a temperature decaying linearly over 30,000 programs (init 0.1), shorter programs favored within a cluster, then `functions_per_prompt=2` implementations are score-sorted, renamed `_v0, _v1, ...` with docstrings 'Improved version of `_v{i-1}`', and the prompt ends with an empty `_v{n}` header for the LLM to continue.
  • Island resets as diversity pressure: every reset_period (14,400 s = 4 h) the weakest half of islands is wiped and re-founded from the best program of one random surviving island; results land back via register_program(program, island_id, scores_per_test), so generations stay attributable to the island that produced their prompt.
  • Evaluator gate (implementation/evaluator.py): _trim_function_body parses the continuation with ast, deleting trailing lines until it compiles, splices it into the template, and runs it in a Sandbox (abstract stub, 30 s timeout) on held test inputs — candidates calling an ancestor `_v*` version are rejected by _calls_ancestor, and only programs returning int/float scores on every input register. Both `LLM._draw_sample` and `Sandbox.run` raise NotImplementedError: no model, sandbox, or distributed infra ships (config defaults: num_samplers=15, num_evaluators=140, samples_per_prompt=4).

Key advantages

  • Ships the actual winning artifacts, not just the loop: the discovered priority functions that build a 512-cap in n=8 (previous best construction: 496) and a 1082-cap in n=9 (matching the previous best), admissible sets up to n=24, w=17, size 237,984, corner-free sets, cyclic-graph independent sets, and bin-packing heuristics with an OR3 (20 instances x 500 items) / Weibull 5k evaluation suite reporting excess over the L1 lower bound.
  • Program-space search yields inspectable mechanisms: the n=8 discovered priority's weight/reflection regularities were hand-distilled into build_512_cap(), an explicit construction of the 512-cap — the notebook walks from skeleton to discovered function to human-understandable structure.
  • The minimal reference LLM+evaluator loop (~640 lines across five files): every trick of the later, bigger systems — signature clustering, temperature schedules, island resets, few-shot score-sorted prompt ordering, ancestor-call rejection — is one short, copyable function.

Install & run

No installation required — open the notebooks in Google Colab (cap_set/cap_set.ipynb, admissible_set, bin_packing, cyclic_graphs each have a Colab badge in the README). To run the pipeline yourself, implement the `LLM._draw_sample` and `Sandbox.run` stubs and call `funsearch.main(specification, inputs, config)` from implementation/funsearch.py (see implementation/specification_nonsymmetric_admissible_set.txt for a spec example).

Learning note

Read programs_database.py's get_prompt/_generate_prompt first — score-sorted `_v0..._vn` few-shots ending in an empty header is the core trick. Then evaluator.py's _calls_ancestor anti-cheat. Run cap_set.ipynb's discovered priority to verify 512 (n=8) and 1082 (n=9) yourself.

Repo README

FunSearch

This repository accompanies the publication

Romera-Paredes, B. et al. Mathematical discoveries from program search with large language models. Nature (2023)

There are 6 independent directories:

  • cap_set contains functions discovered by FunSearch that construct large cap sets, and we also provide those cap sets in a numerical format for convenience.

  • admissible_set contains functions discovered by FunSearch that construct large admissible sets, and we also provide those admissible sets in a numerical format for convenience.

  • bin_packing contains heuristics discovered by FunSearch for online 1D bin packing problems, and an evaluation suite to reproduce the results reported in the paper.

  • cyclic_graphs contains functions discovered by FunSearch that construct large independent sets in strong products of cyclic graphs, and we also provide those sets in a numerical format for convenience.

  • corner_free_sets contains the discovered sets of indices, in numerical format, satisfying the combinatorial degeneration constraints described for the corners-free problem in the Supplementary Information.

  • implementation contains an implementation of the evolutionary algorithm, code manipulation routines, and a single-threaded implementation of the FunSearch pipeline. It does not contain language models for generating new programs, the sandbox for executing untrusted code, nor the infrastructure for running FunSearch on our distributed system. This directory is intended to be useful for understanding the details of our method, and for adapting it for use with any available language models, sandboxes, and distributed systems.
