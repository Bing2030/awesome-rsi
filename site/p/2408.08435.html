Automated Design of Agentic Systems

Shengran Hu, Cong Lu, Jeff Clune

ICLR 2025 · 2025

Local PDFOnlineCode

TL;DR

A meta agent (GPT-4o) programs new agents as complete `forward()` Python functions, scores each on a validation slice, and feeds the growing scored archive back into its own prompt — discovering designs that beat hand-designed baselines on DROP, MGSM, MMLU and GPQA.

Abstract

Researchers are investing substantial effort in developing powerful general-purpose agents, wherein Foundation Models are used as modules within agentic systems (e.g. Chain-of-Thought, Self-Reflection, Toolformer). However, the history of machine learning teaches us that hand-designed solutions are eventually replaced by learned solutions. We describe a newly forming research area, Automated Design of Agentic Systems (ADAS), which aims to automatically create powerful agentic system designs, including inventing novel building blocks and/or combining them in new ways. We further demonstrate that there is an unexplored yet promising approach within ADAS where agents can be defined in code and new agents can be automatically discovered by a meta agent programming ever better ones in code. Given that programming languages are Turing Complete, this approach theoretically enables the learning of any possible agentic system: including novel prompts, tool use, workflows, and combinations thereof. We present a simple yet effective algorithm named Meta Agent Search to demonstrate this idea, where a meta agent iteratively programs interesting new agents based on an ever-growing archive of previous discoveries. Through extensive experiments across multiple domains including coding, science, and math, we show that our algorithm can progressively invent agents with novel designs that greatly outperform state-of-the-art hand-designed agents. Importantly, we consistently observe the surprising result that agents invented by Meta Agent Search maintain superior performance even when transferred across domains and models, demonstrating their robustness and generality. Provided we develop it safely, our work illustrates the potential of an exciting new research direction toward automatically designing ever-more powerful agentic systems to benefit humanity.

Method

The search space is Python, not prompts. The meta agent is handed a <100-line framework (`Info` namedtuple; `FM_Module` wrapping role/model/temperature and a `query()` that concatenates Info objects into a structured prompt) and must write one complete `def forward(self, taskInfo)` per candidate, which the harness executes. Loop (Algorithm 1): seed the archive with hand-designed baselines (COT, COT-SC, Self-Refine, LLM Debate, Quality-Diversity, Step-back, Role Assignment); the meta agent sees the full scored archive plus 'WRONG Implementation examples' and emits {thought, name, code}; two self-reflection rounds revise it for interestingness, implementation mistakes and improvement; it is evaluated on the domain validation split; runtime errors trigger up to five debug reflections; the agent and its metric are appended to the archive. Search runs independently per domain; one fixed meta agent (gpt-4o-2024-05-13) proposes while every candidate and baseline is scored by gpt-3.5-turbo-0125.

Key results

  • Table 1 (held-out test, 95% bootstrap CI): DROP F1 79.4 ± 0.8 vs best hand-designed 65.8 ± 0.9 (Role Assignment) and prompt-only OPRO 69.1 ± 0.9 — the paper's headline +13.6; MGSM accuracy 53.4 ± 3.5 vs 39.0 ± 3.4 (LLM Debate), +14.4; MMLU 69.6 ± 3.2 vs 65.9 ± 3.2 (COT-SC); GPQA 34.6 ± 3.2 vs 31.6 ± 3.2 (Self-Refine) — the gap shrinks where FM knowledge, not scaffolding, caps performance.
  • ARC (25 search iterations, 20-question validation / 60-question test, 5 evaluations each): top three discovered agents reach 13.7 / 13.3 / 12.7 % on GPT-3.5 vs best baseline 8.0 (LLM Debate); transferred unchanged to Claude-Sonnet they reach 38.7 / 39.7 / 48.3 % vs 31.7 baseline (Table 3).
  • Zero-shot transfer of the top-3 MGSM agents within math (Table 4): GSM8K 69.5 ± 3.2 vs best baseline 43.6 ± 3.4 (+25.9), GSM-Hard 31.2 ± 3.2 vs 18.0 ± 2.7 (+13.2), SVAMP 82.6 vs 78.5, ASDiv 91.8 vs 89.2. Beyond math (Table 5) DROP F1 70.4–71.9 vs 65.8 and MMLU 62.4–67.0 vs 65.9, but GPQA 28.6–29.9 stays under the 31.6 baseline — 'outperform or match', not a clean sweep.
  • Empty-initialization ablation (Table 6): with no seeded baselines Meta Agent Search still beats every hand-designed baseline in all four domains, and in math it beats its own seeded run (MGSM 67.5 ± 3.3 vs 53.4 ± 3.5), while seeding wins elsewhere (DROP 79.4 vs 73.9; MMLU 69.6 vs 68.5; GPQA 34.6 vs 32.7).
  • Cost (Appendix J): ~$500 per ARC search-and-evaluation run and ~$300 per reasoning-domain run, dominated by gpt-3.5-turbo-0125 evaluation calls rather than meta-agent proposals.

Key advantages

  • Whole-program search space: because the candidate is arbitrary Python, the loop learns prompts, workflows, ensembles, criticism and refinement together. The prompt-only baseline OPRO is beaten in all four domains (DROP 69.1 vs 79.4), which is the paper's direct evidence that code-space ADAS buys more than prompt optimization.
  • The stepping-stone story is documented, not asserted: on ARC a 'multiple COTs → refine → ensemble' pattern emerged at iteration 3 and was reused afterwards, and the best agent combined ideas first seen at iterations 5 (diverse feedback), 11 (trait-specific experts) and 12 (human-like critic) — LLM-mediated crossover over an archive rather than hill-climbing on one incumbent.
  • Generalization is measured three ways, not one: transfer to unseen math domains, to non-math domains, and across four FMs (GPT-3.5, Claude-Haiku, GPT-4, Claude-Sonnet), where the searched agents keep their lead at every model — evidence the discovered designs are not overfit to the searching model.
  • Extremely cheap substrate: <100 lines of framework, API-only, no GPUs, and the outputs are readable Python — the paper argues this makes the search space interpretable and auditable in a way graph/network search spaces are not.

Limitations

  • One objective (performance) only: cost, latency and robustness are not optimized; multi-objective ADAS is left to future work, and the ~$300–500 per run is itself never treated as a search constraint.
  • By the authors' own account the evaluation function is the weak link — evaluating on a validation split and reading a scalar is 'both expensive and overlooks valuable information', discarding the run logs that carry failure modes, and it cannot handle subjectively judged tasks.
  • Scope is single-step QA plus ARC-style grid puzzles; multi-step interaction with real environments is untested, and the meta agent itself is fixed — the paper never improves the meta-agent's own prompt or search policy, listing self-referential 'Higher-order ADAS' explicitly as future work.
  • Where the FM lacks the knowledge, agent design cannot compensate: the GPQA/MMLU gains are small (34.6, 69.6) and the transferred math agents fall below the GPQA baseline (28.6–29.9 vs 31.6).

Where it fits the RSI arc

Stage 5 (Harness-level RSI), the cleanest anchor of the Prompt & Program Optimization group: the evolving artifact is a whole agent program while the improver stays fixed. Successors (DGM, HyperAgents, AutoHarness, Continual Harness, MetaSkill-Evolve) extend the loop to the meta level or to online settings.
