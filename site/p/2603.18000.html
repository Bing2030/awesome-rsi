AgentFactory: A Self-Evolving Framework Through Executable Subagent Accumulation and Reuse

Zhang Zhang, Shuqi Lu, Hongjin Qian, Di He, Zheng Liu

ACL 2026 (System Demonstrations) · 2026

Local PDFOnlineCode

TL;DR

AgentFactory keeps successful task solutions as executable Python subagents — not textual reflections — in a growing library, refines them from execution feedback, and re-exports them to other agent systems; saved subagents cut orchestrator output tokens roughly in half on transfer tasks.

Abstract

Building LLM-based agents has become increasingly important. Recent works on LLM-based agent self-evolution primarily record successful experiences as textual prompts or reflections, which cannot reliably guarantee efficient task re-execution in complex scenarios. We propose AgentFactory, a new self-evolution paradigm that preserves successful task solutions as executable subagent code rather than textual experience. Crucially, these subagents are continuously refined based on execution feedback, becoming increasingly robust and efficient as more tasks are encountered. Saved subagents are pure Python code with standardized documentation, enabling portability across any Python-capable system. We demonstrate that AgentFactory enables continuous capability accumulation: its library of executable subagents grows and improves over time, progressively reducing the effort required for similar tasks without manual intervention. Our implementation is open-sourced at https://github.com/zzatpku/AgentFactory, and our demonstration video is available at https://youtu.be/iKSsuAXJHW0.

Method

A Meta-Agent orchestrates a three-tier skill system: fixed meta-skills (create_subagent, run_subagent, modify_subagent, list_saved_subagents, view_subagent_code, finish), fixed tool skills (Serper web_search, Jina web_reading, Playwright browser_automation, shell_command), and the one evolving tier — subagent skills saved as pure Python code plus a SKILL.md doc. Install: on an unsolved task the Meta-Agent decomposes it and builds a focused Python subagent per sub-problem, allocating each a tool subset rather than the whole toolset; on success the subagent is promoted from the isolated per-task workspace to the persistent library. Self-Evolve: on similar tasks it retrieves saved subagents, runs and assesses them, analyzes failure feedback, modifies the code (error handling, generality), and revalidates against the current task. Deploy: mature subagents export as standalone scripts; LangChain, AutoGen, and Claude Code onboard them via prompts + SKILL.md alone.

Key results

  • Table 1, Batch 2 transfer tasks with saved subagents, avg orchestrator output tokens/task: Opus 4.6 2971 vs ReAct 7022 (−58%) and 6210 for the textual-experience baseline; Sonnet 4.6 3862 vs ReAct 7029 (−45%) and 8223 textual
  • Stronger models reuse even without a pre-built library: Opus 4.6 already drops to 4324 tokens on Batch 1 from scratch vs ReAct 8298 (the paper flags this as a signal for future models); Sonnet 4.6 does not — 9199 vs ReAct 6893, i.e. building subagents from scratch cost more than plain ReAct
  • The metric isolates orchestration effort (subagent-internal LLM tokens excluded); setup is two 15-task batches where each Batch 2 task mirrors its Batch 1 counterpart with changed specifics, and all tasks completed without runtime errors in every configuration
  • Qualitative loops: a README-generation subagent evolves hardcoded path → LLM JSON parsing with fragile hardcoded fallback → LLM + regex fallback over three runs (Fig. 2); subagents created in AgentFactory (Audio Transcriber, Document Creator) are invoked directly inside Claude Code with no new subagent creation (Fig. 3)

Key advantages

  • Experience is executable: saved subagents re-run as code, so reuse replaces re-derivation — the Reflexion/STaR-style textual-experience baseline never approaches the Batch 2 savings (6210/8223 vs 2971/3862 tokens)
  • Cross-system portability is demonstrated, not just claimed: pure-Python subagents with SKILL.md docs (aligned to Anthropic's Agent Skills standard) onboarded into Claude Code via prompts alone
  • Improvement by accumulation under containment: meta- and tool-skills stay frozen while only the subagent tier evolves, and the Workspace Manager runs each task in isolation so failed modifications can't corrupt the shared library

Limitations

  • The headline metric excludes subagent-internal token consumption — savings are orchestration-level only, and there is no output-quality score beyond 'all tasks completed without runtime errors' on 30 author-curated tasks
  • The from-scratch overhead is backbone-dependent: Sonnet 4.6's Batch 1 orchestration cost (9199) exceeds ReAct (6893); the paper's text highlights only the favorable Opus contrast (4324 vs 8298)
  • Interaction is web-only (search, reading, Playwright); the conclusion defers GUI/non-web applications to future VLM integration
  • Safety is by convention rather than guarantee: shell_command has built-in checks that flag destructive operations, and the ethical considerations section relies on human-readable code plus user auditing of exported subagents
