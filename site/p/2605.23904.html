SkillOpt: Executive Strategy for Self-Evolving Agent Skills

Yifan Yang, Ziyang Gong, Weiquan Huang, Qihao Yang, Ziwei Zhou, Zisu Huang, Yan Li, Xuemei Gao, Qi Dai, Bei Liu, Kai Qiu, Yuqing Yang, Dongdong Chen, Xue Yang, Chong Luo

arXiv 2026 · 2026

Local PDFOnline

TL;DR

SkillOpt treats a single 300-2,000-token skill document as the trainable state of a frozen agent: an optimizer model turns scored rollouts into bounded add/delete/replace edits, each accepted only on a strict held-out validation gain, best or tied-best on 52/52 cells.

Abstract

Agent skills today are hand-crafted, generated one-shot, or evolved through loosely controlled self-revision, none of which behaves like a deep-learning optimizer for the skill, and none of which reliably improves over its starting point under feedback. We argue the skill should instead be trained as the external state of a frozen agent, with the same discipline that makes weight-space optimization reproducible. SkillOpt is, to our knowledge, the first systematic controllable text-space optimizer for agent skills: a separate optimizer model turns scored rollouts into bounded add/delete/replace edits on a single skill document, and an edit is accepted only when it strictly improves a held-out validation score. A textual learning-rate budget, rejected-edit buffer, and epoch-wise slow/meta update make skill training stable while adding zero inference-time model calls at deployment. Across six benchmarks, seven target models, and three execution harnesses (direct chat, Codex, Claude Code), SkillOpt is best or tied on all 52 evaluated (model, benchmark, harness) cells and beats every per-cell competitor among human, one-shot LLM, Trace2Skill, TextGrad, GEPA, and EvoSkill skills. On GPT-5.5 it lifts the average no-skill accuracy by +23.5 points in direct chat, by +24.8 inside the Codex agentic loop, and by +19.1 inside Claude Code. Transfer experiments further show that optimized skill artifacts retain value when moved across model scales, between Codex and Claude Code execution environments, and to a nearby math benchmark without further optimization. Code: https://aka.ms/skillopt

Method

SkillOpt freezes the target model, harness, and evaluator; only the skill text trains. Each step runs a rollout batch (B=40) from the train split; the optimizer model separates failures from successes, splits each into reflection minibatches (Bm=8, 16 parallel analysts), and returns structured JSON edits (append / insert_after / replace / delete). Failure patches merge, success patches merge, then a failure-prioritized final merge deduplicates and resolves conflicts; the pool is ranked and clipped to the edit budget Lt=4 (cosine decay, floor 2) - the textual learning rate. The candidate is scored on the selection split, accepted only on strict improvement (ties rejected), and the best accepted version exported as best_skill.md. A rejected-edit buffer conditions later reflection, and an epoch-boundary slow/meta update writes protected longitudinal guidance under the same gate. Default: four epochs; the optimizer-side meta skill is teacher-only.

Key results

  • GPT-5.5 direct chat, six benchmarks: average no-skill 58.8 -> 82.3 (+23.5), +5.4 clear of a per-cell oracle over human, one-shot LLM, Trace2Skill, TextGrad, GEPA and EvoSkill skills (76.9); SpreadsheetBench 41.8 -> 80.7, OfficeQA 33.1 -> 72.1, LiveMath 37.6 -> 66.9, ALFWorld 83.6 -> 95.5, SearchQA 77.7 -> 87.3, DocVQA 78.8 -> 91.2. Best-or-tied on 52 of 52 (model, benchmark, harness) cells.
  • Same interface under tool harnesses (GPT-5.5, five benchmarks): Codex average +24.8 over no skill and +14.0 over EvoSkill; Claude Code +19.1 over no skill, +3.2 over EvoSkill, whose own average is 57.8 -> 73.7; SpreadsheetBench under Claude Code 22.1 -> 80.4.
  • Not frontier-specific: per-model average gains are +12.7 (GPT-5.4), +15.4 (mini), +26.7 (nano), +16.6 (GPT-5.2), +19.2 (Qwen3.5-4B), +9.1 (Qwen3.6-35B-A3B), about +17.6 points per model; ALFWorld 34.3 -> 69.4 on GPT-5.4-nano and SpreadsheetBench 9.3 -> 23.9 (x2.6) on Qwen3.5-4B.
  • Ablations (GPT-5.5 student and teacher, SearchQA/Spreadsheet/LiveMath): removing the edit budget gives 84.6/75.7/57.3 vs 87.1/77.5/61.3 for the bounded default; dropping the rejected-edit buffer costs 1.6/4.6/2.4 points; removing both meta skill and slow update drops SpreadsheetBench 77.5 -> 55.0 (-22.5). Training evidence scales: 1 example -> 100% of the train partition lifts SpreadsheetBench 47.5 -> 78.0 and LiveMath 59.1 -> 70.5.
  • Transfer, and what it costs: a Codex-trained SpreadsheetBench skill reaches +59.7 on Claude Code (22.1 -> 81.8, above the in-domain 80.4) and the reverse adds +43.6 (27.5 -> 71.1); OlympiadBench -> Omni-MATH gains +3.7/+1.8/+1.3 across three scales. Deployed skills stay small (379-1,995 tokens, median ~920) and come from only 1-4 accepted edits (LiveMath's +29.3 and OfficeQA's +39.0 each from one); training costs 0.6M-46.4M tokens per test point.

Key advantages

  • The accept gate does visible work, and the edit economy proves it: the optimizer proposes many edits per epoch but only 1-4 survive into best_skill.md, because acceptance requires strictly beating the current selection score (ties rejected) - so the artifact cannot silently drift, and two of the largest single-benchmark gains come from exactly one gated edit.
  • Breadth of evidence unusual for a no-weight-update method: six benchmarks spanning extractive QA, spreadsheet codegen, document and multimodal QA, math and embodied interaction, seven target models from GPT-5.5 to Qwen3.5-4B, and three harnesses (direct chat, Codex, Claude Code) all consuming one best_skill.md, with the strongest per-cell competitor as the comparison point in every cell.
  • Optimizer strength is a free training-time lever: because the optimizer runs only offline, swapping in a frontier teacher costs nothing at deployment, and it measurably pays (GPT-5.4-nano SpreadsheetBench +19.0 vs +11.9, SearchQA +19.0 vs +14.1; GPT-5.4-mini +11.4 vs +7.1 and +4.3 vs +2.4). A target-matched optimizer still recovers 56-74% of that gain, so the loop itself, not distillation, carries most of the value.
  • The learned artifact is genuinely portable and auditable: cross-model, cross-harness (+59.7) and cross-benchmark transfers are all positive with no row below the target's no-skill baseline, every change is recoverable from edit_apply_report.json, the slow-update region is markup-fenced against step-level edits, and the meta skill never ships with the deployed skill.

Limitations

  • The loop needs reliable automatic feedback: scored trajectories plus a held-out selection split mean it applies most directly where verifiers, exact-match metrics or executable checks exist; subjective or multi-dimensional domains may need stronger human or model-based evaluation (Appendix B).
  • Training is not free even though deployment is: rollouts plus optimizer calls cost 0.6M-46.4M training tokens per absolute test point (SearchQA 37.9M/pt, DocVQA 46.4M/pt), amortized only when the same skill is reused, and less attractive for one-off tasks.
  • It deliberately trains one portable skill rather than a library or model weights, which the authors concede may be insufficient for heterogeneous domains requiring many disjoint procedures - and it barely explores the self-distillation back into the target model.
  • Optimized skills encode heuristics from the training distribution, so held-out evaluation remains necessary before transfer; scope is also narrowed in places, with ALFWorld omitted from both harness rows because persistent embodied interaction is not representable in the standard Codex / Claude Code adapters.
