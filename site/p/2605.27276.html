SIA: Self Improving AI with Harness & Weight Updates

Prannay Hebbar, Yogendra Manawat, Samuel Verboomen, Alesia Ivanova, Selvam Palanimalai, Kunal Bhatia, Vignesh Baskaran

arXiv 2026 · 2026

Local PDFOnlineCode

TL;DR

A Feedback-Agent (Claude Sonnet 4.6) alternately rewrites a task agent's scaffold and RL-tunes its weights (LoRA on gpt-oss-120b), merging the harness-update and test-time-training silos into one loop that beats both single-lever variants on all three benchmarks.

Abstract

Humans are the bottleneck in building and improving AI. Both the models and the agents that wrap them are written, tuned, and corrected by people. The long-horizon goal of an AI that can figure out how to improve itself remains open. Two largely disjoint research lines attack this bottleneck. The harness-update school has a meta-agent rewrite the scaffold of a task-specific agent (its tools, prompts, retry logic, and search procedure) while the model weights are held fixed. The test-time training school uses hand-written RL pipelines to update the model's own weights on task feedback while the harness is held fixed. These two silos operate in isolation. We propose SIA, a self-improving loop in which a language-model agent (the Feedback-Agent) updates both the harness and the weights of a task-specific agent. We evaluate across three contrasting domains: Chinese legal charge classification, low-level GPU kernel optimisation, and single-cell RNA denoising. Combining both levers outperforms scaffold iteration alone on all three benchmarks. SIA-W+H achieves 25.1% over prior SOTA on LawBench, 12.4% faster GPU kernels than prior SOTA (1,017 vs 1,161 μs), and 20.4% over prior SOTA on denoising. Harness updates make the model agentic, shaping how it searches and acts, while weight updates build the domain intuition that no prompt or scaffold can instil.

Method

Three LLM components: a Meta-Agent writes the initial scaffold A1 from the task spec and reference code; the task-specific agent (gpt-oss-120b) runs the benchmark in a sandbox (read-only data, private working dir); a Feedback-Agent (Claude Sonnet 4.6) reads the full trajectory — every prompt, response, tool call, and extracted answer per instance, not summary metrics — plus the scaffold and scores, then picks the next step: a harness update (A_{g+1} = F(A_g, τ_g, E_g, U); weights frozen) or a weight update (LoRA r=32, lr 4e-5 on gpt-oss-120b, H100s via Modal; scaffold frozen). It also selects the RL algorithm from a six-entry menu (PPO+GAE, GRPO, entropic advantage weighting, REINFORCE+KL, best-of-N behavioral cloning, DPO) from reward structure; in practice scaffold iteration runs first, switching to weights when harness progress stalls. Gate: a deterministic per-instance verifier scores every step.

Key results

  • LawBench 191-class Chinese charge classification (top-1 accuracy, 913-item held-out test): 13.5% initial → 50.0% harness-only — the scaffold converged on a TF-IDF + LinearSVC pipeline, abandoning the LLM path — → 70.1% after PPO+GAE weight updates; prior SOTA 45.0% (+25.1 points).
  • AlphaEvolve TriMul CUDA-kernel task (H100; score = 1500/runtime): harness-only stalled at 0.120 (12,483 µs, 1.14×); entropic advantage weighting drove runtime to 1,017 µs — 14.02× speedup, score 1.475 vs 1.292 prior SOTA (12.4% faster), a 91.9% runtime cut from the harness-only peak.
  • MAGIC scRNA-seq denoising on pancreas data (mse norm, higher = better): harness-only hyperparameter sweeps (k, diffusion steps, bandwidth) plateaued at 0.241; the first GRPO checkpoint added a np.clip + np.rint rounding step → 0.289 vs 0.240 prior SOTA (+20.4%).
  • Ablation (Table 3): SIA-W+H strictly beats SIA-H everywhere, but the dominant lever flips by domain — harness updates did most of the LawBench work, weights nearly all of TriMul's (0.120 → 1.475).

Key advantages

  • Table 1's only system that edits harness and weights inside one self-improving loop; the nearest neighbours each stop short — Hyperagents co-evolves agent and improver but freezes weights, EUREKA composes scaffold-side reward generation with RL training but one-directionally.
  • RL algorithm choice is part of what the Feedback-Agent searches: PPO+GAE when per-step rewards are dense, GRPO when rollouts are cheap and the verifier fires at episode end, entropic advantage weighting when the reward histogram is right-skewed, plus REINFORCE+KL, best-of-N behavioral cloning (cold start), and DPO — selected per trajectory, not a fixed schedule.
  • Conditions on full per-instance trajectories (every prompt, tool call, extracted answer) rather than aggregate scores, so edits diagnose specific failure modes instead of mutating toward summary statistics.
  • Isolates each lever's contribution empirically: weight updates are shown to deliver knowledge no scaffold generation reached (the np.clip+np.rint invariant, H100 tiling patterns), directly answering RQ2 rather than asserting synergy.

Limitations

  • Coupled co-evolutionary Goodhart (§8, the paper's own analysis): both levers optimise the same fixed verifier, so the harness finds scaffolds the current policy can exploit while the weights train on data from a scaffold that will change — the joint fixed point is a Nash equilibrium of two mutually blind optimisers, fragile off-distribution.
  • Lever and algorithm selection is a frozen LLM prior, not learned (§9); the loop alternates in coarse discrete rounds — finer interleaving is left as future work.
  • Three single-task evaluations, one base model (gpt-oss-120b), no seeds or variance reported; and §7.3's algorithm-selection guidance is 'common patterns observed' across tasks not reported here, with a fuller treatment deferred to v2.
