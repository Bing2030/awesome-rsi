PAPER · stage 7 · Coding / Software-Engineering Self-Improvement

AgentCoder: Multi-Agent-based Code Generation with Iterative Testing and Optimisation

Dong Huang, Jie M. Zhang, Michael Luck, Qingwen Bu, Yuhao Qing, Heming Cui

arXiv 2023 · 2023

Local PDFOnline

TL;DR

AgentCoder splits code generation into three roles — a Chain-of-Thought programmer, a test designer that writes basic/edge/large-scale tests without seeing the code, and a Python test-executor — looping until tests pass. GPT-4 reaches 96.3% HumanEval pass@1 at 56.9K tokens.

Abstract

The advancement of natural language processing (NLP) has been significantly boosted by the development of transformer-based large language models (LLMs). These models have revolutionized NLP tasks, particularly in code generation, aiding developers in creating software with enhanced efficiency. Despite their advancements, challenges in balancing code snippet generation with effective test case generation and execution persist. To address these issues, this paper introduces Multi-Agent Assistant Code Generation (AgentCoder), a novel solution comprising a multi-agent framework with specialized agents: the programmer agent, the test designer agent, and the test executor agent. During the coding procedure, the programmer agent will focus on the code generation and refinement based on the test executor agent's feedback. The test designer agent will generate test cases for the generated code, and the test executor agent will run the code with the test cases and write the feedback to the programmer. This collaborative system ensures robust code generation, surpassing the limitations of single-agent models and traditional methodologies. Our extensive experiments on 9 code generation models and 12 enhancement approaches showcase AgentCoder's superior performance over existing code generation models and prompt engineering techniques across various benchmarks. For example, AgentCoder (GPT-4) achieves 96.3\% and 91.8\% pass@1 in HumanEval and MBPP datasets with an overall token overhead of 56.9K and 66.3K, while state-of-the-art obtains only 90.2\% and 78.9\% pass@1 with an overall token overhead of 138.2K and 206.5K.

Method

Input is only the task description/stub. The programmer agent (LLM) emits code after a four-step Chain-of-Thought (understand and clarify, select algorithm, write pseudocode, generate code). The test designer agent (LLM, separate call) emits test cases independently — it sees the prompt stub but never the generated code, so its oracles cannot be biased by the bugs it is meant to catch — and is prompted for basic, edge, and large-scale inputs. The test executor agent is a Python script, not an LLM: agents must wrap output in ```py[Code]```/```py[TestCases]``` blocks, which it extracts, runs in a local terminal, and inspects for assertion/runtime errors. All tests pass → return code; otherwise the traceback is fed to the programmer, which regenerates. Loop ends on success or at an iteration budget (5 in experiments). Nothing is trained — all improvement is in-context repair.

Key results

  • GPT-4: 96.3% HumanEval / 91.8% MBPP pass@1 at 56.9K/66.3K response tokens, vs MetaGPT 85.9/87.7 at 138.2K/206.5K, ChatDev 84.1/79.8 at 183.7K/259.3K, AgentVerse 89.0/73.5 at 149.2K/193.6K, Self-Collaboration 90.2/78.9 at 74.3K/89.2K (Tab. 9).
  • GPT-3.5-turbo: HumanEval 57.3% zero-shot → 79.9% with AgentCoder; MBPP-ET 89.1% vs 63.0% for CodeCoT. Mean pass@1 across the four datasets is 84.1% (GPT-3.5) and 91.5% (GPT-4) against 75.3% and 86.8% for the best baselines, and it holds up on the harder enhanced sets (77.4/89.1) where base models collapse.
  • Ablation (Tab. 2): programmer alone 61.0/47.9 (HumanEval/MBPP) → +test designer 64.0/62.3 → programmer+executor 64.6/69.3 → full AgentCoder 79.9/89.9; both generated tests and real execution feedback are needed.
  • Test quality: designer-test accuracy 87.8/89.9 (GPT-3.5) and 89.6/91.4 (GPT-4), against MetaGPT (GPT-4) 79.3/84.4, CodeCoT 67.1/79.0, and plain GPT-3.5 47.0/57.2; line coverage 91.7/92.3 (GPT-4) vs MetaGPT 81.7/80.5 and CodeCoT 77.2/82.9.
  • Iterations 1→5 (GPT-3.5) raise pass@1 74.4→79.9 (HumanEval), 84.1→89.9 (MBPP), 80.3→89.1 (MBPP-ET); one agent doing both jobs is worse than two (test accuracy 61.0/51.8 vs 87.8/89.9, pass@1 71.3/79.4 vs 79.9/89.9).

Key advantages

  • Isolates why multi-agent code generation works: the win comes from a *non-oracle-biased test designer* plus a *real execution gate*, not from adding more agents — the executor is a plain Python script, so only two LLM calls are in the loop.
  • Cheapest of the measured multi-agent frameworks and the most accurate: 56.9K/66.3K tokens vs 138.2K+ for MetaGPT/ChatDev/AgentVerse, i.e. the paper's efficiency claim is bought by removing coordination chatter rather than by skimping on testing.
  • Ablations separate the contributions cleanly (Tab. 2, Tab. 6–8): a single agent asked to write code then tests loses ~27 points of test accuracy, quantifying the self-confirmation bias in code-then-test prompting.
  • Robustness under stricter tests: near-flat performance on HumanEval-ET/MBPP-ET is direct evidence the generated code is actually correct rather than tuned to the base datasets' two-or-three weak tests.

Limitations

  • The paper has no limitations or broader-impact section: §5 says they are discussed in the Appendix, but Appendix A.1–A.6 contains only output-format setup, overhead, and case studies.
  • Scope is single-function generation on HumanEval/MBPP with ground-truth oracles; nothing is repository-scale, and no weights change, so every gain is in-context and evaporates at the end of the task.
  • The loop stops on 'all tests pass' or a fixed budget of 5 iterations: wrong designer oracles stall or misdirect the repair, and there is no mechanism to detect or discard a bad test.
  • Cost accounting counts response tokens only (no coordination/latency analysis of the failed iterations), and the abstract pairs the SOTA pass@1 (90.2/78.9, Self-Collaboration) with MetaGPT's token counts (138.2K/206.5K), misattributing the baseline comparison.
