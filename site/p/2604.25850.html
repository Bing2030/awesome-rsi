Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses

Jiahang Lin, Shichun Liu, Chengjun Pan, Lizhi Lin, Shihan Dou, Zhiheng Xi, Xuanjing Huang, Hang Yan, Zhenhua Han, Tao Gui, Yu-Gang Jiang

arXiv 2026 · 2026

Local PDFOnline

TL;DR

Harness engineering is manual; AHE automates it with three observability pillars — components as files, trajectories distilled into a layered evidence corpus, each edit bound to a falsifiable prediction. Ten iterations lift Terminal-Bench 2 pass@1 from 69.7% to 77.0%, past Codex and prompt-only self-evolution.

Abstract

Harnesses are now central to coding-agent performance, mediating how models interact with tools and execution environments. Yet harness engineering remains a manual craft, because automating it faces a heterogeneous action space across editable components, voluminous trajectories that bury actionable signal, and edits whose effect is hard to attribute. We introduce Agentic Harness Engineering (AHE), a closed loop that addresses these challenges through three matched observability pillars: (1) component observability gives every editable harness component a file-level representation so the action space is explicit and revertible; (2) experience observability distills millions of raw trajectory tokens into a layered, drill-down evidence corpus that an evolving agent can actually consume; and (3) decision observability pairs every edit with a self-declared prediction, later verified against the next round's task-level outcomes. Together, these pillars turn every edit into a falsifiable contract, so harness evolution proceeds autonomously without collapsing into trial-and-error. Empirically, ten AHE iterations lift pass@1 on Terminal-Bench 2 from 69.7% to 77.0%, surpassing the human-designed harness Codex-CLI (71.9%) and the self-evolving baselines ACE and TF-GRPO. The frozen harness transfers without re-evolution: on SWE-bench-verified it tops aggregate success at 12% fewer tokens than the seed, and on Terminal-Bench 2 it yields +5.1 to +10.1pp cross-family gains across three alternate model families, indicating the evolved components encode general engineering experience rather than benchmark-specific tuning. Ablations localize the gain to tools, middleware, and long-term memory rather than the system prompt, suggesting factual harness structure transfers while prose-level strategy does not.

Method

A closed loop over a decoupled NexAU harness whose seven component types — system prompt, tool description, tool implementation, middleware, skill, sub-agent config, long-term memory — each live in a workspace file, so one edit is one git commit. The seed H0 is bash-only: one shell tool, no middleware, skills or sub-agents. Each iteration: run k=2 rollouts per task; attribute the previous round's manifest against observed task-level deltas and roll back rejected edits at file granularity; an Agent Debugger distills the rollouts into per-task root-cause reports plus a benchmark overview (millions of raw trace tokens compressed to a readable corpus); the Evolve Agent then edits components, each change shipping a manifest entry naming failure evidence, inferred root cause, targeted fix, predicted fixes and at-risk regressions. Next round's measured deltas yield a per-edit keep-or-revert verdict. Only workspace files are writable; verifier, tracer and model config are read-only.

Key results

  • Terminal-Bench 2 (89 tasks = 4 easy / 55 medium / 30 hard): ten iterations lift pass@1 from 69.7% to 77.0%, beating human-designed Codex 71.9%, Terminus-2 62.9%, OpenCode 47.2% and self-evolving TF-GRPO 72.3% and ACE 68.9%; Medium 78.2% → 88.2%, Easy 87.5% → 100.0%. The campaign ran ~32 hours; the only tier AHE trails is Hard (53.3% vs Codex 56.7%).
  • Component ablation: swapping in only long-term memory scores 75.3%, only tools 73.0%, only middleware 71.9% — each beats the 69.7% seed alone — while only the system prompt regresses to 67.4% (−2.3 pp). The three positive single-component gains sum to +11.1 pp against full AHE's +7.3 pp, so components interact non-additively.
  • Transfer to SWE-bench-verified (500 tasks, 7 repos) with no re-evolution: AHE 75.6% aggregate vs seed 75.2%, ACE 74.6%, TF-GRPO 74.2%; 461k tokens/trial vs 526k seed, 582k TF-GRPO, 679k ACE — 12% below the seed and 32% below ACE.
  • Frozen-harness cross-model transfer on Terminal-Bench 2, all five bases positive: deepseek-v4-flash 51.7% → 61.8% (+10.1 pp), qwen-3.6-plus 56.2% → 62.5% (+6.3), gemini-3.1-flash-lite-preview 36.5% → 41.6% (+5.1), GPT-5.4 medium +2.3 and xhigh +2.3 (high +7.3).
  • Self-attribution over 9 rounds: fix-precision 33.7% and fix-recall 51.4% vs random baselines 6.5% / 10.6% (~5x); regression-precision 11.8% and regression-recall 11.1% vs 5.6% / 5.4% (~2x) — 43 predicted regressions, only 5 landed, while 40 unforeseen regressions occurred.

Key advantages

  • Isolates where harness value actually lives: tools, middleware and long-term memory each carry the gain on their own, while 79 lines of system-prompt discipline inserted alone costs −2.3 pp — factual harness structure transfers, prose-level strategy does not.
  • Jointly evolves the full editable component set rather than one surface (tool description, tool implementation, middleware, skill, sub-agent, memory, prompt), with a minimal bash-only seed so every component has to earn its place against measured rollouts, and one-shot explore-agent skills get no protection from later removal.
  • Buys accuracy and cheapness together: the frozen harness posts the highest SWE-bench-verified aggregate while using 12% fewer tokens per trial than its own seed, because behavior moves into tools/memory instead of being re-derived in the prompt on every call.
  • Decision observability makes every edit a measurable contract — manifest prediction, next-round verdict, file-level rollback — and the targeting claim is quantified, not asserted: fix precision/recall sit ~5x above random.

Limitations

  • Components interfere on long-horizon work: AHE trails Codex on the Hard tier (53.3% vs 56.7%), and the memory-only variant alone scores 63.3% on Hard, above full AHE — the evolve agent optimizes an aggregate dominated by 55 Medium tasks and trades away part of the Hard memory effect.
  • Regression foresight is near-blind (only ~2x random; 40 of 45 regressions unforeseen), which the authors name as the clearest direction for future loops: the loop can justify why an edit helps but cannot name what it breaks.
  • Operating-point coupling: step budget and per-task timeout were fitted to GPT-5.4 high during evolution, so cross-model numbers conflate portability with budget — within one family the gain is non-monotone (+2.3 medium, +7.3 high, +2.3 xhigh), and xhigh trials push past the timeout that pass@1 counts as failure.
  • Governance is incomplete by the authors' own account — a controlled research prototype, not a mature autonomous self-improvement system; evaluation is limited to Terminal-Bench 2 plus SWE-bench-verified, leaving other languages, repo-scale deployments and human-in-the-loop workflows untested.

Where it fits the RSI arc

Stage 5 (Harness-level RSI) — the diagnostic anchor of the harness-evolution cluster: the bottleneck is observability, not agent capability, and the gain localizes to tools, middleware and memory rather than the prompt. Pairs with ADAS and AutoHarness on what to evolve, RRSI's anti-overfitting regularizers and Harness-Zero on where the loop goes, and ACE/TF-GRPO as its prompt-only foils.
