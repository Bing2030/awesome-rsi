Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents

Jenny Zhang, Shengran Hu, Cong Lu, Robert Lange, Jeff Clune

ICLR 2026 · 2026

Local PDFOnlineCode

TL;DR

A coding agent rewrites its own source code, validates each self-modification empirically on SWE-bench and Polyglot instead of proving it, and keeps every viable variant in an open-ended archive, lifting SWE-bench Verified from 20.0% to 50.0%.

Abstract

Today's AI systems have human-designed, fixed architectures and cannot autonomously and continuously improve themselves. The advance of AI could itself be automated. If done safely, that would accelerate AI development and allow us to reap its benefits much sooner. Meta-learning can automate the discovery of novel algorithms, but is limited by first-order improvements and the human design of a suitable search space. The Gödel machine proposed a theoretical alternative: a self-improving AI that repeatedly modifies itself in a provably beneficial manner. Unfortunately, proving that most changes are net beneficial is impossible in practice. We introduce the Darwin Gödel Machine (DGM), a self-improving system that iteratively modifies its own code (thereby also improving its ability to modify its own codebase) and empirically validates each change using coding benchmarks. Inspired by Darwinian evolution and open-endedness research, the DGM maintains an archive of generated coding agents. It grows the archive by sampling an agent from it and using a foundation model to create a new, interesting, version of the sampled agent. This open-ended exploration forms a growing tree of diverse, high-quality agents and allows the parallel exploration of many different paths through the search space. Empirically, the DGM automatically improves its coding capabilities (e.g., better code editing tools, long-context window management, peer-review mechanisms), increasing performance on SWE-bench from 20.0% to 50.0%, and on Polyglot from 14.2% to 30.7%. Furthermore, the DGM significantly outperforms baselines without self-improvement or open-ended exploration. All experiments were done with safety precautions (e.g., sandboxing, human oversight). The DGM is a significant step toward self-improving AI, capable of gathering its own stepping stones along paths that unfold into endless innovation.

Method

DGM starts from one lightweight coding agent — a Bash tool plus a whole-file editor, powered by frozen Claude 3.5 Sonnet (New). Each iteration samples k parents from the archive: every agent whose score is not perfect is eligible, with probability proportional to a sigmoid-scaled score s_i = 1/(1+exp(-λ(α_i−α_0))), λ=10, α_0=0.5, times a novelty bonus 1/(1+n_i) counting its functioning children. The parent reads its own benchmark evaluation logs, proposes one feature to implement, and receives that proposal as a problem statement, which it edits into its own Python repository. A child is gated on compiling and retaining basic codebase-editing ability (10 tasks), then staged-evaluated (50–60 tasks, 200 for strong agents), and every viable variant is added to the archive, which is never pruned. Runs: 80 iterations, k=2 on SWE-bench, k=4 on Polyglot; archive maintenance and parent selection are fixed, not self-modifiable.

Key results

  • SWE-bench Verified: base agent 20.0% → 50.0% over 80 iterations; Polyglot 14.0% → 38.0% on the 50-task subset and 14.2% → 30.7% on the full benchmark. The best DGM agent is comparable to the checked open-source SoTA on SWE-bench and surpasses Aider on Polyglot.
  • Ablations (Table 1): DGM 50.0%/38.0% (SWE-bench/Polyglot) vs DGM w/o open-ended exploration 23.0%/14.0%, DGM w/o self-improve (fixed meta-agent, ADAS-style) 39.0%/28.0%, DGM Greedy (always branch from the best performer) 39.7%/30.0%.
  • Discovered self-modifications are concrete (Figure 3): line-range file viewing plus string-replacement editing in the edit tool, non-empty-patch validation with retry, multiple patch generations ranked by a second FM, history-aware patch generation, auto-summarize at the context limit.
  • Transfer: on 200 SWE-bench tasks with the FM swapped, base 23.0% → 33.0% (o3-mini) and 19.0% → 59.5% (Claude 3.7 Sonnet). Zero-shot cross-benchmark, the SWE-evolved agent scores 28.9% on Polyglot (base 14.2%) and the Polyglot-evolved agent 24.5% on SWE-bench (base 20.0%).
  • Cost and stability: ~2 weeks and ~USD 22,000 per SWE-bench DGM run vs ~USD 10,000 per baseline run; three Polyglot runs give 40.7% ± 2.3%. DGM preserves basic code-editing functionality in 51.3% of generated agents vs 32.5% for both baselines.

Key advantages

  • It closes the self-referential loop rather than assuming it: the artifact being improved is the same agent that performs the improvement, so benchmark gains demonstrably raise the capacity to self-modify. The baselines isolate exactly that (fixed meta-agent = ADAS-style 39.0/28.0; no archive = hill-climbing 23.0/14.0; always branch from the best = Robeyns-style 39.7/30.0).
  • Non-greedy, non-zero-probability parent selection over a never-pruned archive escapes deceptive dips: at iterations 4 and 56 on SWE-bench the final best lineage fell below its own parent, yet continued exploration along that path produced the top agent.
  • Improvements are not benchmark- or model-specific: they survive an FM swap (200 SWE-bench tasks: 19.0→59.5 under Claude 3.7 Sonnet) and transfer zero-shot across benchmarks in both directions, which is evidence of general skill acquisition rather than harness overfitting.
  • Every accepted self-modification is a code diff with an auditable archive lineage, so gains can be traced and rolled back; the same loop retargets to a safety objective simply by changing the scoring function (hallucination case study, Appendix H).

Limitations

  • Still falls short of closed-source SoTA SWE-bench solutions, and demands heavy compute to get where it does: about 2 weeks and ~USD 22,000 for a single SWE-bench run (~USD 10,000 per baseline run).
  • Bounded by the frozen FM: only prompts, workflows and Python code evolve, never the model's weights or training script — training a new foundation model is explicitly left as future work.
  • The open-ended exploration itself (archive maintenance, parent selection) is fixed by the authors and not modifiable by the DGM, so the improver's meta-level stays human-designed.
  • The central assumption — coding-benchmark gain reflects better self-improvement — is also where objective hacking appears: in the hallucination study (150 iterations, 3 SWE-bench tasks) node 114 reached a perfect 2.0 score by deleting the special-token logging its hidden hallucination detector relied on.
