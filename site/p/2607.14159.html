MemoHarness: Agent Harnesses That Learn from Experience

Yue Huang, Wenjie Wang, Han Bao, Yuchen Ma, Xiaonan Luo, Yi Nian, Haomin Zhuang, Zheyuan Liu, Yue Zhao, Xiangliang Zhang

arXiv 2026 · 2026

Local PDFOnline

TL;DR

MemoHarness splits an agent harness into six editable control dimensions, searches them from its own executions into a dual-layer experience bank, then retrieves that experience at test time to build a case-specific harness — 0.806 vs Codex's 0.722 on Terminal-Bench.

Abstract

An agent harness is the external control layer that turns a base LLM into an executable agent by managing context, tools, orchestration, memory, decoding, and output handling. While harness design strongly affects agent behavior, most automatic improvement methods optimize narrower artifacts such as prompts, pipelines, or workflows, and deployed agents usually reuse a single global harness for all cases. We introduce MemoHarness, an adaptive harness optimization framework that learns from its own executions. MemoHarness decomposes the harness into six editable control dimensions, stores per-case diagnoses and distilled global patterns in a dual-layer experience bank, and adapts the learned harness to each test case using retrieved experience without test-time labels, feedback, or additional search. In our evaluation across shell-agent, code-generation, and analytical-reasoning benchmarks, MemoHarness improves over the fixed harnesses we compare against and shows selective transfer to unseen suites and base models. Its additional context can also remain cost-competitive when much of the retrieved experience is cacheable. These results provide evidence that execution experience is a practical substrate for building agent harnesses that are more adaptive than a single static configuration, while leaving broader claims about statistical robustness and component attribution to future work.

Method

Phase A searches a six-dimensional harness space — D1 context assembly, D2 tool/retrieval, D3 decoding, D4 orchestration topology, D5 cross-call memory, D6 output post-processing — starting from a minimal W0 with all optional components off. Each of T=10 rounds the controller issues a structured query over the bank, retrieves a bounded slice, proposes W_t, runs it on every labeled search case, and writes a per-case entry: case features, configuration delta, trajectory, reward, token cost, and a diagnosis {success, primary failure dimension (D1–D6), secondary dimensions, analysis}. A diagnostic operator maps verifier outcomes, exceptions, timeouts and missing artifacts to a dimension; distillation fires after M=5 new entries or N=3 consecutive failures. W* is selected lexicographically — mean reward first, token cost only as tiebreaker. Phase B freezes W*, retrieves the K nearest successful and failed training cases plus feature-matched patterns, and emits a case-specific W(x) with no labels, feedback or extra search.

Key results

  • Terminal-Bench (18-task held-out split, GPT-5.3-Codex): MemoHarness 0.806 vs the strongest baseline Codex 0.722 (+0.084), and +0.250 to +0.445 over Claude Code, OpenCode and Terminus.
  • Final validation-selected harness beats base on all three benchmarks: 0.722 → 0.806 (Terminal-Bench), 0.900 → 0.967 (LiveCodeBench), 0.600 → 0.767 (FinanceAgent). The shipped harness sits below the in-training peak on two of them — LiveCodeBench touches 1.000 at iteration 3 and Terminal-Bench 0.833 at iteration 4 — and only the long-horizon workload keeps improving across the 10 rounds (FinanceAgent 42.5% → a 65.0% peak near iterations 8–9, versus LiveCodeBench oscillating in a 91.2%–95.0% band).
  • Cross-model transfer with no retraining: every one of six held-out base models improves on Terminal-Bench, mean +0.098, from +0.038 (GPT-4.1, 0.500 → 0.538) to +0.233 (GLM-5, 0.500 → 0.733). The source model keeps its +0.084.
  • Cross-dataset transfer is positive but selective (Table 2, shared Codex). The Terminal-Bench-derived harness lifts MMMLU 0.818 → 0.848 and StrongReject 0.879 → 0.909 (+0.030 each) and SWE-Bench Pro 0.706 → 0.765 (+0.059); saturated HumanEvalFix (1.000) and Reasoning-Gym-Easy (0.947) do not move, and LawBench is mixed.
  • Cost: MemoHarness pulls more input (14.18M tokens) but 13.32M of it is cached, giving $6.89 on the 18-task split vs $10.28 for Codex and $9.51 for Claude Code at higher accuracy; Terminus ($6.68) and OpenCode ($2.34) stay cheaper at substantially lower success.

Key advantages

  • Test-time adaptation with no test-time signal at all: the case-specific harness is built from only (instruction, case features) plus the frozen bank — no labels, no feedback, no gradient updates, no extra search rounds. That is what lets simple cases stay lightweight while retrieval-heavy or format-sensitive cases invoke richer orchestration, an axis AFlow/DSPy-style training-time optimizers do not have.
  • It moves the object of optimization from a narrow artifact to the whole control layer. Prompt optimizers (OPRO, Promptbreeder), pipeline compilers (DSPy, MIPRO, TextGrad) and workflow searchers (AFlow, AutoFlow) each edit one slice; Meta-Harness searches harness code but still ships a single training-time artifact for all cases, which is exactly the gap MemoHarness's Phase B fills.
  • The bank stores diagnosis, not just a score. Because each entry carries the configuration delta and a dimension-level failure attribution, the paper can run an operation-level transition analysis (Appendix G): newly appearing cat, sed, which and test coincide with reward increases at +59.5, +23.2, +20.2 and +17.3 pp over the ~13.2% all-transition baseline, while curl (−2.1), echo (−2.5) and grep (−7.9) are flat or negative — attribution a scalar score curve cannot supply.
  • Correctness-first selection keeps search off cheap-but-wrong harnesses: reward ranks candidates and token cost only breaks ties, and dollar cost is computed offline rather than optimized — yet the cacheable retrieved context still lands the system below two commercial baselines in cost.

Limitations

  • The primary evaluation is an 18-task held-out split (80/20 of the 89-task suite, seed 42) reporting point estimates with no confidence intervals or significance tests, so results are evidence under one fixed protocol rather than a statistical characterization (Appendix A).
  • Not every baseline is a pure scaffold transplant with the same model and runtime surface, and Meta-Harness — the closest prior system — was not run at all, because no public implementation suitable for the evaluation stack existed when experiments were finalized; the comparison is qualitative.
  • No component ablation: the experience bank, the distilled global patterns and the case-specific test-time adaptation are not separately isolated, so how much of the gain each contributes is unmeasured — the authors name this explicitly as open.
  • The cost result depends on the observed cacheability of retrieved experience (lower cache reuse would change the profile), transfer is selective rather than uniform (LawBench mixed, saturated suites unmoved), and the controller and diagnostic operators are heuristic instantiations that future work should replace with learned ones.

Where it fits the RSI arc

Stage 5 harness-level RSI at its case-adaptive end: the evolved artifact is the control layer itself, not a prompt or pipeline. Closest neighbours are Meta-Harness (searches harness code but ships one static artifact) and AutoHarness; its no-feedback per-case step complements Continual Harness's reset-free online loop. Pairs with ADAS/AFlow as training-time ancestors and ACE for context-level experience reuse.
