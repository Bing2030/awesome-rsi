What it does

ADAS (Automated Design of Agentic Systems) — Meta Agent Search: a meta agent iteratively programs new agents as executable forward() code, scores each on a validation split, and appends survivors to a growing archive of designs (arXiv 2408.08435, ICLR 2025).

How it works

  • Agent-as-code: every candidate is one complete `def forward(self, taskInfo)` function; `evaluate_forward_fn()` in `_mmlu/search.py` literally `exec()`s the string and installs it via `setattr(AgentSystem, 'forward', func)`, so discovered agents run inside a shared shell whose `LLMAgentBase.query()` returns `Info` namedtuples (name, author, content, iteration_idx).
  • Per-domain self-contained searches: `_mmlu/`, `_arc/`, `_drop/`, `_gpqa/`, `_mgsm/` each carry a `search.py` + `{domain}_prompt.py`; the archive is seeded by `get_init_archive()` with 7 hand-written agents (COT, COT_SC, Reflexion, LLM_debate, Take_a_step_back, QD, Role_Assignment) and persisted to `results/{expr}_run_archive.json`.
  • Each generation: `get_prompt(archive)` shows the meta agent the full scored archive plus a placeholder `AgentArchitecture` interface and 'WRONG Implementation examples'; the proposal then goes through two Reflexion revision passes (`get_reflexion_prompt(archive[-1])` feeds back the previous attempt — the repo-level realization of the paper's re-architect step) and an execution-error debug loop (`debug_max=3`) that returns stack traces as `debug_thought`.
  • Fitness is median + 95% bootstrap CI of accuracy on a 128-example validation slice (`--valid_size 128`, `--n_generation 30`, gpt-4o default); after search, `evaluate()` re-runs every archived agent on the held-out test split, and `_arc/search.py` instead execs a candidate `transform()` function with `run_examples_and_get_feedback()` giving per-example CORRECT/WRONG feedback.

Key advantages

  • The cleanest executable-improvement substrate in this catalog: improvements are whole Python programs the meta agent wrote (multi-agent flows, debate, reflection), so the search space is Turing-complete rather than a fixed prompt/prompt-part genome like prompt-optimizers or Darwin-Gödel-style mutation.
  • Scored archive (not just mutation of one incumbent) makes it the reference setup for studying novelty, stepping stones, and transfer: `_transfer_math/` re-evaluates agents discovered on one domain zero-shot on unseen ones (gsm8k, gsmhard, SVAMP, Asdiv, DROP).
  • Small enough to fully read in an afternoon — one `search.py` per domain, no framework — so you can trace every loop of a code-level self-improver end to end and re-target it to a new task by editing one `evaluate_forward_fn`.

Install & run

conda create -n adas python=3.11; conda activate adas; pip install -r requirements.txt; export OPENAI_API_KEY="YOUR KEY HERE"; then python {DOMAIN}/search.py with {DOMAIN} in {_arc, _drop, _gpqa, _mgsm, _mmlu} (defaults: 30 generations, gpt-4o-2024-05-13).

Learning note

Read `_mmlu/search.py:evaluate_forward_fn` first — `exec()` + `setattr(AgentSystem, 'forward', func)` is the whole thesis in two lines. Then `_mmlu/mmlu_prompt.py` for the meta prompt (archive, interface, WRONG examples) and Reflexion prompts. Heed the untrusted-code-execution warning; results JSONs are committed under `results/`.

Repo README


Automated Design of Agentic Systems

ICLR 2025

🏆 Outstanding Paper (NeurIPS 2024 Open-World Agent Workshop) [Tweet]

In this work, we describe a newly forming research area Automated Design of Agentic Systems (ADAS), which aims to automatically create powerful agentic system designs, including inventing novel building blocks and/or combining them in new ways.

We present a simple yet effective ADAS algorithm named Meta Agent Search to demonstrate that agents can invent novel and powerful agent designs. In Meta Agent Search, a "meta" agent iteratively programs interesting new agents in code based on previous discoveries.


Setup

conda create -n adas python=3.11
conda activate adas
pip install -r requirements.txt

# provide your OpenAI API key
export OPENAI_API_KEY="YOUR KEY HERE"

Running Instructions

Running Meta Agent Search

To run experiments for each domain, navigate to its respective folder. The code in each folder is self-contained. Launch experiments using the search.py script located in each domain's folder.

python {DOMAIN}/search.py

Replace {DOMAIN} with the specific domain folder name {_arc, _drop, _mgsm, ...} to run the experiment for.

Customizing Meta Agent Search for New Domains

You can easily adapt the code to search for new domains. To do so, follow these steps:

  1. Modify the evaluate_forward_fn() function and adjust any necessary formatting prompts (e.g. this line) in the search.py file.

  2. Consider adding additional basic functions for the meta agent to utilize during the design process (similar to this line).

  3. Update the domain-specific information within the prompts to match the requirements of your new domain (e.g. this line).

  4. Run the search and evaluation on your new domain.

Safety Consideration

[!WARNING]
The code in this repository involves executing untrusted model-generated code. We strongly advise users to be aware of this safety concern. While it is highly unlikely that model-generated code will perform overtly malicious actions in our current settings and with the models we use, such code may still act destructively due to limitations in model capability or alignment. By using this repository, you acknowledge and accept these risks.
