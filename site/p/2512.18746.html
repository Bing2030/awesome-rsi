MemEvolve: Meta-Evolution of Agent Memory Systems

Guibin Zhang, Haotian Ren, Chong Zhan, Zhenhong Zhou, Junhao Wang, He Zhu, Wangchunshu Zhou, Shuicheng Yan

arXiv 2025 · 2025

Local PDFOnline

TL;DR

MemEvolve treats the agent's memory architecture itself — Encode/Store/Retrieve/Manage — as the evolvable object: an outer loop diagnoses each candidate's failures and redesigns its four modules, lifting Flash-Searcher and SmolAgent by up to 17.06 points on agentic benchmarks.

Abstract

Self-evolving memory systems are unprecedentedly reshaping the evolutionary paradigm of large language model (LLM)-based agents. Prior work has predominantly relied on manually engineered memory architectures to store trajectories, distill experience, and synthesize reusable tools, enabling agents to evolve on the fly within environment interactions. However, this paradigm is fundamentally constrained by the staticity of the memory system itself: while memory facilitates agent-level evolving, the underlying memory architecture cannot be meta-adapted to diverse task contexts. To address this gap, we propose MemEvolve, a meta-evolutionary framework that jointly evolves agents' experiential knowledge and their memory architecture, allowing agent systems not only to accumulate experience but also to progressively refine how they learn from it. To ground MemEvolve in prior research and foster openness in future self-evolving systems, we introduce EvolveLab, a unified self-evolving memory codebase that distills twelve representative memory systems into a modular design space (encode, store, retrieve, manage), providing both a standardized implementation substrate and a fair experimental arena. Extensive evaluations on four challenging agentic benchmarks demonstrate that MemEvolve achieves (I) substantial performance gains, improving frameworks such as SmolAgent and Flash-Searcher by up to $17.06\%$; and (II) strong cross-task and cross-LLM generalization, designing memory architectures that transfer effectively across diverse benchmarks and backbone models.

Method

Any memory system is abstracted as a genotype Omega = (Encode, Store, Retrieve, Manage) inside EvolveLab, which re-implements 12 published memories on one BaseMemoryProvider ABC. Each iteration k runs two nested loops. Inner: every candidate Omega_j starts from an empty memory base and populates it over a 60-task batch (40 fresh + 20 reused from the previous iteration), scoring each trajectory into f = (task success, token cost, latency). Outer: summaries F_j = (Perf, -Cost, -Delay) are ranked by non-dominated Pareto sort, ties broken by Perf; the top-K = 1 parent survives, and Diagnose-and-Design replays that parent's own trajectories to emit a structured defect profile across its four modules (retrieval failures, ineffective abstractions, storage inefficiencies), from which an LLM designs S = 3 executable descendants that edit only the permissible implementation sites. Three iterations, seeded from one hand-built memory (AgentKB); the best descendant is then frozen and re-deployed.

Key results

  • Flash-Searcher + GPT-5-mini with the TaskCraft-evolved memory, no dataset-specific meta-evolution: GAIA 69.09 -> 73.33 pass@1, xBench-DS 69.0 -> 74.0, WebWalkerQA 71.18 -> 74.71 — a 3.53-5.0 point gain on all three, matching the paper's stated 3.54%~5.0% range.
  • SmolAgent + GPT-5-mini rises from xBench pass@1 51.0 to 57.0 and pass@3 68.0, and reaches GAIA pass@3 72.12 — comparable to AgentKB's 73.94 while skipping AgentKB's large offline knowledge base. Flash-Searcher + MemEvolve hits GAIA pass@3 80.61, above CK-Pro pass@3 (75.15) and OWL-Workforce (60.61).
  • Cross-LLM transfer with the GPT-5-mini-evolved memory, no manual adaptation: Kimi K2 goes WebWalkerQA 52.35 -> 69.41 (+17.06 points) and TaskCraft 58.00 -> 68.00 (+10.0); DeepSeek V3.2 goes WebWalkerQA 69.41 -> 72.35.
  • The seven re-implemented human-designed memories give no consistent gain under the same framework. ExpeL underperforms No-Memory on all three (GAIA 66.06 vs 69.09; xBench 64.00 vs 69.00; WebWalkerQA 69.41 vs 71.18) and DILU costs 2.42 points on GAIA (66.67 vs 69.09).
  • Gains are not bought with tokens: GAIA API cost per query $0.085 vs $0.086 no-memory, xBench $0.136 vs $0.141, WebWalkerQA cheaper at $0.040 vs $0.048 — but wall-clock latency rises (GAIA 693.33s vs 505.46s).

Key advantages

  • Moves the evolvable object one level down: instead of hand-picking a memory schema and only filling it with experience, MemEvolve bilevel-optimizes the schema — inner loop evolves the experience base, outer loop evolves the architecture — with an explicit fitness vector covering quality, cost and latency rather than accuracy alone.
  • The four-module genotype is what makes architecture search tractable: every descendant must be an executable configuration of (Encode, Store, Retrieve, Manage) inheriting one ABC, so evolved memories stay valid and pluggable instead of degenerating into unparseable prompt soup.
  • EvolveLab is a reusable artifact in its own right: 12 unified memory re-implementations, online and offline evaluation modes, and LLM-as-Judge or exact-match protocols — a fair arena for comparing memory designs that did not previously exist.
  • The evolution trace is inspectable and legible: AgentKB's frozen encode/store becomes an Adaptive Decision system (nine skill granularities), then a Meta Memory system (four-level trajectory storage plus an LLM retrieval guardrail), then Riva, then Cerebra — which distills reusable tools and adds periodic database maintenance.

Limitations

  • The search is a shallow local hill-climb, not open-ended evolution: 3 iterations, survivor budget K = 1, S = 3 descendants per round, 60 trajectories per evaluation, and a single fixed seed architecture (AgentKB). No ablation isolates how much of the gain comes from the architecture versus from merely having richer retrieval context.
  • Gains are bounded by the host framework, on the authors' own account — "memory is not a panacea and remains bounded by the capabilities of the underlying agentic framework." On GAIA, MemEvolve on SmolAgent only matches AgentKB (72.12 vs 73.94 pass@3).
  • The cost of meta-evolution itself is never reported: three rounds x three candidates x 60 deep-research rollouts of search overhead, in dollars and wall-clock, is unaccounted for against the per-task cost table.
  • Transfer is intra-regime. The authors concede memories evolved on TaskCraft are unlikely to transfer to fundamentally different task families (e.g. embodied action) where environments, action spaces and tool sets differ substantially — cross-task generalization is demonstrated only among web/deep-research benchmarks.
