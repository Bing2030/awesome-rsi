Mathematical Discoveries from Program Search with Large Language Models

Bernardino Romera-Paredes, Mohammadamin Barekatain, Alexander Novikov, et al. (Google DeepMind)

Nature 2024 · 2024

Local PDFOnlineCode

TL;DR

A frozen PaLM2-Codey LLM rewrites one function inside a hand-written skeleton; an evaluator scores candidates on real inputs; best programs return as two-program prompts across an island population. It found a 512-element 8-dimensional cap set and bin-packing heuristics beating first/best fit.

Abstract

Article Mathematical discoveries from program search with large language models https://doi.org/10.1038/s41586-023-06924-6

Method

Input is an 'evaluate' function scoring candidate solutions, an initial program (often a greedy skeleton) and often a richer 'solve' skeleton; only the isolated critical function - cap set 'priority', bin packing 'heuristic' - is evolved. Each iteration the programs database samples one island, then k=2 programs within it (favouring high-scoring, shorter ones, Boltzmann-weighted over score-signature clusters) and builds a prompt listing them as priority_v0/priority_v1 plus an empty priority_v2 header; the frozen Codey LLM (no fine-tuning, ~10^6 samples total) completes it. New programs are executed on the inputs; incorrect ones (timeouts, invalid output) are discarded, the rest scored and stored in their island. Every 4 h the worst half of islands is wiped and reseeded with a copy of one high-scoring program from a surviving island. Samplers and evaluators run asynchronously (typically 15 samplers, 150 CPU evaluators).

Key results

  • Cap set: FunSearch matches the best known sizes for n = 3-7 (9, 20, 45, 112, 236) and finds 512 in n = 8 versus the previous best 496, discovered from scratch as a program that manual simplification turned into an explicit 512-cap construction with Hill-cap-like structure.
  • Cap set capacity lower bound: an I(12,7) admissible set improved the lower bound from 2.2180 (ref. 38) to 2.2184; reading the program revealed a coordinate-permutation symmetry, and searching symmetric admissible sets gave I(15,10) -> C >= 2.219486 and a partial A(24,17) set of size 237,984 -> C >= 2.2202, described as the largest improvement in 20 years (upper bound 2.756).
  • Online bin packing, OR-Library: excess bins over the L2 lower bound is 5.30% / 4.19% / 3.11% / 2.47% on OR1-OR4, versus first fit 6.42 / 6.45 / 5.74 / 5.23 and best fit 5.81 / 6.06 / 5.37 / 4.94; trained only on OR1-sized instances, it still generalizes upward.
  • Weibull-distributed instances: 0.68% / 0.32% / 0.03% at 5k / 10k / 100k items, versus best fit 3.98 / 3.90 / 3.79 and first fit 4.23 / 4.20 / 4.00 - 0.03% off the lower bound on the optimum at 100k items.
  • Robustness: every admissible-set experiment beat the previous capacity bound and 60% found the full-size I(12,7) set, but the n = 8 512-cap appeared in only 4 of 140 experiments.

Key advantages

  • First LLM-based system to produce verifiable new results on an established open problem, surpassing the best human-known construction - evidence the discovery is genuinely new rather than retrieved from training data.
  • It searches function space, not solution space: the output is a few interpretable lines of code whose enumerated solution can exceed 200,000 vectors, and inspecting that code produced the symmetry insight that pushed the capacity bound further.
  • Off-the-shelf frozen LLM (no fine-tuning) with one pipeline handling both pure mathematics and applied combinatorial optimization without problem-specific tuning; the distributed async design keeps cost low (few accelerator samplers, many cheap CPU evaluators).
  • Demonstrates a working human-in-the-loop protocol - FunSearch proposes, domain experts inspect and feed back structure, search restarts from the refined specification.

Limitations

  • Narrow applicability: the paper states FunSearch works best when there is an efficient evaluator, a rich (not binary) scoring signal, and a skeleton with an isolated part to evolve; theorem-proof generation falls outside this scope because no rich enough signal exists.
  • High variance on the hardest problem: the n = 8 cap set required 140 experiments to succeed 4 times, and the authors note several independent repetitions may be needed to improve on prior results.
  • Dependence on a strong code LLM and heavy sampling (~10^6 samples; 15 samplers, 150 CPU evaluators), and reliance on user-provided skeletons without which performance 'tends to improve significantly' only when the initial program is well written.
  • The capacity lower bound 2.2202 is still far from the 2.756 upper bound, and the main text's two successes are cap/admissible sets and online bin packing - the corners problem and Shannon capacity of cycle graphs are left to Supplementary Appendix B.
