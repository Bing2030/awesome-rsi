EvolveR

repo

What it does

EvolveR — self-evolving LLM agents via an experience-driven lifecycle: rollout trajectories are distilled into guiding/cautionary principles in a Milvus experience DB, retrieved at task time via a <search_experience> action, and outcome scores reinforce a GRPO-trained Qwen2.5-3B policy (arXiv 2510.16079, ICML 2026).

How it works

  • evolver/experience/experience_manager.py — ExperienceManager.reflection() runs every training step (experience.organize_interval=1): it flushes the trajectory buffer to the VDB, re-scores each retrieved principle with Laplace-smoothed success (success_count+1)/(usage_count+2) in _update_metric_scores(), then _distill_new_experiences() summarizes each trajectory via SUMMARIZE_SUCCESSFUL/FAILED_TRAJECTORY_PROMPT into a [DESCRIPTION] sentence plus [STRUCTURE] (subject, predicate, object) triplets — typed 'guiding' on success, 'cautionary' on failure — dedups candidates with pairwise MATCH_PRINCIPLE_PROMPT yes/no LLM votes over connected components, then merges into an existing principle (embedding-similarity gate + LLM match, linking the source trajectory as a positive/negative example) or creates a new one; principles scoring under clean_low_metric_threshold=0.3 are purged, as are 'collapsed' ('!!!!!') and special-token-contaminated ones caught at retrieval time.
  • evolver/experience/milvusdb/ — the 'Experience VDB': a FastAPI server (routers/principles.py, trajectories.py, search.py, export_import.py; start_server.sh) over a single-file Milvus DB; scripts/train_grpo-3b.sh installs a trap that POSTs /export/ of the principles+trajectories collections to data/evolver/result/<experiment>/db_exports as jsonl on exit, and scripts/test-3b.sh restores a prior run via VDB_IMPORT_DB_FILE — the evolved memory is a checkpointable, transferable artifact, not transient context.
  • evolver/llm_agent/generation.py — the multi-turn rollout (max_turns=10) over <think>/<search>/<search_experience>/<answer> actions: a <search_experience> query calls ExperienceManager.retrieve(top_k=3), returning RetrievedExperiencePackage(principle, similarity_score, positive_examples, negative_examples); _build_prompt_with_experience() packs packages into the token budget with priorities 1. principle description + metric_score, 2. structure subgraph, 3. example trajectories; actor state_masking masks the <information>/<experience> observation blocks out of the policy loss.
  • evolver/rewards/ + vendored verl/ and LLaMA-Factory/ — outcome_reward_fn (exact match for closed QA; weighted F1 + an LLM 'independence/diversity' score for open-ended) drives GRPO via verl.trainer.main_ppo (algorithm.adv_estimator=grpo; default weights format=0.1, outcome=1.0, experience=0); experience_reward_fn can additionally pay merit_score × embedding-similarity for used principles; scripts/cold_start_sft.sh produces the qwen-3b-instruct-cold_start starting checkpoint, and evolver/search/ serves an e5_Flat.index over the wiki-18 corpus (explicit Search-R1 lineage).

Key advantages

  • Memory with a trust ledger: every principle carries usage_count/success_count and a smoothed metric_score that decides both survival (purged below 0.3) and retrieval merit — you can watch individual strategies earn and lose the system's trust across training, which prompt-only memory banks (ACE playbooks, Dynamic Cheatsheet) never measure.
  • Principles are dual-representation and example-grounded: a natural-language description for embedding retrieval plus SPO-triplet structure, each shipping linked successful AND failed trajectories as few-shot evidence at retrieval time — the most concrete artifact in this catalog for studying strategy (not fact) memory.
  • The lifecycle closes inside the RL loop itself — distill every step, retrieve during rollouts, reinforce from outcomes — rather than wrapping a frozen model; and jsonl export/import lets one experiment's grown memory seed another (VDB_IMPORT_DB_FILE), making memory evolution itself reproducible.

Install & run

conda create -n evolver python=3.10 && conda activate evolver
pip install torch==2.4.0 --index-url https://download.pytorch.org/whl/cu121
pip3 install vllm==0.6.3
pip install -e .   # installs the vendored verl
pip3 install flash-attn --no-build-isolation
# plus two side envs: `vllm` (embedding server) and `retriever` (faiss-gpu=1.8.0, pyserini)
# data: HF dataset Edaizi/EvolveR-NQ-HotpotQA -> data/nq_hotpotqa_train/{train,test}.parquet
conda activate vllm && bash scripts/vllm_server.sh
conda activate retriever && python scripts/download.py --save_path data/Wiki-corpus-embedd && cat data/Wiki-corpus-embedd/part_* > data/Wiki-corpus-embedd/e5_Flat.index && gzip -d data/Wiki-corpus-embedd/wiki-18.jsonl.gz && bash scripts/retrieval_launch.sh
bash scripts/train_grpo-3b.sh   # GPU_NUM=8 by default; or skip training with pretrained HF Edaizi/EvolveR (EvolveR-3B, Qwen2.5-3B)

Learning note

Start with evolver/experience/prompts.py — the guiding/cautionary duality is the whole design. Then read the 'Reflection Cycle Summary' log line: merges, dedups, DB counts per step. _update_metric_scores() is the trust rule: (success+1)/(usage+2). Note rewards.weights.experience=0 by default — outcome EM does the reinforcing.

Repo README

EvolveR: Self‑Evolving LLM Agents through an Experience‑Driven Lifecycle

This repository contains the official implementation of EvolveR, a framework enabling LLM agents to self-improve through a closed-loop experience lifecycle, where they distill abstract principles from past trajectories and retrieve them to guide future actions.

📰 Updates

  • 2026-05-01: 🎉 Paper accepted at ICML 2026.
  • 2025-10-21: Paper is publicly available in arxiv.
  • 2025-10-20: Codebase is publicly available.

🎯 Getting Started

Installation

We recommend using Python 3.10 and Conda for environment management.

1. Create Training Environment

# 1. Clone the repository
git clone https://github.com/Edaizi/EvolveR.git
cd EvolveR

# 2. Create and activate conda environment
conda create -n evolver python=3.10 -y
conda activate evolver

# 3. Install dependencies
# install pytorch
pip install torch==2.4.0 --index-url https://download.pytorch.org/whl/cu121
# install vllm
pip3 install vllm==0.6.3 # or you can install 0.5.4, 0.4.2 and 0.3.1

# verl
pip install -e .

# flash attention 2
pip3 install flash-attn --no-build-isolation
pip install wandb

2. Create Embedding Server Environment

conda create -n vllm python=3.10
pip install vllm

3. Create Local Retrieval Server Environment

conda create -n retriever python=3.10
conda activate retriever

# we recommend installing torch with conda for faiss-gpu
conda install pytorch==2.4.0 torchvision==0.19.0 torchaudio==2.4.0 pytorch-cuda=12.1 -c pytorch -c nvidia
pip install transformers datasets pyserini

## install the gpu version faiss to guarantee efficient RL rollout
conda install -c pytorch -c nvidia faiss-gpu=1.8.0

## API function
pip install uvicorn fastapi

🗄️ Data Preparation

We will provide the processed data on Hugging Face Hub. You can download it from the following link:

  • EvolveR-Data

Place your training and validation data in the following structure. The provided training script uses this path by default.

./data/nq_hotpotqa_train/
├── train.parquet
└── test.parquet

You can modify the DATA_DIR variable in scripts/train_grpo-3b.sh to point to your dataset location.

🚀 Training

1. Deploy Embedding Server

conda activate vllm
bash scripts/vllm_server.sh

2. Deploy Local Retrieval Server

Download the indexing and corpus.

conda activate retriever

save_path=data/Wiki-corpus-embedd
python scripts/download.py --save_path $save_path
cat $save_path/part_* > $save_path/e5_Flat.index
gzip -d $save_path/wiki-18.jsonl.gz

Launch Local Retrieval Server

conda activate retriever
bash scripts/retrieval_launch.sh

3. Execute the main training script.

bash scripts/train_grpo-3b.sh

The script will handle all training steps, including lauching Launching Experience Vector Database (VDB), interacting with the Experience VDB.
