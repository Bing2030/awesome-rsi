Reflexion: Language Agents with Verbal Reinforcement Learning

Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao

NeurIPS 2023 · 2023

Local PDFOnline

TL;DR

Reflexion reinforces language agents through words, not gradients: after a failed trial the agent writes a first-person reflection on the error, appends it to an episodic memory buffer, and retries — reaching 91% pass@1 on HumanEval and +22 points on AlfWorld.

Abstract

Large language models (LLMs) have been increasingly used to interact with external environments (e.g., games, compilers, APIs) as goal-driven agents. However, it remains challenging for these language agents to quickly and efficiently learn from trial-and-error as traditional reinforcement learning methods require extensive training samples and expensive model fine-tuning. We propose Reflexion, a novel framework to reinforce language agents not by updating weights, but instead through linguistic feedback. Concretely, Reflexion agents verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer to induce better decision-making in subsequent trials. Reflexion is flexible enough to incorporate various types (scalar values or free-form language) and sources (external or internally simulated) of feedback signals, and obtains significant improvements over a baseline agent across diverse tasks (sequential decision-making, coding, language reasoning). For example, Reflexion achieves a 91% pass@1 accuracy on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 that achieves 80%. We also conduct ablation and analysis studies using different feedback signals, feedback incorporation methods, and agent types, and provide insights into how they affect performance.

Method

Training-free, inference-only loop over a frozen LLM, with no gradient update anywhere. Three roles: the Actor Ma (Chain-of-Thought or ReAct prompted) emits trajectory tau_t against the environment; the Evaluator Me scores it, rt = Me(tau_t), via exact-match grading (HotPotQA), a hand-written heuristic (AlfWorld: same action and same observation for more than 3 cycles, or more than 30 actions in one environment), self-written unit tests CoT-generated, AST-validated and sampled up to n = 6 (code), or an LLM judge (decision-making). The Self-Reflection model Msr consumes {tau_t, rt} and writes a first-person verbal summary sr_t of the mistake. Algorithm 1: sr_t is appended to long-term memory mem, the raw trajectory is short-term memory, and the Actor re-runs until Me passes or the trial cap hits. mem is a sliding window bounded at Omega = 1-3 entries (3 for AlfWorld and HotPotQA, 1 for code).

Key results

  • Table 1 pass@1, HumanEval Python 80.1 (GPT-4, previous SOTA) → 91.0 with Reflexion; also HumanEval Rust 60.0 → 68.0, MBPP Rust 70.9 → 75.4, Leetcode Hard Python 7.5 → 15.0 (40 hard Leetcode problems released after GPT-4's Oct 8 2022 pretraining cutoff, 19 languages). MBPP Python is the one regression: 80.1 → 77.1.
  • AlfWorld, 134 environments: ReAct + Reflexion solves 130/134 with the hallucination/inefficiency heuristic and keeps learning across 12 consecutive trials, while ReAct-only stops improving between trials 6 and 7 and settles at a 22% hallucination rate with no long-term recovery.
  • HotPotQA, 100 questions (Table 5): CoT (GT) + text-davinci-003 0.60 → 0.77, gpt-3.5-turbo 0.57 → 0.71, gpt-4 0.68 → 0.80; ReAct + text-davinci-003 0.30 → 0.55, gpt-3.5-turbo 0.26 → 0.38, gpt-4 0.39 → 0.51. CoT-only and ReAct-only baselines fail to solve any first-trial failure on retry at temperature 0.7. The intro's headline is a 20% HotPotQA gain; the largest table delta is +25 points.
  • Two ablations isolate the mechanism. On HotPotQA CoT (GT), self-reflection adds an 8% absolute boost over episodic memory alone (keeping only the most recent trajectory), so refinement-only loops are weaker than reflection-guided ones. On the 50 hardest HumanEval Rust problems (Table 3), Reflexion 0.68 vs 0.60 base, 0.60 for tests-without-reflection, and 0.52 for reflection-without-tests — removing test execution hurts more than removing the verbal reflection.
  • The MBPP Python failure is explained by test quality (Table 2): the false-positive rate of self-generated tests (tests pass, solution wrong) is 16.3% on MBPP Python versus 1.4% on HumanEval Python, where a flaky suite lets the agent submit early. Separately, starchat-beta gains nothing at all on HumanEval Python (0.26 → 0.26, average over 8 trials, Table 4).

Key advantages

  • Trains nothing and updates no weights: the 'policy' is literally {frozen LLM, memory buffer}, so it runs on closed models (GPT-4, text-davinci-003, gpt-3.5-turbo) and every improvement is stored as human-readable text, unlike policy- or value-based RL that needs fine-tuning and massive samples.
  • Feedback-agnostic by construction — the same loop consumes binary success, hand-written heuristics, exact-match grading, self-written unit tests, or an LLM evaluator, and the paper runs all of these across decision-making, reasoning and code. Feedback can be external or internally simulated.
  • Keeps code results pass@1-eligible: it gates on self-generated and AST-filtered tests rather than hidden ground-truth test cases (unlike AlphaCode, Self-Debugging and CodeRL), and is language-agnostic — Python and Rust via MultiPL-E — which is what makes 91.0 HumanEval and 15.0 Leetcode Hard legitimate single-sample numbers.
  • It separates reflection from mere retrying. The episodic-memory ablation (8% absolute) and the reflection-omission arm of Table 3 (0.60, no gain over baseline) both show that verbal error diagnosis is the causal ingredient, not extra attempts — blind trial-and-error debugging is ineffective on hard tasks.

Limitations

  • Local minima, stated by the authors as the core risk and demonstrated on WebShop (Appendix B.1): ReAct + Reflexion over 100 environments was terminated after 4 trials having failed to significantly outperform ReAct, generating no useful self-reflections. Conclusion: it cannot solve tasks requiring a lot of diversity and exploration.
  • Memory is a fixed sliding window of 1-3 experiences with no retrieval structure — the paper explicitly defers vector-embedding or SQL memory to future work — so gains are bounded by the context window and vanish between sessions.
  • Self-evaluation is the load-bearing dependency and it fails silently: a flaky or wrong self-written test suite yields false positives (16.3% on MBPP Python) and premature submissions, and the authors prefer false negatives only because the agent may then repair its own test. Test-driven development also breaks for non-deterministic, impure, hardware-dependent or concurrent functions.
  • The ability to self-correct is emergent with model scale: starchat-beta showed zero improvement (0.26 → 0.26), and the authors state it is a quality of stronger, larger models. There is also no formal guarantee of success.
