FT-Dojo: Towards Autonomous LLM Fine-Tuning with Language Agents

Qizheng Li, Yifei Zhang, Xiao Yang, Xu Yang, Zhuo Wang, Weiqing Liu, Jiang Bian

arXiv 2026 · 2026

Local PDFOnline

TL;DR

FT-Dojo is the first interactive benchmark for end-to-end LLM fine-tuning agents — 13 tasks across 5 domains with a shared raw-data pool, Docker sandbox and held-out evaluator; FT-Agent, a planning/fail-fast/feedback framework, wins 10 of 13 tasks.

Abstract

Fine-tuning large language models for vertical domains remains labor-intensive, requiring practitioners to curate data, configure training, and iteratively diagnose model behavior. Despite growing interest in autonomous machine learning and language agents, end-to-end LLM fine-tuning has not been systematically studied as an interactive agent task. We introduce FT-Dojo, an interactive benchmark environment for autonomous LLM fine-tuning, comprising 13 tasks across 5 domains. Rather than a new collection of static datasets, FT-Dojo standardizes a task interface, shared raw-data repository, sandboxed execution environment, structured feedback protocol, and held-out evaluation procedure. We further develop FT-Agent, a fine-tuning-oriented autonomous framework that uses structured iteration planning, fail-fast validation, and multi-level feedback analysis to refine data and training strategies. Experiments show that FT-Agent provides a strong initial baseline, achieving the best performance on 10 out of 13 tasks, with additional controlled comparisons against frontier agents, open-source planning backbones, and multi-run statistics supporting the main findings. Case studies show that agents can recover from failures through cumulative learning, while still exposing limitations in causal diagnosis and long-horizon planning. The implementation is available at https://github.com/microsoft/rd-agent.

Method

FT-Dojo formalizes fine-tuning as argmax over data strategy θd and training hyperparameters θt, given structured feedback f(t). Each task supplies a natural-language objective plus an evaluation script; agents work inside a GPU-limited Docker sandbox against three interfaces — a Meta API (task spec, data descriptions, API docs), a shared raw-Data Repository (not per-task splits, so source selection is itself an optimization target), and an Evaluator built on OpenCompass returning aggregate metrics, per-instance predictions with correctness labels, and training loss curves. Validation and test splits are non-overlapping, each min(100, ⌊n/2⌋); training is capped at 2,000 self-constructed samples via SFT or LoRA on Qwen2.5-7B-Instruct within a 12-hour single-B200 budget. FT-Agent adds structured iteration planning (compact data-strategy + training-config + rationale plans instead of verbose logs), three-stage fail-fast validation (schema/syntax, mini-run format check, runtime sanity), and multi-level feedback diagnosis that promotes a new best configuration when Fτ improves.

Key results

  • Best on 10 of 13 tasks (mean±std over 3 runs). AIME 2025: 0.00 → 11.11±3.82 accuracy, while Qwen2.5-7B-Instruct, constrained Manual SFT and tool-augmented OpenHands all stay at 0.00 — the agent diagnosed missing reasoning supervision and synthesized CoT from a pool where 82% of samples lack solutions
  • Strongest where code or structural constraints are strict: Table QA Visualization Pass@1 29.33±6.11 vs OpenHands 24.00; Chemistry Molecule Editing 54.44±2.94 vs OpenHands 40.00. The losses are reported honestly — OpenHands wins both Reaction metrics (FTS 35.59 vs 30.92, Acc 60.00 vs 35.33) and Manual SFT wins Financial QA (71.68 vs 67.20)
  • Fail-fast validation converts budget into iterations: 6.0 vs 2.75 effective iterations inside the same 12h (2.2×; Table QA FC 7 vs 2), avg loops 8.77 vs 3.69, improvement rate 24.37% vs 17.31%, for $5.73 vs $3.92 of iterative spend
  • Five-task controlled comparison (same data repo, Docker env, LlamaFactory/OpenCompass wrappers, 12h): FT-Agent+GPT-5.2 averages 42.83, above Claude Code Sonnet-4.6-thinking (39.86), LLM-assisted Manual SFT (37.11), Codex GPT-5.2 (36.06) and OpenHands GPT-5.2 (34.55); swapping the planner to DeepSeek-V3.2 (35.83), GPT-4o (36.65) or Qwen3.5-397B (31.97) keeps it in range
  • Case-study duality: on Mol Edit the agent recovers from a 2% vocabulary-corruption collapse to 56% accuracy via format fixes and RDKit SMILES validation, but on PI4PC it shotguns generic fixes (NEFTune −11pp, collapse to 8%) and returns to the 34% baseline after 8 loops; on Visualization a locally-sane filter chain cut ~1,800 samples to 27 (98.5%) and dropped Pass@1 20% → 4%

Key advantages

  • First interactive, protocol-standardized environment for end-to-end fine-tuning: rather than per-task static datasets, it makes data curation and training configuration joint optimization targets under one fixed 2,000-sample budget, with a two-phase validation/test protocol that keeps the test set inaccessible during optimization
  • Unusually clean factorization — base model, raw data repository, Docker sandbox, training/eval wrappers, GPU, splits and wall clock are held fixed so only the agent framework varies — plus honest negative controls: doubling OpenHands to 24h on AIME changes nothing (best checkpoint lands in the first 6 hours), and scaling data 2k → 5k can hurt under a fixed budget because processing squeezes iteration time
  • Documents emergent autonomous cross-domain data transfer: for Numerical Reasoning the agent mixed in 10% out-of-domain DeepScaleR (AIME/AMC math) for 32.00 → 46.00 accuracy; for Mol Opt it built a 70/25/5 composite of mol_opt/mol_edit/mol_und for SR 23.33 → 36.67 with valid-SMILES 68.67 → 91.67 — and it stays selective, using only in-domain data on Reaction, Mol Edit and Mol Und
  • No black box: the paper's conflict-of-interest disclosure names the Microsoft authors behind FT-Agent, and the harness is released at github.com/microsoft/rd-agent with pluggable task-objective and evaluation-script modules, so new fine-tuning tasks need no core infrastructure changes

Limitations

  • A benchmark, not a method, and the authors say so: the constituent datasets are pre-existing held-out evaluators (PANORAMA, ChemCoTBench, FinanceIQ, TableBench, AIME 2025), only the protocol is new; 13 tasks in 5 domains with pools from 4,497 to 136,211 raw samples is still narrow coverage
  • Causal diagnosis is the headline deficit: on PI4PC the agent describes symptoms with hedging language ('likely', 'appears') and applies generic ML techniques without asking why the task overfits, never operationalizing the train–eval mismatch it correctly named in Loop 2; net gain was zero
  • Planning myopia: the agent optimizes each pipeline step locally without modeling cumulative state changes, which is exactly how the Visualization dataset collapsed 98.5%; a 3-stage validation gate cannot catch joint effects that only appear after composition
  • Statistics are uneven by necessity: 3 seeds for FT-Agent only (full coverage would cost 1,500+ GPU-hours, so baselines are single controlled runs) and chemistry reaction similarity is volatile (30.92±11.22), which the paper flags as large variance; one author group also built both the benchmark and the winning agent
